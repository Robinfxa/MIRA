# IMG-READINESS-01: current local image capability evidence

Baseline: immutable mira-xiahe-chapter-final-20261006T0721Z. Owner: image-readiness slice;
shared bootstrap/CLI image hunks coordinated with the integration owner. No public
schema, provider, auth, environment, real database, network or dependency changes.

### IMGREADINESS01-001 Configuration declaration
Given images disabled or missing custom-brief/data/usage consent, check/startup
  identifies the exact declaration state without probing credentials or an account.
  Legacy catalog readiness is never custom-brief tool readiness.
### IMGREADINESS01-002 Process and session capacity
Given a runtime with available local session and process capacity, its current
  tool definitions may include generate_story_image. Exhausted/shared busy process
  capacity removes that tool, preserving independently eligible show_photo.
### IMGREADINESS01-003 Actual request projection
Given a final adapter request drops tools for the existing dialogue budget or
  continuation rules, safe diagnostics record the actual final advertisement,
  current request scope and closed reason, never an inferred permanent inability.
### IMGREADINESS01-004 Observed failure
Given a provider port fails, diagnostics distinguish the last observed generation
  or review operation failure from current readiness. Local decode/review rejection,
  missing configuration and untested subscription eligibility are not remote errors.
### IMGREADINESS01-005 Stale boundaries
Given Stop, Close or a newer input, old readiness callbacks cannot create current
  readiness records. Observation cannot grant tools, reset/refund budget or change
  successful fixed-photo receipt behavior. No user dialogue boilerplate is added.
### IMGREADINESS01-006 Private metadata boundary
Exported metadata contains closed enums and bounded counters only; no brief,
  candidate, exception text, model/path/key/header, arbitrary tool name or digest.
