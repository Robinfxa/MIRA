# IMG-01 Bounded fictional story images

Status: offline implementation; no live provider authorization or quality claim.
Base: exact 2242 capture of frozen mira-integration-20261005T2238Z.
Owner block: providers (contracts), actor (session consumer), http (resource delivery), web (downstream).
Resources: injected finite image/vision clients, decoder, per-session four-slot in-memory budget; no persistent pixels.

### IMG01-001 Closed proposal and source contract
Given selected released author fiction, when a closed scene proposal is selected, compile only server-owned scene text. Invalid/unavailable images never fail ordinary chat.
### IMG01-002 Exact pixel qualification
Given admitted intent, when generated bytes are canonicalized, visual review receives exactly the served PNG and must pass every request/spec/digest/policy-bound check.
### IMG01-003 Reserved post-seal acceptance
Given sealed ordinary text and an unconsumed current reservation, when image review passes, append exactly one media grant; new input, Stop, Close and photo dismiss defeat late results.
### IMG01-004 Authenticated resources and receipts
Given a qualified current grant, only its owning session/token and exact resource/digest/effect/epoch can fetch bytes. Only a matching presentation receipt establishes generated_visualization history. No memory/canon promotion.
### IMG01-005 Default unavailable
Given no explicit image runtime factory, no backend is constructed or called. Image timeout/failure stays separate from chat failure. Synthetic fixtures verify only software contracts.

### IMG01-006 One bounded review intent per accepted input
Given a valid closed proposal, expose pending with an application-owned UUID before JEV and claim the accepted-request/epoch/spec identity before any review await. Duplicate candidates, including prior reject/UNKNOWN, do not repeat image review or overwrite an active image status. New accepted input creates a new review scope. Late errors from older review cannot modify the new input's pending operation. Held reviews and generation failures terminate pending work without retroactively rejecting independently available chat.

### IMG01-007 Receipt-authoritative mixed photo visibility
When generated media exists, reorder only photo entries inside their existing presented tuple positions by actual presentation sequence. Preserve exact effect objects, cue associations, unrelated caption/audio/pose/scene positions, and fixed-only legacy order. DecisionSnapshot uses the same domain projection without relaxing identity/order validation. Immediate dismissal refreshes stored current-visibility facts. Archive capture continues to pair immutable issued effects and receipts by effect ID, not tuple position.

### IMG01-008 Optional process operation admission
An optional injected ImageOperationAdmission reserves synchronously before the first provider await and releases active ownership in finally after the actual operation coroutine settles. Failed reserve calls no provider and does not release nonexistent ownership. Image, decode, review and cancellation paths release exactly once; uncooperative providers retain their slot until they settle. The default is None and the Actor's exact runtime class guard remains intact. Attempts and unknown costs are not refunded by release.
