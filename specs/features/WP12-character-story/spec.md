# WP12: authored character, story and affect application slice

Baseline: immutable2353,1010 files; direct subscription/API composition and paired
memory remain separately consented. This source is next-stage work, not the
published2219 installer. Default story mode is disabled. No real provider or user
memory was used during implementation.

### WP12-001 Same authored facts and current state
Generation and independent output review receive one versioned application-owned
canon/story projection and one asset readiness catalog. Author fiction never
creates real-user facts. Unreleased canon stays hidden. V4 output wire references
the same request's context instead of serializing it twice; local binding digests
and the32KiB bound remain. Input review retains all reliable user inputs, author policy, restrictions, actual presentations/audio/referents, and current story identity/node/boundary summary; duplicate canon provenance and stored episode text are excluded while the full local snapshot digest remains. Its16KiB bound is unchanged. Old v1–v3 contracts remain replayable.

### WP12-002 Suggestions and evidence are distinct
LLM JSON can propose story and affect with closed fields, never permissions,
compiled IDs, receipt IDs, confidence or source IDs. Same-batch JEV observations
supply simple relevance/willingness/refusal/affect labels using the explicit0.6
policy. Clear NO closes the invitation with no relationship penalty. UNKNOWN
holds optional progress and uses the existing deterministic system fallback.
Plain conversation can stay at the same node and still update internal affect.

### WP12-003 Presented events only
The application compiles exact reviewed effects and binds the reducer's plan to
effectID/digest/component. A subtitle receipt advances the offer; it cannot prove
wardrobe. Only the exact wardrobe receipt creates a qualified fictional visual
episode. Accepted-only effects, stale/replayed/after-Stop mismatches and candidate
assertions never establish completion. Explicitly unavailable clothing closes the
invitation instead of leaving a stale active offer.

### WP12-004 Private persistence and reentry
The optional fixed-scope checkpoint is opened only after local operator pairing.
Save consent includes recipient disclosure for selected OpenAI/JEV and optional
Google generated speech. Check/import do not create credentials or a database.
One bounded worker saves checkpoint and qualified episode archive in one SQLite
transaction. Context retains at most32 episodes; the append-only archive is not
automatically transmitted. A timed-out started write has unknown outcome and
stays busy; same snapshot retry reconciles without automatic provider calls.
Stop does not wait for SQLite; receipt ACK follows durable completion. Reentry
preserves acknowledged fiction but cancels pending effects rather than promoting
an unseen offer. Revocation closes owned resources and a delayed previously-authenticated request cannot reopen them; startup rechecks current pairing before/inside the runtime lock and after private factory awaits.

### WP12-005 User entry and honest capability limits
`tools/live_provider.py --story` explicitly enables in-memory authored story and
affect, while persistence additionally needs a private DB/scope, pairing and its
specific consent. No default auto logging. Asset names alone are not readiness.
The initial loop is cafe→displayed invitation→reviewed choice→registered raincoat
presentation→rain view; other16 author storylets are not claimed as runtime nodes.
Internal emotion is not a visible-face receipt. Generic costume/accessory actions,
renderer acceptance and actual-device/provider validation are separate gates.

Consumers: Actor, direct Responses, JEV, private HTTP pairing, optional SQLite,
existing presentation receipt/cancellation. Resources: existing request/turn/byte
limits; one operator/session/IO worker; bounded context and query results. No new
third-party dependency. Tests have actual RED/GREEN logs where defects were found;
new clean tests without earlier failure are baseline verification, not invented TDD.
