### NATIVEPHOTOINTENT01-001: Natural sharing intent
In an ongoing photo-sharing context, a present request such as 还有别的照片吗 or 别的给我看看 can request another suitable fictional image without the magic word 生成. If generate_story_image is actually available and current consent/capacity allow it, the native model should request it through the existing tool. It should not merely repeat fixed inventory or ask the user to pronounce a technical command.

### NATIVEPHOTOINTENT01-002: Context and actual availability
Past-experience questions, mentions, quotation, hypotheticals and negation alone do not request an image. Model-typed intent, not application keyword scanning, determines a request. Missing/disabled tools, exhausted capacity and an existing pending job never imply permission for an implicit generation or duplicate job. Describe the current limitation without claiming that fictional inventory permanently contains only one photograph; pending and displayed facts retain the existing receipt contract.

### NATIVEPHOTOINTENT01-003: Evidence limits
Synthetic native tool choices verify serialization and application behavior only. Existing actual user-confirmed image display and automatic completion speech remain frozen and unchanged. Natural model follow-through needs a separate unscripted rerun.

### NATIVEPHOTOINTENT01-004: Model-visible subject scope matches current compiler
When enabled, the image tool currently supports empty scenery and still-life only. Humans and animals, including fictional ones, are outside that existing scope. Tell the model this before it chooses a tool: explain the current limitation naturally and offer an empty-scene alternative; do not silently substitute another subject or consume usage for the substitute. This corrects model-visible guidance only, without widening compiler/reviewer/admission policy or changing jobs. Actual natural-model compliance needs the separate native rerun. Preserve the unchanged instruction, prompt and whole-continuation bounds.
