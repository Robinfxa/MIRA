### WEBUNLIMITED-001 Null local quotas preserve finite service counters
Given intentional local-unlimited readiness, when the DTO is serialized and compiled browser transport opens it, local duration, sample, utterance, session lease, global lease, and recognition-renewal maxima are null. Null never coerces to zero/one and arms no lifetime timer. Finite service used/remaining counters retain their operational bounds; zero means exhausted, not unlimited. Existing finite values keep their stop behavior, and finite configuration bounds match the schema.

### WEBUNLIMITED-002 Cumulative counters are not lifetime quotas
Given a long local lease, sequence, absolute source offset, revision, lease-start count, commit segment and recognition stream index may exceed old cumulative ceilings. Strict integer/nonnegative validation and bounded per-message text/PCM remain. Browser counts remain safe integers. Local source, revision, and input ownership fences prevent retired identities or delayed callbacks from restarting accepted work.

### WEBUNLIMITED-003 Exhaustion and capacity have distinct closed reasons
Given a service budget is exhausted, a closed service_budget_exhausted event stops capture and retains draft/accepted text. It never automatically reopens or resets service usage, and the page can still send typed input. An already accepted commit may finish once if its acknowledgement races this service stop; explicit Stop/new input still fences it. Given pending_capacity, the exact draft remains and the live lease allows later user-reviewed sending; there is no automatic retry or revoked-lease claim.
