### WP13SPEAKER-001 Recognition controls address

Given an unrecognized visitor or an unreceipted recognition, when serializing
speaker facts, no authored friend history addresses the visitor as that role.
Given an exact successful recognition receipt, the first-person speaker contract
addresses the active fictional role. Stop, late receipts and exit cannot activate
or restore a role. Dialogue alone cannot establish recognition or real identity.

### WP13SPEAKER-002 Released canon survives dialogue cutback

Given an active role and receipted authored story layers, when prior conversation
rows are omitted, retain those exact same-source canon texts with release links.
Keep the current unreleased layer as one reference to its existing chapter source.
Do not import later layers, invent biography, duplicate the current layer, or
mistake disclosure receipts for physical shared history or a completed gift.

### WP13SPEAKER-003 Ordinary voice and recent reference

Given ordinary questions about prior authored events, use the active role's
available canon naturally in first person without explaining provenance or AI
reality unasked. Explicit AI or real-identity questions remain truthful. Missing
real-user recall is not missing authored canon. Given a short visual follow-up,
resolve it against recent accepted inputs and presented replies, including an
outfit topic; available photos do not determine the referent. Pending dialogue
and unpresented drafts never become reference evidence or completed actions.

### WP13SPEAKER-004 Actual request boundary

Given either subscription or API transport, inspect the actual serialized tool
and text request through synthetic HTTP, including state before and after receipts
and after history cutback. The fixed speaker policy and same-source facts survive
serialization. Native speaker uses the same policy. Injected output proves the
wire/state contract only, never model semantic quality or real-device acceptance.
