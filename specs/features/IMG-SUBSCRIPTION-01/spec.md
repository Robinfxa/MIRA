# IMG-SUBSCRIPTION-01: offline-tested standalone subscription image compatibility

Base: immutable mira-combined-next-20261006T0018Z, 1292-file capture manifest SHA-256 8739c3c84c5628bae4a6a3b5a38fcbff8ae49ba35a48c9cabedc42612899d209. Owner: providers via the existing unique tests/contracts/test_*.py registration in tests/quality.toml. Consumers: separately selected bootstrap composition, existing story-image runtime and PillowPngDecoder, independently admitted pixel review. No bootstrap, CLI, schema, ports, API adapter or decoder changes in this slice. Resources: one 1024x1024 opaque PNG, 8 MiB image bound, independent 12 MB HTTP-wire and decoded-JSON bounds, 4 KiB specification, 120-second maximum total deadline. These are local resource limits, not documented service limits, quotas or prices.

### IMGSUBSCRIPTION01-001 Fixed subscription-only request
Given an admitted bounded MediaRequest and an injected opaque MIRA CodexCredentialSource, when generation runs, then exactly one POST targets https://chatgpt.com/backend-api/codex/images/generations with model gpt-image-2, prompt, background opaque, quality auto, size 1024x1024 and n=1. Only documented-in-source DTO fields are sent. No edits, reference images, tools, input URLs, private session/history/memory or API credentials are accepted. The API backend remains unchanged and is never called as fallback. The locally generated image-turn UUID does not expose a MIRA session identifier.

### IMGSUBSCRIPTION01-002 Scoped credentials and safe failure
Given the existing MIRA credential source, when it resolves or internally refreshes credentials, then this adapter only awaits get_credentials once within the same total deadline and validates opaque bearer/account/residency headers. It does not open auth files, create credentials, change scopes, add refresh logic or impersonate Codex. Missing/malformed credentials, source exceptions, HTTP errors and redirects fail with fixed local errors without retry or token/provider-payload output.

### IMGSUBSCRIPTION01-003 Single complete bounded response
Given identity or gzip JSON bytes, when the body is received, then compressed and decoded sizes are separately bounded; gzip must be one complete stream with no trailing data. Duplicate JSON keys, invalid constants, malformed envelopes, explicit error/refusal/incomplete/partial results, URL-only results and counts other than one fail closed. The first-party required created unsigned integer and data[].b64_json shape is enforced. Like the source's default serde behavior, bounded additional benign metadata (including usage, model, revised_prompt and passive URLs alongside inline bytes) is ignored and never followed. Optional source DTO metadata is type-checked and never used as pixel truth, identity or entitlement; auto/null hints are accepted, and an explicit non-PNG output_format fails. Missing Content-Type is accepted because the source does not require it; an explicitly contradictory MIME is rejected as local policy. Strict base64 and PNG signature/byte bounds precede the existing maintained Pillow decoder; only that downstream canonicalizer can validate complete static opaque 1024x1024 pixels. A GeneratedImage alone has no review or presentation authority. No usage units are inferred from metadata.

### IMGSUBSCRIPTION01-004 Stop and absolute deadline
Given cancellation or deadline expiry at credentials, dispatch, body, stream cleanup or client cleanup, when an await returns even after swallowing cancellation, then the existing RequestFence prevents any late GeneratedImage or second request. Parsing is checked against the same absolute deadline. As elsewhere, an injected dependency which never returns cannot be forcibly terminated by the adapter.
