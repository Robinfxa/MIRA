# Explicit text-application memory entry

This composition contract accompanies M06AR. It binds the verified local store
and Actor reader to the public text-development entry. Defaults remain off.
The candidate is separate from published1212 and does not authorize any actual
provider call or access to real user memory during automated verification.

### M06RECALLENTRY-001: Separate named transmission consent

Given no memory options, startup and declaration checks do no memory IO. Given
partial options or missing transmission consent, fail before reading admission
or memory configuration. Complete options select only an existing private
database and an operator-owned scope alias, outside the checkout. File/link,
ancestor, bounded JSON and exact schema checks fail safely without changing
permissions. Consent names Codex generation and TypeSafe JEV output review;
local recording and raw diagnostic consent do not imply transmission consent.
Memory serve also requires explicit per-launch pairing-file creation consent.
Declaration check never generates a code or file; failed frontend preparation
never creates a credential. Codes stay in a new private file, never terminal
output or a URL.

### M06RECALLENTRY-002: App ownership and recipient boundary

Given memory-enabled app composition, require one local operator/session.
Constructors/factories and unpaired lifespan are inert. Only a successful
origin-bound operator pairing opens the read-only reader. Shutdown/revocation
closes it after sessions, including post-pair startup failure. Session deletion
does not close an app-owned reader. Browser requests cannot choose memory scope.
Memory combined with voice is rejected until a separately disclosed Google
recipient option exists. This first slice never appends or records dialogue.

### M06RECALLENTRY-003: SQLite and production adapter wiring

Given synthetic manually stored statements and a configured scope, a real ASGI
turn uses the same immutable packet through Actor, Codex prompt and output JEV
context/snapshot. Input JEV does not receive the remembered text. Scope IDs are
not exported, another scope is not recalled, and the database remains byte-for-
byte unchanged. Fake transports establish wiring only, not live model behavior
or permission to use fixtures as real review approval. No receipt is fabricated.

### M06RECALLENTRY-004: Diagnosable, private failure

Given stale memory, overflow, timeout or unavailable storage, retain a fixed
non-content-revealing code and existing diagnostic locator. Frontend copy names
the known cause/action without implying that earlier presented effects never
happened. Memory-enabled turns suppress raw model input/output capture; normal
exports do not include memory packets, private scope configuration or SQLite.

## Verification scope

Owned blocks: config, providers, http and web, with architecture and all shared
application consumers in the combined release. New Node memory-error cases are
part of the web lane; traceability below points to collected Python controls.
All records are synthetic and local. No live API, user database, microphone,
model-memory quality, multi-user deployment or complete M06 claim is made.
