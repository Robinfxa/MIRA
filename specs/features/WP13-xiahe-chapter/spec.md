### WP13-001 Current fictional role recognition
Given an unrecognized visitor, only a typed model proposal bound to the exact current
input/epoch and a program-validated unambiguous
self-assertion can stage recognition. The actual scene receipt activates the role.
Negation, quotes, name questions, third-person and conditional claims cannot do so.

### WP13-002 Receipt-backed finite story
After recognition, three old-friend story cues and one photo-promise cue are presented
on separate turns (including multi-clause current role assertions); only exact subtitle receipts advance the chapter. Preview uses
the actual existing photo receipt. A separate gift offer must be visibly presented;
acceptance stages a distinct handover scene whose completion is the finite ending.
No timer or free chat progresses it. Source is explicitly authored fiction.

### WP13-003 Consent, cancellation and reentry
Decline carries no penalty and can reopen only on current explicit request. Exit or
correction removes current role authority, invalidates future acts and preserves
actual receipts. Stop, newer input, missing assets and failed display never complete
pending actions. Exact duplicate receipts are idempotent; stale receipts cannot revive
progress. Existing schema 3/4/5 saves read without rewriting old bytes, new schema 6
records the explicit chapter version and retains old rain-loop state/provenance.

### WP13-004 Independent optional rain paths
Raincoat then window and window then raincoat both work through existing receipts.
A typed current explicit reopen is forwarded by the Actor. Their completion is optional
for the photo ending and cannot stand in for photo or handover receipts.

### WP13-005 Typed gift choice and bounded service use

A visible gift button binds choice, offer ID and the exact receipted offer effect ID/digest.
The application validates this before starting a new input and creates a local candidate;
no second LLM guess, semantic vote or generation request is necessary. Ordinary text can
still produce a typed current acceptance proposal. Existing content, effect capacity,
Stop and receipt boundaries apply. Missing scene resources leave a visible fallback
and no chapter success. Only program state changes/presentations need receipts; free
chat has no additional approval. All chapter transitions are locally validated finite
plans; unrelated optional wardrobe/emotion effects retain their existing JEV lane.

presentation mapping. Dormant default chapter state is omitted from the legacy
model wire to retain exact byte compatibility; the generation proposal contract
still exposes the stranger-to-recognition entry. HTTP projection remains complete.
