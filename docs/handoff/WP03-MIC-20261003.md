## Bounded development composition follow-on

An opt-in offline-tested composition helper now implements the existing development-app
`voice_factory` seam; it reuses `create_google_voice` and adds one-lifespan, per-instance request
and audio-duration ceilings. It is not wired into the CLI/admission JSON, is not enabled by
default, and does not establish entitlement or a dollar-spend ledger. The helper requires the
caller to supply explicit authorization, typed Google voice settings, opaque credentials, an
async token provider, and any approved custom HTTP/CA/proxy client. It performs no ADC discovery,
network request, persistent grant, retry, or microphone capture. See the offline contract and exact
limits in [WP03 Google voice composition](../../specs/features/WP03-google-voice-composition/spec.md).

The earlier successful Gemini TTS probe used the minimal request body without optional
`responseFormat` or `maxOutputTokens`. The existing generic adapter's `responseFormat` field is
documented-valid; the available evidence does not attribute the old 400 to that field. This slice
leaves the adapter body and model selection unchanged, so it does not claim a live request result.
