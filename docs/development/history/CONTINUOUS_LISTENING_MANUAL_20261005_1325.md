# MIRA 连续聆听候选：启动与 5 分钟验收

这份说明适用于包含连续聆听功能的新阶段；准确版本和最终验收收据以同包 START-HERE 为准。已发布1845包仍是按住说话（PTT）路径，旧包的成功不能作为连续聆听验收。

## 启动前

- 在自己的 Mac 上把这份准确候选**新鲜恢复**到新的项目目录，再按它随附的依赖说明准备运行环境。不要覆盖／就地升级冻结的旧包，也不要把旧虚拟环境（`.venv`）搬进新目录；虚拟环境含有原目录绑定的路径，搬迁后不代表可用。
- 如需复用既有 MIRA 环境文件（包括旧文件名 `old.env`），只有文件已在项目目录以外、由本人拥有且仅本人可读写时，才通过其**现有绝对路径**作为 `--env-file`。ADC 文件和 admission 也须用现有的绝对路径并满足 CLI 的私密文件检查。不要复制、导出、贴出或重新登录取得任何认证文件；不要编辑 admission 来强改配置。路径不能通过检查时先停止，不要另造副本。
- 本轮连续聆听仅在这个新候选里。旧 1845 的 PTT 保持原状。
- 启动服务**不会打开麦克风**；只有页面中明确点击“点击开始连续聆听”并处理浏览器麦克风权限后才会采集。

若本人已经有匹配的 application admission，且确实准备进行实时麦克风验收，`tools/live_voice.py serve --help` 已验证以下是本候选接受的启动参数。把 Python 变量指向**新鲜恢复后准备好的解释器**，不要使用搬来的虚拟环境；把三个文件变量指向上述**既有**私密文件。文件必须是绝对路径、普通文件（非符号链接）、本人拥有、仅本人可读写且在候选项目目录外。两个 profile 必须匹配 admission。不要把路径或文件内容发给别人。

```sh
"$MIRA_PYTHON_ABSOLUTE" tools/live_voice.py serve \
  --env-file "$MIRA_ENV_ABSOLUTE" \
  --admission "$MIRA_ADMISSION_ABSOLUTE" \
  --adc-file "$GOOGLE_ADC_ABSOLUTE" \
  --usage-profile application \
  --authorize-google-voice-data-and-spend \
  --tts-requests "$TTS_REQUEST_LIMIT" \
  --stt-requests "$STT_REQUEST_LIMIT" \
  --tts-max-seconds "$TTS_MAX_SECONDS" \
  --stt-max-seconds "$STT_MAX_SECONDS"
```

上面不是账号检查：`serve` 会加载指定的 ADC 并启动本地应用；真实 STT 只会在浏览器允许麦克风且你点击开始后发生。连续音频会发送到 Google STT；点击“发送已确定文字”后，该段文字进入既有 MIRA/Codex/JEV 对话流程。Google/Codex/JEV 调用可能产生费用；所有数量和秒数都是**单次应用进程内的技术上限，不是美元额度或账单上限**。应用重启会重置内存中的计数，不会变成跨重启总账。若没有既有、匹配的 application admission，不要重写或复制准入文件：probe 配置保持原有较窄上限，按页面实际声明验收，连续时长不得超过 30 秒。

## 两种使用配置的含义

- `probe` 是原有限制：Codex、JEV 请求及会话轮数的各项声明上限最多 8；STT/TTS 请求上限最多 8，语音输入／输出流上限 30 秒。连续租约实际不会超过 `min(120 秒, 已声明 STT 秒数)`，并向下取整为整秒；小于 1 秒时连续功能关闭，但 PTT 仍可能可用。
- `application` 必须在既有文本 admission 中明确声明，启动语音 CLI 也必须明确传 `--usage-profile application`。它让调用方可分别选取有限的文本及 STT/TTS 请求数（各不超过 100）、会话轮数（不超过 100）和 STT 秒数（不超过 290）；TTS 仍不超过 30 秒。它不会自动加大调用数或创建美元限额。每条连续租约的真实上限仍是 `min(120 秒, 声明的 STT 秒数)`，不足 1 秒则关闭连续功能。
- 每条租约最多 12 次手动发送；同一会话最多启动 4 条租约。服务范围的租约启动上限等于 `--stt-requests`。连续 STT 与 PTT 共用同一个**每次启动的 STT 请求计数器**。租约创建会占用一次租约启动名额；收到第一个合法PCM音频块后、调用provider之前，才不可撤销地预留一次共享STT请求。空流或非法首块不消费STT调用额度，已预留后的取消/未知结果不退还。页面展示的是连接开始时的用量快照，不是费用额度，也不是之后更新的累计总数。要在 5 分钟里验证点击停止、全局停止和切换后台三种释放路径，至少要有 3 个可用 STT 请求和 3 次会话租约启动名额；之前的 PTT 也可能占用同一计数器。

## 5 分钟人工设备清单

计时从页面已打开、服务状态可见开始。建议戴耳机，降低扬声器回声风险；耳机不能证明回声消除有效。UI 明示耳机／扬声器回声尚未经实机验证。仅记录本人实际观察；遇到权限拒绝、超时或服务不可用就记 `blocked`／`not_run`，不要推断通过。

1. **0:00–0:30 就绪**：确认是新候选、页面连接成功，连续聆听按钮可见。此时浏览器不应正在采集；若按钮缺失或禁用，记录错误码／状态后停止测试。打开页面或启动服务不会自动开麦。
2. **0:30–1:30 手动转写**：点击“点击开始连续聆听”，按浏览器提示决定是否允许麦克风。预期状态变成“正在聆听”，页面显示本条秒数、手动发送数及连接时的 STT／启动计数快照。说一句短话再安静几秒：页面可出现临时或稳定转写，但静音不会自动发给 MIRA，临时转写也不会自动提交。只有“发送已确定文字”可用时，先核对文字，再由你点击发送；只应提交服务端确认的稳定文本。确认结果状态，并避免在“结果不确定”时重发，以免重复。
3. **1:30–2:10 点击停止**：点“停止连续聆听”。预期麦克风指示结束，页面显示已停止，未发送文字仍留在页面。
4. **2:10–3:10 全局停止**：再明确点一次开始；在输入区点击“停止回应”。预期当前连续麦克风租约也结束并释放。
5. **3:10–4:10 切到后台**：第三次明确开始，然后切换到另一个浏览器标签页。返回 MIRA 后，预期租约已停止、麦克风已释放；没有自动续开。页面隐藏、失焦、关闭页也会触发停止路径。
6. **4:10–5:00 复核**：确认未发生自动续租；已收到的文字仍可核对。到秒数或手动发送上限时，租约停止，不会自动 rollover。记下 `pass / fail / blocked / not_run`、浏览器／Mac 型号与时间、界面实际状态，以及页面显示的安全错误码或诊断 ID。

若时间不足，优先完成一次“说话 → 核对 → 手动发送 → 点击停止”，其余停止路径如实标 `not_run`。不要截图、粘贴或索取密钥、ADC/admission 内容、原始 provider 日志或含私人会话的诊断转储；报错时只提供界面公开的错误码／诊断 ID、发生步骤和期望／实际结果。

## 结果边界

这项验收只证明所测 Mac/浏览器上的实际麦克风启停、转写预览与手动提交表现。实际收到转写只能证明本次所用STT调用成功；若也成功生成回复，则另外记录该次模型/审核结果。仅做这份启停清单不能推广为完整Codex/TTS账户就绪、所有配额、生成和发声质量、回声处理或其他设备已通过。代码、离线测试和包检查不能替代这些实机结果。

## 重开监听前的未发送草稿

停止或到限时，当前可见转写会留在单独的“上次聆听预览”中，不成为新监听可发送的文字。它可能仍是临时转写，也可能包含已经另列确认的部分；请自行核对。最多保留4段，满时阻止继续开始而不静默删除。只能明确放入空文字框，再自行编辑/发送；不会覆盖已有输入，也不会自动重发。此列表只留在当前页面内存，刷新/离开页面不代表已保存到记忆或日志。

## 识别服务结束时的预览

后续候选会在识别服务正常结束或出错时，先保留服务端已经观察到、但尚未发到页面的
最后一份有界转写，再显示结束状态。临时转写仍是临时文字，不会自动变成已确定输入；
已收到的最终片段也不会自动发送。明确停止、替换租约、断连与关闭继续阻止旧回调。
此修复不延长识别、不等待额外尾句，也不证明完整句末已经确定。

## 自然句末候选（需同版本前后端）

新前端可以明确选择自然模式；旧客户端默认仍是手动模式。自然模式仅在本条语音活动
已经结束、最终结果覆盖其结束位置、没有未完成临时转写或新活动冲突时，提供可自动
提交的句子标识及准确修订。缺少可靠边界时继续保留文字并提供手动发送，不把标点、
等待时间或一段 `is_final` 当成完整句尾。Google 的活动与转写偏移并不保证对齐，
因此不是每一句都保证自动触发；还须按同版本在真实设备上验收。

已提交语句的迟到尾词会关联回同一句并要求核对，不会悄悄成为下一条输入。页面需要
分别保留当前预览与旧句更正。已经进入会话的原输入是实际记录，不会因更正被伪称撤销。
