# 可选的 JEV 字幕语义分块

本切片只对完整生成后的普通纯文字回复做有界字幕分块，不是模型 token 流。
主生成器仍须先交出结构完整的 CandidateRange。

在原来的 `tools/live_provider.py check` 或 `serve` 参数中增加：

```sh
--boundary-max-requests 20 --boundary-timeout-seconds 0.4
```

默认 `--boundary-max-requests 0` 完全不启用分块包装，也不增加 JEV 调用。
正数为本次进程额外的 JEV 边界请求上限，应用模式最多100；`check` 分别列出
输入判断、可选事件判断、边界判断和三者合计的请求上限。它们是技术次数限制，
不是美元账单上限。边界调用复用原来已明确授权的 TypeSafe/JEV 接收方和传输。
本轮测试全为合成，没有调用任何真实 provider、读取认证或新增安装。

只有24–4096个 Unicode code point、至少三个可切句子边界、恰好一个字幕且不含
语音/动作/场景/剧情/情绪/媒体建议的候选会进入分块。原文第一个完整句子立即
发放独立字幕许可；JEV只选择尚未发出尾部的少量合法分组方案，最多共四块。
JEV不能重写正文、产生任意偏移量、批准内容或颁发动作/语音许可。引号、括号、
数字、表情符号和组合字符按保守的原文字边界保留；这不是中文语义准确率保证。

边界等待默认0.4秒，可明确设为大于0且不超过2秒。UNKNOWN、低置信度、非法
响应、错误、超时或预算耗尽都保留整段尚未发出的原文尾部，绝不重新发送前缀。
等待上限是软件配置，不是实测服务延迟保证。迟到结果只可被丢弃，不能修改已发
字幕；Stop、新输入和关闭仍以本地当前版本为准。

字幕按独立阅读队列呈现，默认至少间隔800毫秒。只有实际执行了该块的呈现才
产生其回执和页面历史；队列时间不是音频对齐，更不证明用户已经阅读或听到。
代码偏移量均为 Unicode code point，前端使用 Array.from 计数，而非 UTF-16
字符串长度。每块正文是原文的连续不重叠切片，合并时不额外插入空格。

所有含 speech 的候选保留完整原字幕和原来的单一 speech，不增加 Google
请求，也不延后它等待新的分块判断。当前 Actor 会先等待语音权限判断再消费
下一个候选；合成失败测试证明，把语音放在第一小块会在该判断耗尽整轮时间时
丢失尚未消费的字幕尾部。因此本切片明确不支持语音逐段字幕，不把这一部分
写成完成。含可选事件的候选也保持整 cue，保留原剧情邀请的精确回执绑定。

源头终态错误、整轮 generation timeout 和用户取消仍沿原 Actor 的失效规则
处理；边界回退不能把失败生成或已取消话轮变成自然完成。真实 JEV 语义质量、
浏览器像素/设备听感、模型首字延迟和真实成本收益尚未验收。
