# MIRA Pixi 3分钟视觉检查卡

日期：2026-10-04  
状态：供之后实机/浏览器验收使用；源图和CSS几何已复核，尚无Pixi真实浏览器截图。

## 用途

用当前 WP04 交互确认：角色是否完整可读、相机/看雨动作是否与文案一致、照片出现后是否仍能认出镜头，以及Stop是否留下已经呈现的场景。角色帧是12张完整透明PNG，每次只显示一张；素材没有说话口型动画。`rehearsal`是离线固定流程，真实麦克风关闭；检查“speaking”时要确实听到预录音频，字幕本身不算听见声音。

## 3分钟顺序

尽量在同一台设备上完成：先截桌面1440×900，再把窗口调到390×844做窄视口观察（窗口模拟不等于真实手机验收）。每个状态稳定后截一张；记下浏览器、视口、按钮和遇到的现象。

1. **0:00–0:20，空闲基准**：在 `rehearsal` 打开页面，先看1440×900，再看390×844。确认画面只有一位Mira、眼睛嘴部清楚、相机可辨认、角色下缘没有被裁掉。桌面保留主标题；390px视口会隐藏大标题区，检查场景topline仍可读。
2. **0:20–0:45，放低相机**：点“先放下相机吧”。相机应降到腰部附近，暖表情仍能辨认。桌面人物caption不应挡住眼睛或相机镜头；手机视口有意隐藏重复caption。
3. **0:45–1:10，看雨**：点“一起听会儿雨”。头和目光应转向窗外，表情变成若有所思。雨窗/动作仍应清楚；不应只换了背景却让Mira继续直视镜头。
4. **1:10–1:30，组合表情**：在排练指引里点“暖灯”。暖表情应出现，而角色仍保持刚才的看雨方向；脸不应回到正面或相机动作被意外重置。
5. **1:30–1:55，照片叠层**：点“给我看看你的旅行”。照片应作为单独旅行插画出现；确认Mira的脸没有被盖住，相机镜头仍可辨认。记录照片具体遮到哪只手或哪段机身。
6. **1:55–2:40，Stop保持**：点“讲讲旅途”，等实际听见预录声音开始后按“停止回应”。声音和说话phase应立即结束，已出现的照片、雨窗和相机姿势应保留。当前PNG不会动嘴，因此没有口型动作不算问题。
7. **2:40–3:00，桌面复看**：返回1440×900，复看看雨或照片状态，确认人物没有跑位、被裁切或出现两张全身图叠在一起。

按钮文字均按当前页面可见文案记录；排练指引里的“暖灯”“讲讲旅途”需要使用离线 `rehearsal` 页面。[页面与按钮](../../apps/web/index.html)

## 当前布局估算

这些数字来自PNG和CSS计算，不是浏览器绘制或真实手机测量。

- v3可见脸部从额头/发际到下巴约312个源像素高；按1428像素源高度换算，约157个逻辑单位。
- **390×844**：Pixi舞台视觉区高520px，绘制区域约366×520；560×720角色图等比contain后约366×470px，脸约103px高。移动端隐藏大标题区与重复人物caption，保留场景topline；旅行照片缩小并上移。
- **320px宽视口**：角色横向受限，脸估约83px；这是窄屏空间限制，不应与390px目标混为一谈。
- **1440×900**：应用舞台约1280×620px，角色最大约520×620px；等比contain后实际图约479×620px，脸估约136px。与旧的140px桌面下限相差约4px，当前按接近目标记录，不为这点差异继续放大布局。
- 在手机视口中，照片遮到左手/相机一角仍需看最终截图确认；不能从源图和CSS单独判定通过。

## 怎样区分问题和偏好

**记作功能/呈现问题：**表情与动作组合错、相机未放低、看雨时仍正视、画面空白/重复人物、脸或眼嘴被标题盖住、镜头被照片完全挡住、边缘明显裁切或帧切换跳动、实际没听到音频却显示speaking、Stop后声音继续或已呈现场景/照片消失。

**记作审美偏好：**喜欢哪张表情、发型/服装是否更合心意、整体成熟性感程度、色彩冷暖、照片摆放是否好看。请给偏好打1–5分，并写最喜欢的一点和最希望调整的一点；这些意见不自动等于功能失败。

遇到问题时保存一张截图，并附：浏览器/设备、视口宽×高、刚点的按钮、预期状态、实际状态、有没有听到真实播放声音。可把一句主观意见标成“偏好”，避免和呈现缺陷混在一起。
