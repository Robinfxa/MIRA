# 同一 Wi-Fi 访问、默认免配对

普通 `tools/live_provider.py serve` 现在默认尝试让同一私人网络的设备访问，不再要求手动配对。**能访问该地址的人可能使用你已经启用的聊天、语音和生图额度。** 仅在可信私人网络启动，不要配置公网转发。

## 正常启动与地址

保留原来的 provider、model、env-file、auth-store、语音/图片授权及更小预算。服务只在明确调用 `serve` 时启动，不重新登录，也不复制其他应用的认证。

启动时只选择唯一可确认的活动物理 Wi-Fi/以太网 RFC1918 IPv4 地址。两个监听均为精确地址：

- 服务电脑：`http://127.0.0.1:8000`。原来的 `--voice`、浏览器麦克风授权和本机声音功能保留。
- 同一 Wi-Fi 的设备：终端输出的 `http://PRIVATE_IP:8000`，默认自动进入独立临时会话，无需配对码。这个 HTTP 入口只支持文字及已启用的图片功能，不录音、不合成回应声音。

例如电脑 IP 为 `192.168.2.13`，手机打开 `http://192.168.2.13:8000`。请以本次启动输出为准；若 DHCP 后地址改变，重启服务重新选择。手机上的 127.0.0.1 指向手机自己。

多网卡、没有合格地址或系统查询不可用时，终端会明确显示“局域网未启用，仅本机”，本机旧入口仍可使用；程序不会猜网卡。如果确认这台电脑的当前地址，可在原命令追加：

```sh
--private-bind 192.168.2.13
```

这会沿用同一个端口、保留本机入口并开精确 LAN 入口。显式地址无效或绑定失败会停止，不偷偷换地址。支持显式 RFC1918 IPv4 或 ULA IPv6；自动发现目前仅 IPv4。`0.0.0.0`、`::`、公网 IP 和 VPN/虚拟接口自动选择均不支持。显式 IP 并不证明网络可达或设备属于同一 Wi-Fi。

需要明确仅本机时追加 `--loopback-only`。已有 `--memory-db`、`--story-db` 或 `--conversation-db` 的持久模式仍默认限定本机单操作者及原配对，不自动共享私密库；和显式 LAN 参数组合会拒绝。普通 `--story` 是临时剧情，不属于持久库。

`check` 不探测网卡、打开监听、创建配对文件、读取登录、调用模型或验证账户；普通模式声明 `address_selection: on_serve`，真正地址由 `serve` 一次选择并用于同一个配置、输出和监听。

## 语音边界与 HTTPS

本机原 `--voice` 命令保持；手机 HTTP 不属于浏览器安全上下文，不能据此使用麦克风。LAN 入口从服务端禁止语音 HTTP/WS、声音偏好升级，并为该入口创建没有语音识别/合成端口的文字 Actor；只隐藏按钮不是这条边界。

手机也需要语音时，仍使用已有、两端都信任的 HTTPS 证书和原语音授权。显式 HTTPS 保持单 TLS 监听，电脑与手机使用同一个 HTTPS URL：

```sh
--private-bind YOUR_PRIVATE_IP --port 8443 \
--device-origin https://YOUR_PRIVATE_HOST:8443 \
--tls-cert-file /absolute/existing/certificate.pem \
--tls-key-file /absolute/existing/private-key.pem
```

没有配对目录时仍免配对。证书必须覆盖该主机名/IP、两端能够解析且已信任；私钥须本人拥有的私有普通文件，不能是符号链接。程序不安装根证书、不改变系统信任、防火墙、VPN 或路由器，不建公网隧道。不要绕过浏览器证书警告。麦克风仍需用户主动点击并授权。

显式 `--device-origin http://...` 是原单 LAN HTTP 模式，需要 `--allow-private-http-text` 并拒绝 `--voice`；若要保本机语音和手机文字，应使用上面的默认双入口或仅追加 `--private-bind IP`。

## 如果你仍想手动配对

在原命令中明确选择配对路线，并给一个已有、源码外、本人拥有、权限 0700、无符号链接的目录。例如仅文字：

```sh
--private-bind 192.168.2.13 --port 8000 \
--device-origin http://192.168.2.13:8000 \
--require-device-pairing \
--device-pairing-dir /absolute/existing/private/pairing-directory \
--allow-private-http-text
```

此路线保留两个一次性配对码；手机与电脑各用一个。需要创建新目录时，可在自己的终端运行 `mkdir -m 700 "$HOME/mira-pairing"`，再将其绝对路径用于参数；已存在目录不要重复创建或随意改变权限。

1. 启动后终端会输出两个不同的“Device … private pairing file”路径。
2. 在服务电脑亲自打开第一个文件，将整行代码输入手机页面，再点“确认并配对”。第二个文件代码用于电脑页面。
3. 每个代码五分钟内仅能用一次；浏览器访问有效八小时。刷新不用重配，临时对话会清空。
4. 服务重启、配对撤销或代码过期后，用新启动产生的新文件。不要把代码放到 URL、聊天、录屏或源码包。

配对语音须把 origin 换为已有可信 HTTPS 并保留 TLS/语音原参数。`--require-device-pairing` 与免配对开关不能混用；提供配对目录也会选择配对模式。`--trusted-private-network-no-pairing` 保留为显式兼容选项，不再是正常 LAN 免配对所必需。

## 会话与额度

- 默认免配对最多同时接入 16 个浏览器身份/临时会话，这是本机资源保护，不是限定两台设备。每个浏览器、每个访问地址有独立进程内随机 cookie；默认八小时或服务结束失效，刷新不延长服务端期限。
- 刷新或重连原子替换自己的会话并清空临时对话，其他设备继续。拿到另一个会话 token 也不能跨浏览器使用。实际接受请求的监听地址决定本机/LAN权限，不能靠伪造 Host/Origin 切到本机语音。
- “结束此设备会话并停止回应”释放自己的身份与会话。关闭标签页保留有界身份以支持刷新；清除 cookie、无痕窗口或另一个地址会占新名额。满额时在原页面结束、等过期或重启服务；并发首次开多个标签页也可能占多个名额。
- 所有入口/设备共享同一 provider runtime、STT/TTS/图片/API预算。没有增加任何 provider 上限或自动重试，也不把失败切到付费 API。订阅文字与 STT 的原本机无限默认仍受供应商配额/费用约束；原 TTS 20 次、图片 1 次等有限设置不按设备翻倍。
- HTTP 是明文；cookie、文字和会话内容在所选网络上不加密。免配对不是账号验证。私网模式关闭全局原始音频录制，持久库/档案仍不开放给 LAN。

## 验证范围

软件验证使用合成接口、ASGI、实际编译前端和本地回环服务器，不使用真实认证、付费模型或真实网卡。真实 Mac、手机、同 Wi-Fi 可达性、HTTPS 信任、麦克风、声学打断、实际模型与供应商用量仍需设备验收。界面打开不能代替语音通过。
