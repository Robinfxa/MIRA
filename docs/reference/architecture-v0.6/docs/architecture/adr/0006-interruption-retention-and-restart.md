# ADR-0006：停止未来演出、保持合法结果与因果重新开始

**状态：已确认（G04政策方向）；具体wire、算法、阈值与素材／设备能力未冻结。**  
**依据：D6，用户在G04论证与默认体验确认问题后回复。**  
**本版：v0.4 · 2026-10-02。**

## 1. 用户确认原文与范围

> 你思考的有道理，批准

该回复承接G4R与上一轮讨论。直接确认的体验命题是：停止回应后不再推进旧演出，仍获准且已显示的照片、已成立环境与预审雨声默认可以留下；全部静音、关闭画面或其它明确边界覆盖默认保持。

下面是对本轮G04方案的架构回填摘要，**不是用户逐字说出的长引文，也不是全部字段／素材／开关获批的声明**：

G04 默认停止当前回应的未来语义演出，不默认清空仍获准且已成立的场景结果。显式隐藏、静音及用户边界优先；场景保持不获得旧剧情继续执行权。安全收势只执行预审的非语义运行态过渡，不完成被取消的业务动作。明确停止使旧分支永久失效，新的有效交互以因果绑定方式重新开启新回应；同次主动输入可以同时制止旧回应并发起新请求。原分支恢复仅限未失效且输入、批准、游标、依赖、预算和能力条件全部满足，并遵守原语义恢复默认关闭的门槛。

## 2. 正文应保持的政策

- 暂停、停止当前回应、关闭指定对象、持续静音与重置不是同一操作。明确控制先本地生效，未知语义先抑制，不追加一次“可不可以停”的模型投票。
- 明确主动输入可以同时接管并发起新请求；旧未呈现分支失效，可靠请求形成后可响应同次交互。空输入不恢复旧分支。
- 照片保持同一合法内容与展示状态，不产生新披露；未来字幕、动作、镜头和未显示媒体取消。新交互清理主字幕位不抹去披露历史。
- 剧情视频停止时间线与人声、回到常驻角色；只有可核验且获准的已呈现静帧可以作为参照，不跳未来帧，不等同视频完成。具体静帧布局与资产能力待验证。
- 安全收势不完成被取消的原业务动作；原效果interrupted与停止过渡completed分开。不新增Interrupt Agent或自发放许可的场景系统。
- G02-A仍由同一Actor管理；回应分支与已成立场景维持的生命周期分开。停止／保持政策在获准时可供本地使用，客户端不得自行扩权。
- 重新开启绑定已处理停止依据、当前有效请求和新回应；更新停止优先。新回应获准不清除旧分支失效记录，不自动解除持续限制。
- 真正恢复只适用于未失效分支且全部条件满足。混合表演不仅检查音频；旧定时器不得追赶补演。已失效后的“继续”是基于真实进度的新计划。

## 3. 不隐含批准

不冻结具体事件枚举、停止锁字段、请求／停止关联算法、保持期限、作用域编码、snapshot迁移、TTS隔离与设备参数、回执持久化或UI布局。不宣称收势、静帧捕获、声音游标或混合恢复能力已经实测。

`pause_resume.semantic_resume_enabled`仍**默认关闭**；只有原适配器／设备与相关必需效果门槛通过后才可独立启用。推测合成等其它实验同样不因G04获批开启。G05后端、G06生成媒体、角色素材创作和reset语义不在本次自动批准范围。

本次不授权GitHub写入、产品部署或付费调用，不以批准架构替代验收。

## 4. 理由与未采用极端

只停声音会让无语音动作或未来字幕／媒体继续；每次清空全场会破坏已经成立的共同指代，也不抹除历史。当前选择同时保护用户接管与场景连续性。无条件恢复整场快照不被采用：各模态游标、依赖与最新输入不是一个可回滚物理时钟。[G4R §1–8]
