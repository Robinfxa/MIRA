# ADR-0007 · G05 判断分工与 Codex 订阅优先

**状态：方向已确认；具体承载与账户能力待验证。** 2026-10-02。

## 1. 确认依据 D7

用户在G05／G06联合论证后回复，原文如下（末尾括号按原话保留）：

> 我同意，但是我倾向于用codex的usage来做llm和生图功能，免费高效（当然也要预留api接口

“我同意”接受联合路线；后半句修改LLM／生图接入优先级，并要求保留API。下面是编辑性归纳，不是用户逐字批准了本轮新发现的OAuth路线、预算参数或app-server配置。

## 2. 已确定的架构

保留单一语义控制权威和可替换DecisionBackend。JEV继续作为文本Input／Output判断的首接入与中文评测对象，通过门槛后启用。实际图像由D-M直接读取；不通过文本描述冒充视觉检查。不同后端概率不伪等价，实质拒绝不换裁判直到允许。

LLM与生图优先考虑用户已有Codex／ChatGPT订阅额度，标准API适配必须保留。Codex是执行／认证承载，不是固定型号，也不替代Session Actor、G03范围审核或G04停止控制。没有批准取消JEV或把ASR／TTS全部换成Codex。

## 3. 新核查的能力边界与细化

M09区分原生Codex、专门授权的ChatGPT plan usage Responses以及Platform API-key。当前订阅Responses预览不支持托管image_generation，与Codex产品内置生图消耗通用额度是不同通道。真实生图桥接必须单独验证，不能将API-key静默塞给订阅worker。[CX1–CX7]

薄订阅Responses与app-server的选择、D-M订阅承载、线程隔离、额度观察及默认不自动花费是本轮实施细化；不把它们写成账户实测或已冻结wire。调用付费API、创建登录、购买额度、公开部署与GitHub写入均不在本次授权内。

## 4. 正文落点

总书§01.7；M02语义合同；M05生成适配；M09承载／认证／额度主合同；M01、M03、M04、M07、M08与A1–A3同步引用。G05方向不再未决，实际接口参数和探测留在实现接缝。
