## 00 总纲：本书回答什么

本书回答：在语音 v0.2 的实时控制基础上，MIRA 如何成为一个能够通过声音、动作、场景和媒体回应用户的角色系统；输入如何约束生成，内容如何获得执行资格，打断如何阻止未来效果，实际呈现如何成为下一轮上下文。

用户面对的是处于具体环境中的原创成年角色，不是以聊天消息列表为中心的助手。一次回应不再等同于一段语音，然而语音与同步字幕仍是产品必须提供的能力。[REQ，第1–3页；D1]

v0.5已经回填D7对G05／G06的同意与Codex usage优先、API预留。本版继承该决定，按模块加入开源复用证据；M09仍拥有后端边界，新增M10只提供实施交接，不增加运行时服务。文档v0.6不等于wire、账户权限或性能已验证。正文继续采用四种地位：

| 标记 | 含义 | 使用规则 |
|---|---|---|
| **已确认** | 用户明确指定或选择的架构方向 | 后续模块不得静默改变 |
| **来源基线** | 语音 v0.2、MIRA 等资料已有的机制／建议 | 保留来源地位；不等于代码已经存在，也不等于所有细节另获批准 |
| **细化提案** | Grill 中已提出的应用合同、字段、算法或实现映射 | 可以继续评审，不当作冻结接口 |
| **未决** | 尚需用户选择或集成证据的事项 | 不由开发者自行补写并标成既定需求 |

数值若来自 v0.2，仅是来源中的实验目标或配置起点。书中情节与动作例子是设计推演，不是已批准的美术资产、模型能力或测试结果。v0.5曾核查CX1–CX8对应的Codex／计划用量文档；本次仅使用该记录与借鉴书，不重新核查任何外部来源，也没有账户／模型调用。[V02，前言；MIRA，§1、§21]

## 01 已确认的架构决定

### 01.1 基础：语音 v0.2，不另造一套实时控制系统

用户明确要求“以语音 v0.2 为基础的多模态控制架构”，并先参考 GitHub ValueHermes 的 doc 文档进行详细设计。于是现有 Session Actor、Input／Output Decision、可取消运行时、身份与版本区分、单一角色人声仲裁器是设计出发点，而不是待替换的外围设施。[D0；ADR-0001]

参考 ValueHermes 的是设计方法与边界，不是将其投研业务、正式／advisory 账别、L2 子进程或完整通用 DAG 引擎搬到语音热路径。该仓库也不被描述为已有 MIRA 实时语音实现。[VH00；VH03；VH05]

### 01.2 G01：交流行为主导

用户选择 **B**。有效回应可以由语音、动作、场景变化、媒体展示或有依据的安静陪伴构成；非语音行为不必依附一段台词。继续使用一个 Session Actor、受控能力、执行资格和实际呈现证据。[D1；ADR-0002]

因此，“不要拍我”可以通过放低相机完成回应；“陪我听雨”可以通过应邀的姿态／场景变化建立安静陪伴。运行加载动画、无关微笑、空模型输出则不能自动充当实质回应。

这一决定没有批准持续自主导演 Agent、周期性主动搭话、自动推进剧情或生成媒体必选路径。

### 01.3 G01.1：约束前置、受限选择、完整审核

用户选择 **③**。Input Decision 识别请求、限制、指代、兼容性和未知项；Actor 结合作者策略、可靠当前状态与真实能力形成当前约束；主模型在合法范围内提出台词和表演；Output Decision 审核完整候选；运行时决定执行和完成。[D2；ADR-0003]

前置软建议不是必须说话或必须做动作的硬模式锁。输出 `allow` 不是播放器调用。主模型不能写权限、伪造回执、任意修改剧情状态，或者把失败效果改成已经完成。

### 01.4 G02：全局控制版本＋完整有效许可集合

用户在架构书 v0.1 之后明确回复“**G02 选 A**”。因此采用同一 Session Actor 发布全局有序的完整有效许可集合；语音、字幕、动作、镜头和媒体分别满足自身依赖后执行，不再把 A 仅列为建议。[D4；ADR-0004]

快照更新替换当前授权状态，不是重放命令。仍合法的语音流与效果在新集合中明确保留；撤销后旧集合不能恢复执行；本地活动与停止锁仍具有即时收紧资格的作用。控制快照与音视频数据分开，不按动画帧发布。详见 M04。

分通道版本＋公共撤销屏障的 B 方案保留为未采用备选；它不再是当前实现路线。此裁定不批准全部 wire 字段、摘要算法、期限、持久化或设备参数，在该次裁定时不替 G03–G06 作出选择；G03 后续由 D5 单独确认。v0.1 当时将 G02 留作未决的记录是正确历史，不回写成当时已获批准。

### 01.5 G03：同一次主要生成，按语义充分范围增量审核和发布

用户在G03论证之后明确确认：[D5；ADR-0005]

> G03 采用同一次主要生成，以完整且具备充分语义上下文的范围增量审核和发布。一个范围可以包含多个 beat；必要后文未知时等待，必要时扩大到整轮。保留 A 作为同合同的保守模式和评测对照，不把 C 放入默认主链。

这确定的是主生成拓扑与审核／发布粒度：继续使用TurnPlan／PresentationBeat，但一个审核／发布范围可以由多个beat构成；结构完整不等于语义条件完整。必要限定、后文或整体信息不足时等待，不能为了首段延迟强行拆分。A与增量模式复用约束、内容审核、G02许可、执行和回执合同；C不作为默认新增导演调用。

生成、审核、执行和事实提交仍分开。后段生成可以与有效前段的审核／准备／呈现重叠，但已接受内容不得被后段原地改写；有界FIFO与连续已批准范围继续成立。具体解析、审核范围身份、计划封口和局部失败细化归M03；审核上下文及请求覆盖归M02，TTS衔接归M05。[G3R §5–10]

本裁定没有证明供应商结构化流已经可用、语义判定绝对正确或B实测更快。准确wire格式、算法、启用配置与验收阈值仍需实现证据；不自动启用推测TTS、语义恢复或G06生成媒体。

### 01.6 G04：停未来、保结果；恢复与重新开始分开

用户在G04论证后回复“**你思考的有道理，批准**”。该回复确认本轮停止／保持政策，尤其是停止回应后照片与预审雨声可以默认留下，明确关闭／全部静音覆盖默认保持。以下为架构归纳，不伪装为用户逐字长引。[D6；ADR-0006]

G04 默认停止当前回应的未来语义演出，不默认清空仍获准且已成立的场景结果。显式隐藏、静音及用户边界优先；场景保持不获得旧剧情继续执行权。安全收势只执行预审的非语义运行态过渡，不完成被取消的业务动作。明确停止使旧分支永久失效，新的有效交互以因果绑定方式重新开启新回应；同次主动输入可以同时制止旧回应并发起新请求。原分支恢复仅限未失效且输入、批准、游标、依赖、预算和能力条件全部满足，并遵守原语义恢复默认关闭的门槛。

G02-A继续是唯一授权组织方式。回应分支与已成立场景维持不共享单一寿命；保持政策提前可供本地使用，不能演化成第二套权限系统。新回应不会解除旧分支失效，也不自动解除持续静默／隐藏边界。具体停止事件、因果关联、保持期限、收势资产、静帧与混合恢复能力仍需冻结／验证，G05–G06不在本次批准范围。

### 01.7 G05：按真实能力分工，LLM承载优先订阅额度

D7同意G05／G06联合路线，并提出优先用Codex usage做LLM和生图，同时保留API。JEV仍是文本语义判断的首接入与中文评测对象，D-M直接读实际图像；不因为想统一计费而取消G01.1分工。LLM承载与实际型号分开，订阅优先不保证原Luna型号可用。[D7；ADR-0007；G56R]

v0.5的官方文档记录指出专门授权的ChatGPT plan usage可承载eligible Responses请求，且该时点预览不支持托管生图；这与Codex产品内置生图不是同一能力面。本次仅继承该来源记录，不将其改称2026-10-03的在线核查。具体比较薄OAuth请求、原生Codex或app-server适配的实现提案归M09，不能把公开端点等同于API-key计费，也不能把产品内置能力等同于已验证runtime接口。[CX1–CX7]

### 01.8 G06：受控异步图片，Codex生图优先，视频非默认

以角色动画和受控素材维持稳定体验，在线图片仅为可失败的场景／物件／想象再现。原生Codex订阅生图优先验证、标准API保留；实际结果须直接读图验证并通过当前情境检查后才展示，不展示未核验预览、不掌握关键披露和人物身份、不将生成再现当现实事实。现场生成视频不进入默认链路。[D7；ADR-0008]

“免费高效”是用户的经济与性能偏好，不写为事实或SLO。额度耗尽不会授权自动付费、换账号绕限额或降低审核标准。API预留不等于额外消费授权；实际wire、账户、模式与预算参数仍需验证。[M09]

## 02 产品范围与交付底线

需求范围是移动端网页优先、单个原创成年角色、连续 3–5 分钟互动。基础场景可使用雨后咖啡馆与摄影师 Mira，但秘密内容、具体动作和剧情路线仍属于创作输入。[REQ，第1页；MIRA，§1]

| 需求 | 架构承接 | 不能被替代的证据 |
|---|---|---|
| 场景和角色主界面，文字／语音入口 | 场景层、输入控制器、字幕层 | 实际移动页面，不是只有接口说明 |
| 待机、倾听、思考、说话可感知 | interaction_mode 与受控表现映射 | 画面能辨认，不只是内部状态枚举 |
| 麦克风、多轮语音、同步字幕 | 语音 v0.2 运行时与同源正文 | 实际收音、输出、字幕与连续上下文 |
| 说话中打断、旧响应不复活 | 本地先抑制、分支失效、执行前检查 | 声音及未来字幕／动作／媒体均停止 |
| 3种表情、2种非说话动作、1次环境变化、1次对话触发视觉事件 | 真实能力目录、表演计划、呈现执行器 | 真实资产与内容触发，不是虚构动作名或固定计时播放 |
| 至少一种多模态表现 | 角色动画、状态驱动视频或生成媒体路线 | 所选正常路径真正可运行，加载／失败／中断得到处理 |
| 端到端、状态连续、无密钥体验 | 同一运行合同的真实／Mock／回放适配 | 不另写一条仅供演示的独立流程 |
| 源码、启动、录屏、README、AI_USAGE | 工程交付与证据说明 | 3–5分钟录屏含打断和至少一种失败／降级 |

以上数量和交付要求来自需求书，不是本书新增指标。完整映射归附录 A2。[REQ，第1–5页]

## 03 系统画像：一个有状态角色，一条受控执行链

```text
文字 / 麦克风 / 明确停止 / 已支持的场景交互
                  ↓
客户端快路径：活动观察、停止锁、本地抑制与预审保持（G04）
                  ↓
每会话一个 Session Actor
  输入快照与话轮 / 输出分支 / 当前事实与剧情许可
  语义判断任务 / 主生成与TTS任务 / 计划与实际呈现账本
                  ↓
Input Decision 观察 + 当前可靠状态 + 作者策略与真实能力
                  ↓
Actor 组合本轮回应约束（ResponseContract 为细化合同名）
                  ↓
ContextPacket → 同一次主要生成提出完整 TurnPlan / PresentationBeat 候选
                  ↓
结构与能力检查 → 组成具备充分语义上下文的审核范围（G03）
必要时合并多个 beat，必要后文未知时等待至整轮
                  ↓
Output Decision → 连续已批准范围 → Actor 重验当前有效性
发布全局版本的完整有效许可集合（G02-A）
                  ↓
客户端本地检查与依赖调度
  ├─ Playout Arbiter → 角色人声
  ├─ 字幕
  ├─ 动作与表情
  └─ 场景、镜头、图片、视频
                  ↓
实际呈现 / 失败 / 中断回执 → Actor 归约 → 下一轮上下文
停止后新交互以因果绑定重新开启；失效分支不复活（G04）
                  ↓
后台记忆索引与整理（派生通道，不是当前权限权威）
```

图中的职责链体现已确认方向与来源基线。G02-A 的授权组织方式与G03的语义充分范围增量发布均已确定；A仍作为同合同整轮保守模式和评测对照。`ResponseContract`、许可wire、生成framing、审核范围字段和适配器细节仍按各模块的细化状态执行。

逻辑模块不等于微服务。v0.2 的第一版是异步服务进程内多个模块，每个会话一个 Actor；耗时网络工作异步启动，结果回到 Actor 顺序应用。Actor 不能因为等待模型而停止处理打断。[V02，§4]

## 04 构件与生命周期

| 构件 | 核心职责 | 不拥有的权力 | 详稿 |
|---|---|---|---|
| Session Actor／状态归约器 | 当前状态、分支与资格、接受计划、回执提交 | 不把语义猜测当确定事实 | M01、M04 |
| Input／Output Policy | 组织有限语义问题与候选审核 | 不调用播放器、不签发权限 | M02 |
| 主生成与计划编译 | 同一次主要生成、完整范围冻结／接受、编译受控效果 | 不伪造资产、身份、完成状态 | M03 |
| 语音运行时 | ASR、正文FIFO、TTS、等待语、单人声仲裁 | 不接管另一份独立剧情历史 | M05 |
| 呈现调度与适配器 | 本地活动检查、资源依赖、真实执行与回执 | 不独立决定用户意图或推进剧情 | M04、M06 |
| 人格、记忆与场景资产 | 人设、当前事实、联想、storylet、能力映射 | 派生记忆不覆盖实时边界与许可 | M06 |
| 观测与回放 | 区分判断、执行与事实，提供可复查证据 | 测试记录不直接成为用户经历 | M08 |
| 后端承载、认证与额度 | 订阅优先与API接口、任务隔离、能力探测 | 不发内容许可、不自动付款、不成为第二份历史 | M09 |

| 生命周期 | 穿过的主要构件 | 结束依据 |
|---|---|---|
| 普通语音回应 | 输入→约束→生成→审核→TTS→许可→播放 | 实际交付及本次必需效果 |
| 非语音回应 | 输入→约束→表演候选→审核→许可→动作／媒体 | 行为对应的可核验完成条件 |
| 安静陪伴 | 请求→建立行为→场景回执→保持状态 | 建立行为有终点，持续模式不占用无限生成任务 |
| 打断与续接 | 本地抑制→输入重验→失效或条件恢复 | 不复活失效分支，按已呈现事实重建 |
| 媒体迟到／失败 | 任务有效性→资源和内容检查→当前资格 | 失败不写成功；就绪不自动展示 |
| 记忆整理 | 来源事件→后台提取／索引→当前有效性检查 | 派生结果可重建，不成为即时权威 |

非语音完成字段仍按H2细化；G04已确定停止／场景保持政策。具体完成schema、保持作用域编码和资源能力仍未冻结，不因本表而视为全部批准。

## 08 本版内容与实施之间的界线

本版形成架构合同与实现借鉴的统一入口。现成桥接、语音、角色、记忆和测试工具按M01–M10落位，不再把基础能力整体描述为从零研发；但本项目仍未形成已验收的产品实现、账户接入、真实声线、动作资产或移动端性能。来源静态检查不能折算为运行体验验收。

已经明确的方向可以指导接口拆分与测试设计，但完整运行协议仍需冻结 G02-A 的实现细节，还需冻结G03的解析、范围审核、封口和TTS接缝，还需冻结G04停止／保持／因果重新开启的实现接缝，同时须完成G05／G06的中文、实际图像、Codex订阅承载与API接口验证。各项不明之处应作为可定位的未决合同存在，而不是由代码、prompt或Mock暗中补完。

本版不新增72小时排期承诺。资料已有的实施顺序与交付底线归 M08；其作用是明确依赖，不保证未知团队在特定时点交付。[MIRA，§20；REQ，第5–6页]

## 09 文档维护规则

批准范围记在 ADR 与 A1；相应条文回填到模块章；总书只保留跨模块结论与链接。后续评审修改具体章节和未决状态，不再让“最新一轮Grill”成为唯一知道当前架构的地方。

来源文件和旧Grill保留历史版本，不能回写旧提案伪造成当时已获批准。单文件阅读版由分章生成；文档结构检查仅验证路径、来源和批准状态的一致性，不代替架构正确性或产品验收。
