### D5确认原文

> 同意，G03 采用同一次主要生成，以完整且具备充分语义上下文的范围增量审核和发布。一个范围可以包含多个 beat；必要后文未知时等待，必要时扩大到整轮。保留 A 作为同合同的保守模式和评测对照，不把 C 放入默认主链。

“先论证”是本次确认之前的过程要求，不是提前批准；G3R是该要求产生的历史论证稿。本次D5确认后才改变当前G03状态。

## 4. 后续回填规则

用户裁定某G项后，在本表记录选择与确切范围、建立相应ADR并更新唯一主章节；涉及其它模块时更新引用和受影响合同。没有明确回答的事项保持未决，不通过工具执行、schema生成或Mock表现擅自结案。

旧历史文件不回写批准状态。单文件阅读版重新构建；本版未对GitHub作任何更改。

## 5. D7后的明确修订

G56R原“Image API首个适配”和“Luna配置不变”的接入优先级，由D7的订阅优先偏好修订；逻辑GenerationBackend与语音控制不变，实际型号不保证相同。JEV仍保留首接入定位，不能借LLM偏好将其全部换成Codex。

D-M可优先探测有真实图像输入的订阅承载，但不得将生成器自评当独立检查。API预留不授予额外花费；默认不自动付费是执行边界，具体预算仍需确认。G05／G06已确认方向和M09未冻结细节分开。
