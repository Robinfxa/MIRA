# M02 语义判断与回应约束

> **v0.6整合说明：** 原架构合同继续有效；本章新增“复用落点”只将借鉴书的既有证据和建议接到本章。具体技术栈未由本次整合自动批准；差分见A4，源码原阅读范围见A5。


**地位：** G01.1职责分工及G03完整语义充分范围增量审核已确认；G04停止／保持政策也已确认，本章回填必要审核上下文、覆盖区分及干预范围。问题原语、精确字段和阈值仍为细化合同。  
**依据：** D2；V02 §5.3–5.4、§7.5、§8.3–8.4；H1 §5–6；H2 §8；H3 §1–2；G3R §5–8；D5；VH14 §1–2。 D6；G4R（相关小节见正文）；ADR-0006。

## 1. 已确认的判断权链

```text
Input Decision观察
  → Actor组合当前约束
  → 主模型在合法集合内选择具体表演
  → Output Decision审核完整且具备充分语义上下文的范围（可含多个beat）
  → Runtime重验资格并执行
  → 实际回执决定提交与完成
```

Input Decision不锁死每一轮必须说话或必须做动作；它识别要求与限制，提供表达软建议。主模型不能以人物自然性为由越过有效边界。Output Decision也不能直接操作播放器。[D2]

本章的“Decisions”首先表示应用语义判断职责。原v0.2用JEV作为主语义控制候选，将OpenAI Decisions API放在待接入接口位置。D7接受G05按实际能力分工：JEV仍是文本首接入对象，D-M直接读图，LLM／生图订阅优先、API保留。固定型号、账户和返回schema必须验证，不从名称推导能力。新承载候选归M09。

## 2. 输入state必须包含实际演出上下文

纯转写不足以解释“这张”“停一下”“别解释了”。H1提议的DecisionSnapshot应包含：

```text
snapshot_id / event_watermark
activity_seq / input_epoch / input_revision
output_epoch / generation_id
当前完整转写与可靠输入事件
已呈现 / partial / unknown内容
当前可见对象投影、素材引用与投影水位
具体未执行候选、效果与依赖
真实正在进行的生成、TTS或媒体工作
有效边界、当前允许的剧情事实、能力目录版本
判断政策版本及相关上下文依赖
```

“可见对象”来自真实呈现记录及其有水位投影，不等于已知用户眼神。没有采集的摄像头、目光和声音信息不得补造。未获准秘密也不因为是“判断请求”就可以被外发。[H1 §5.2、§6.1；MIRA §6、§9.3]

## 3. Input Decision问题集的整编

| ID | 判断内容 | 结果作用 | 边界 |
|---|---|---|---|
| I1 | 输入是否完整、用户是否让出话轮 | 与可靠声学状态组合 | ASR final不是整个话轮结束 |
| I2 | 附和、纠正、停止解释、改变展示、换话题 | 帮助决定适用性与处理范围 | 明确停止不等待模型许可 |
| I3 | “这张／那里”对应哪个允许候选对象 | 指代候选或ambiguous | 不让模型创造不存在的对象身份 |
| I4 | 具体未呈现候选／效果是否仍兼容 | compatible／冲突／需重规划／unknown | 同话题不等于旧回答应继续 |
| I5 | 本次要求、实现限制与表达软建议 | 进入ResponseContract | 按G01.1，不是单一硬性模式锁 |
| I6 | 是否接受当前邀请的具体行为 | 绑定邀请与输入依据 | 旧“可以”不授权新披露 |
| I7 | 表达方式、动作强度、等待语是否需调整 | 适用范围内的偏好更新 | 不能装饰性重启正确正文 |
| I8 | 值得准备哪种工作 | 检索、文本、素材预载或媒体准备意图 | 外传、费用、并发与执行由程序限制 |

**I5的显式演进：** H1曾用 `speech/gesture/media/mixed/quiet` 作讨论枚举；H2指出它混合媒体通道与交流方式；G01.1最终选择的是权力分工，不是批准这个枚举。当前正文以请求、限制、软建议分开表达，具体schema仍待冻结。

问题可以共享完整快照，但不能在并列问题中暗中依赖另一题刚返回的答案。若先选对象再据选择判断后续动作，需要代码组合或显式下一阶段，不能把存在顺序依赖的推理声称为独立并行。[V02 §5.3；H1 §5.2]

### 3.1 G04的干预、指代与重新开始判断

| 位置 | 细化内容 | 权力边界 |
|---|---|---|
| I2 | 暂停、停止回应、关闭对象、改约束、换话题与unknown | 明确控制先本地执行；不靠孤立关键词，不额外投票批准停止 |
| I3 | “这个／继续”指当前对象或被中断活动 | 不引用未展示未来媒体，不默认同时启动全部通道 |
| I4 | 旧候选是否仍回答当前请求，必需依赖是否受影响 | compatible不等于恢复许可；同话题新问题不继续旧讲解 |
| I5 | 停止后是否还有可靠新请求，持续静默／隐藏是否仍适用 | STOP本身不邀请额外回复；同次主动输入可停旧并请求新回应 |
| I6 | 明确拒绝关闭OpenIntent，新请求重新评估 | 旧“可以”不恢复已拒绝行为 |

相关快照需要停止依据、同次用户交互关系、当前隐藏／静音状态及待续对象，准确字段待冻结。不新增Interrupt Agent。模型观察仍是可出错的语义解释，停止锁、因果检查和资格由程序处理。[D6；G4R §7、§9]

## 4. ResponseContract：Actor组合，不是模型发证

字段提案如下：

```text
ResponseContract
  contract_id / contract_digest
  basis_input_epoch / basis_input_revision / event_watermark
  character_revision / relevant_context_revision
  governing_policy_refs
  response_obligations[]
  effective_constraints[]
  allowed_capability_refs[] / allowed_disclosure_refs[]
  preferred_realization_hint
  unresolved_items[]
```

有效限制保存来源、作用对象、范围、解释状态和解除／替代依据。不能只保存 `speech_allowed=false` 却不知道为什么禁止、多久有效、是否包含等待语和视频角色人声。[H3 §2]

明确按钮、作者规则、有效用户边界与素材能力由其原owner供给；自然语言判断是可能出错的解释，程序应用过一次不使其获得数学正确性。未知时保留unknown，不默认为更大权限。

“不要说话，给我看看刚才那张照片”包含不讲话与展示正确照片两个要求。主模型可以设计允许的展示方式，不能把无关沉默当满足；若照片不可用，走符合当前限制的失败／澄清路径，不能用TTS偷偷绕过静默要求。

## 5. Output Decision：审核完整语义充分范围（G03）

| ID | 判断对象 | 程序如何使用 |
|---|---|---|
| O1 | 当前完整范围的可发布性、必要后文、无依据断言 | 必要后文不足时等待／合并，必要时到整轮；只推进连续已批准范围 |
| O2 | 范围内台词／动作／素材是否一致，是否与有效已接受前缀冲突 | 不能忽略已接受但尚未播放的前段；冲突候选不执行 |
| O3 | 是否假定物件已展示或动作已完成 | 提示依赖；真实依赖由程序绑定和核实 |
| O4 | 是否越过当前边界或允许剧情事实 | 与确定性许可、能力和受控披露共同约束 |
| O5 | 是否显著偏离角色与情境 | 区分软偏好与实质上下文变化 |
| O6 | 当前范围是否有效推进请求；封口时整体是否覆盖仍有效的义务 | 阶段推进不等于整轮完成；未满足义务保留；无关装饰不抵消请求 |

O6来自H2对G01.1的细化，现按G03论证区分阶段推进与整轮覆盖；编号不是新增模型服务。无语音候选同样审核语义动作与媒体，文本为空不是绕过入口。[D5；G3R §7]

批准绑定当前合同、精确内容、动作参数、素材版本以及依赖／完成政策引用。内容变化必须使相关批准失效；内容不变但依据变化，也需重新核验适用性。不能只检查 `allow=true`。[H2 §8.4；H3 §2.1]

### 5.1 审核必须看到的前缀

审核输入包含本次合同、实际已呈现及partial／unknown范围、**已接受但尚未呈现的有效前缀**、当前完整候选，以及必要的有限后文。只提供已播文本，无法发现与已经排队但未播内容的冲突；失效候选不混入有效前缀。[G3R §6.3]

结构解析成功只使候选可审，不使其可发。必要限定尚未得到时等待或合并相邻beat；时间／字数阈值不构成allow。精确范围身份、内容摘要、合同和依赖由程序绑定，不使用尚未完成且持续变化的整轮plan摘要。[G3R §5、§6.3]

### 5.2 阶段推进、整体覆盖与实际完成

用户要求“先看照片，再说明拍摄地点”时，展示照片可以是有意义的第一范围，地点义务仍保留。不能要求每个首段解决全轮从而强制退化为A，也不能因第一段相关就把整轮标记完成。

封口时整体语义覆盖须收口；实际完成还依赖必需效果回执。语义收口可并入最后一个必要审核范围，不默认再串联固定导演／审计调用；具体调用策略与预算需冻结。模型不能删除未完成义务或自报完成以绕过收口。[G3R §7–8]

### 5.3 G04后的新计划审核

O1／O2／O3／O6不得把旧未播尾部、未完成视频或被取消动作当成已经完成。旧待执行前缀失效后从有效前缀中移除，真实曝光与partial／unknown仍保留。新计划需要处理当前请求、重新核验展示对象与未完成义务；重新开启不自动解除持续限制。[G4R §9–11]

## 6. 结果状态不能压成一个布尔值

H1建议的DecisionObservation分开保存：request身份与snapshot、问题集与provider合同版本、真实请求状态、归一化答案、适用性、语义不确定性及获准的诊断引用。

```text
HTTP成功 ≠ schema合法 ≠ 语义明确 ≠ 仍基于当前状态 ≠ 可执行
```

超时、传输错误、契约错误、语义拒绝、unknown和过时是不同原因；不把它们统一成false后丢失事实，也不以超时默认allow。禁止用hash假装保存了可以重验的完整响应。隐私、凭据与未披露剧情同样限制诊断材料。[H1 §6.2]

## 7. 语义判断与确定性关口

D-M仅在未知媒体结果需要真实内容验证时触发；固定素材可引用相同版本的已有审核。处理的是实际结果，不是拿生成prompt证明生成内容正确。G06已确定受控图片、未审核预览不显示、现场视频非默认；G05确定实际读图。具体后端、生成域可判定程度与产物合同待实测。

D-EXEC继续检查会话、客户端、本地停止、版本、有效分支、批准身份、能力、依赖、资源与游标。D-COMMIT核验回执和截止范围，决定实际呈现记录。两者不由语义模型投票。

输入返回、输出审核返回、资源就绪、许可发放、实际执行、回执提交分别是有效性检查点。增加这些程序检查，不等于增加六次串行模型调用。[H1 §5.5；H3 §7]

## 8. 调用纪律与验收

输入沿用一个in-flight加一个latest-pending完整快照；原始delta先累计修订。输出沿用有界冻结FIFO；晚到的后段不能覆盖必要前段。停止、回执和批准结果不是可丢弃的输入快照。模型不按音频帧、动画帧或每次眨眼调用。[V02 §5.4、§8.4]

G03回填还需比较必要限定跨beat、有效待播前缀冲突及封口覆盖；固定回放不能证明语义充分性判断正确。

验收分别检查：限制提取、指代、请求覆盖与一致性的语义质量；合同身份、失效、unknown处置和本地资格的确定性正确性。不能用类型测试证明语言理解正确，也不能用自然性评分放过错误授权。

已确认G05路线后的实现未决：具体后端版本与账户；问题原语及归一化schema；冲突处理与置信阈值；字段hash规范；额外判断的实际延迟／成本；D-M内容验证范围。现有材料不支持填入一组已验证数值。

## 9. G05原语、证据与错误的执行合同

D7承接G56R的语义分工与中文门槛。按Noul／Choice／Score等真实原语映射，而不是让有限判断接口自由生成状态补丁。I2／I5中的多要求可能同时成立，不强行互斥；I3提供none／ambiguous。没有对应受控谓词时保留原文和unresolved，不凭空捏造规范化规则。[G56R §3–4]

统一DecisionObservation的是问题、快照、范围、结果与来源；不统一伪造confidence。原语不同，返回验证也不同；缺题、格式错误、异常概率、技术超时、语义未知和reject分开。阈值绑定固定模型与题目，按中文输入验证，不沿用营销准确率。

每项必要判断固定当前活动后端，shadow只进评测。实质拒绝不换裁判抽签；技术回退只有在既定路线、外传、费用许可和剩余截止预算内进行，各层重试共享预算。必要内容判断失效不能默认allow，图像检查不可用则关闭该新图，不拖垮仍获准的角色基线。[G56R §5]

## 10. 订阅承载不改变判断权

D7没有取消JEV。主LLM生成与D-M的订阅路线是M09中的承载选择，不能把Codex生成时自评直接当Output Decision或D-M。D-M取得实际像素，独立受限上下文并保留unknown；相同模型分两次调用不保证统计独立。

新的订阅路线、API-key与原生Codex不能复用未经校准的概率／错误规则。执行器只接受当前范围的有效批准，账单来源与剩余额度从不替代内容合格、最新输入或实际回执。
