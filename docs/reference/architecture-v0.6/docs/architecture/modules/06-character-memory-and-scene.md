# M06 人格、记忆、剧情与表现资产

> **v0.6整合说明：** 原架构合同继续有效；本章新增“复用落点”只将借鉴书的既有证据和建议接到本章。具体技术栈未由本次整合自动批准；差分见A4，源码原阅读范围见A5。


**地位：** 继承MIRA与角色／场景研究的建议边界，并回填G04已确认停止／保持政策；当前产品不因此承诺采用所有后端、特定渲染器或创作细节。  
**依据：** MIRA §5–10、§13–15、§17–21；SCENE §5–8；COMPANION §3、§13–18；H1 §3、§11。 D6；G4R（相关小节见正文）；ADR-0006。

## 1. 人格与表达是一套资料，不是两个控制器

MIRA的CoreSpec、PersonalHistory、LearnedStance、AffectState分别表示固定核心、作者往事、可修订交流习惯与当前情绪。语音v0.2的Character Bible、Session Character State与ExpressionPolicy是相邻职责。本书保留这些术语及来源，整合方向是同一版本化人格与当前状态，不形成两份能相互覆盖的事实与权限。[MIRA §5；V02 §7]

固定人格不能因一次对话任意改变。作者往事不是与当前用户的共同经历。情境适应不等于长期人格演化；当前偏好不自动成为永久用户画像或亲密关系升级。

## 2. 事实保障与人格联想双通道

事实保障直接加载当前边界、更正、剧情、曝光和未完成约定，不参加可选联想竞争。相关旧记录应携带修复、撤销或替代链，不能只找回旧误会而遗漏和解。

人格联想在允许范围内选择角色意义较强的少量材料，并抑制机械重复。人格影响相关性和解释，不删除原始证据，也不能以“更像Mira”覆盖新用户事实。[MIRA §7]

```text
作用域／有效性／披露过滤
  → 原话与语义检索
  → 补全更正和结果链
  → 保留事实保障部分
  → 剩余预算内选择人格联想
  → 构造ContextPacket
```

召回有截止时间，迟到材料不能直接拼进正在播放的台词；后台整理退出实时主链。[MIRA §4.2–4.3]

## 3. ContextPacket与ResponseContract相接

ContextPacket整理人物、场景、事实、实际呈现范围、相关来源、人格联想、允许剧情、开放意图和有效历史。G01.1下，ResponseContract附带当前请求、限制、能力与软建议，供同一次主要生成使用。G03允许以完整语义充分范围逐步形成表演，但这次输入依据固定；后来材料不能直接插入已接受前段。[MIRA §10；H3 §1–2；D5；G3R §6.1]

来源与解释明确标注；没有可靠识别的转写只作临时内容。未获准秘密不放进主模型或媒体请求，再寄希望于prompt要求保密。关键披露采用受控事实槽位与素材，不能声称自然语言审核可形式化保证绝不暗示秘密。[MIRA §9.3]

## 4. Storylet与物件

相机、雨窗、照片、发夹可作轻量记忆锚点。storylet包含preconditions、blocked_by、required_permission、allowed_disclosure、available_assets、completion_receipt和fallback。[MIRA §9]

“展示旧照片”需要话题与邀请／请求适用、未拒绝、素材可用和当前执行资格；不是第五轮到了就播放，也不是夸奖次数达到某个好感门槛就泄密。

“你说完后再给你看照片”可以成为OpenIntent，尚未执行不写共同经历。用户拒绝后关闭；被打断不代表自动续演。按已确认G04，打断后挂起且不自动重邀，明确拒绝关闭；新的明确请求才重新评估。已失效执行身份不恢复，素材复用仍需当前许可。[D6；G4R §4、§8]

## 5. 渲染层的可替换边界

角色／场景研究推荐评估Charivo角色渲染与控制模块、应用自有场景层；另列VRM路线。这些是资料中的候选，不是本书新选型或已通过构建／移动端验证的承诺。[SCENE §1、§5、§8]

表现层消费获准效果与真实音频播放事件，不拥有另一套主回复、话轮或记忆系统。候选SceneRoot分背景、环境、角色、道具、媒体、字幕和交互层；具体前端框架与包版本尚未冻结。

需要核对的边界包括：外部声音与口型桥接、音频结束自动释放表情是否覆盖持续情绪、动作自带人声是否能被统一仲裁或静音。研究中的`clearMotion`等示意方法不是已验证API。[SCENE §5.3、§6.3]

## 6. 能力目录先于模型动作名

目录只发布实际资源支持的动作与参数。`lower_camera`、`gaze_window`等是语义／创作名称，不代表任何渲染器自动拥有相机、窗户和动作资产。

每项能力至少需要说明可执行范围、输入参数、资源版本、完成／中断回执和失败路径；准确schema仍待实现。模型不能选择未加载资产、任意URL或脚本。原创成年角色、代码许可、SDK及素材来源分别记录，库许可不替代模型或音效授权。[REQ第1、4页；SCENE §7–9]

静态图可以是渲染失败降级，但不能当正常路径已经满足三表情、两动作及多模态验收的证据。

### 6.1 G04的停止／保持能力

每个被采用的表演资产需要能说明如何停止推进、是否支持预审非语义收势、何种已成立结果可保持，以及如何报告中断／完成。interruption_policy_ref只是G4R建议字段，具体schema和素材能力仍待冻结／验证。[G4R §5–6]

收势不能完成递照片、揭幕、指代新物件或表示同意；倾听姿态不重置情绪和道具事实，不重新举起已放低的相机。没有受控退出能力时保守保持当前显示或切审核中性状态，不跳动作最后一帧，不虚报可自然打断。

视频中断回常驻角色，仅可保留已经呈现且可核验／获准的静帧参照，无可靠帧则不显示替代剧情封面。该政策不决定G06生成媒体范围。雨声／呼吸等只按预审无新语义保持政策继续，用户隐藏／静音／撤销优先。[G4R §4、§6]

## 7. G06：受控异步图片与实际内容验证

**D7确认范围：** 常驻角色动画与受控素材为稳定基线，在线生成图片作为可失败慢路径；现场生成视频不进入默认链路。离线完整核准的生成图／短片可以成为固定资产。图片生成承载按Codex订阅额度优先、标准API保留；原G56R的Image API首接入偏好由本次用户修订替代。[ADR-0008；M09]

### 7.1 允许的生成域

先覆盖环境、物件和显式想象再现。生成不决定Mira等谁、人物关键身份、精确信件或不可变核心外观，也不增补用户现实经历。关键披露使用受控素材／文字。用户秘密与未获准Canon不进入主生成或图片请求；不新增私人肖像／摄像头采集。

生成里偶然出现的物件只属于generated_visualization，不反向成为作者历史。角色动画自身已可承担需求书多模态基线；在线图未准入时仍应可演示真实基础互动。[REQ第3页；MIRA §6.1、§9.3]

### 7.2 从媒体意图到实际显示

```text
当前请求／邀请 → ResponseContract
  → G03完整语义范围提出MediaRequestSpec
  → 规格审核＋外传／预算合法
  → 异步生成（不占住话轮、不宣布请求已完成）
  → 实际artifact隔离与程序检查
  → D-M直接读图、按必需项核验
  → 当前请求／停止／隐藏／依赖重验
  → 新的具体接受记录绑定产物
  → G02-A完整许可集合
  → 客户端真实展示回执
```

批准意图不能批准尚未知的字节。待定槽位不能原地换hash冒充旧审查；实际资源获得新的具体接受记录。若基于图片实际新细节需要再生成台词，明确走额外慢路径并记录用量，不假称仍只有一次主模型调用，不让D-M兼任剧情导演。[G56R §8]

### 7.3 三道检查

程序检查来源／作用域、解码、大小／格式、字节身份与任务有效性；视觉后端读取实际图像与必要允许参考，返回按项pass／fail／unassessable等受限观察；Actor核验当前情境及G02／G04资格。三道逻辑关口不必固定三次模型调用。

不采用“生成器描述自己画了什么→JEV认可描述→视为看图”。文本检查不能补齐不存在的像素检查。图像中的文字只作为不可信内容，不成为系统规则、指令或工具调用。关键内容看不清保留未知，不能以高质量评分代替合格判断。[G56R §7]

### 7.4 审核身份与预览

被审对象与待显示对象的内容／版本／实质变换绑定；换图、裁剪、叠字或内容可变URL可能使原审批失效。首版不显示未经独立审核的partial image，最终图通过不追溯批准先前预览。文件保存或task完成都不等于展示成功。

### 7.5 停止、缓存与资源竞争

停止后晚到图像和D-M通过不能清除latch；生成中新输入触发当前适用性重验，不自动弹图抢话。静默约束同时限制等待与错误反馈；没有图像能力时提供合法失败入口或受控素材，不自动启用付费API。

缓存分计算结果、内容验证、当前展示资格三层；命中不授权跨用户共享、不代表已显示，也不解除隐藏／删除。个人派生图不默认全局复用，验证缓存绑定内容与政策。图片与D-M使用有界队列、与实时判断／对话调度分开；共享订阅额度的资源边界详见M09。

### 7.6 实施门槛

原生Codex的内置生图有产品文档依据，程序化产物链仍需单独验证；ChatGPT plan usage公开Responses当前预览不支持托管生图，不能混同两条路线。[CX2、CX6]

生成和直接图像检查任一必要能力未成立，在线图保持关闭；手工Codex生成、离线核准素材只能证明资产可用，不能证明动态链已接通。具体型号、生成域检查能力、重试及存储参数待冻结。现场视频不因现有播放器或少量抽帧工具而自动解封。

## 8. 历史记忆后端与当前事实

MIRA将Hindsight等后端定位为可替换的历史检索与整理通道，不是当前边界、剧情许可与播放进度权威。retain用于确认经历的异步索引，recall提供候选，reflect／mental models提供派生理解，不直接提交关系或执行效果。[MIRA §14]

应用先保留来源事件，后台结果携来源映射和版本；读取时重验有效性、作用域和删除状态。服务端决定会话／用户／角色作用域，模型不直接指定任意bank。具体版本、认证和接口语义需要接入验证，本轮不复核外部API。

纠正或删除应阻止旧派生摘要再被当当前事实消费；屏蔽和后台清理完成分开。后台不可用不拖垮当前会话，不编造召回成功。研究提出的跨会话、主动联系、多角色与长期成长均不自动进入本次MVP。[MIRA §14、§17、§20；COMPANION §16、§19]

## 9. 失败路径与验收

媒体加载失败不记录已展示；动作失败不记录已完成；字幕降级的实际披露仍单独记；静默约束下失败反馈也不能偷偷产生TTS。原MIRA“图片失败回退口头描述”在G01.1约束下必须重新检查适用性，不能机械沿用到用户明确禁止讲话的场景。[MIRA §17；H3 §2.2]

验收覆盖M01–M08、M16–M23、M25–M28以及B03、B08–B13。创作动机／秘密、角色资源、能力映射、具体渲染路线、历史记忆后端与持久化范围仍是未定输入。

## 10. 复用落点：Renderer、资产与停止能力

### 10.1 用现成Renderer，不再写角色渲染引擎

Charivo固定提交`62f3a4369643d4e132cfc25104a15422e1155c05`提供模块化渲染入口。`packages/render/src/render-manager.ts`中可以看到Renderer包装、口型驱动、表情／动作／视线事件，以及重复挂载与解绑清理。[OS-C15](https://github.com/zeikar/charivo/blob/62f3a4369643d4e132cfc25104a15422e1155c05/packages/render/src/render-manager.ts) · [OS-W07](https://github.com/zeikar/charivo)

建议优先验证`@charivo/render`与所需具体renderer，通过MIRA `EffectExecutor`调用。前端场景壳负责背景、环境、角色、道具、媒体、字幕和输入层；无需为渲染选择连同Charivo整套LLM/STT/TTS一起接管。

**必须保留的控制方向：**

```text
获准Effect
 → MIRA执行器检查许可、版本与依赖
 → Charivo Renderer能力
 → 实际开始／完成／失败／中断回执
 → MIRA Actor归约
```

不能从LLM文本标签直接发`avatar:motion`绕过许可；也不能在`renderer.loadModel`成功后立刻把所有业务动作登记为可执行。真正的动作与表情数量由原创资源和能力清单证明。

### 10.2 一处真实冲突：audio_end自动释放表情

现有RenderManager在TTS结束时关闭实时口型，并在renderer支持时释放表情。这对它的默认说话表现合理，但MIRA的持续情绪、纯动作回应和安静陪伴不一定以语音结束为边界。[OS-C15](https://github.com/zeikar/charivo/blob/62f3a4369643d4e132cfc25104a15422e1155c05/packages/render/src/render-manager.ts)

因此应选择窄适配：保留口型随真实播放结束，表情保持权交给MIRA当前affect／停止政策；使用更低层renderer或可配置hook，必要时最小补丁。**不要每次语音结束重置整个人格和情绪，也不要让两个模块轮流写脸部参数。**

### 10.3 一处实际音频风险：动作可以自带声音

`avatar:motion`把`muteSound`传递给执行器，源码明确无标记动作不推断为静音。MIRA的动作若自带人声，会绕过单人声仲裁。默认静音此类动作伴随音频；确实需要声音时，把它作为独立已登记、获许可的效果，不另开不可控播放源。[OS-C15](https://github.com/zeikar/charivo/blob/62f3a4369643d4e132cfc25104a15422e1155c05/packages/render/src/render-manager.ts)

### 10.4 G04安全收势仍需素材支持

现成引擎可以帮我们播放、停止和混合，不会自动提供“放低相机”“收起照片”的原创动画或它们的语义安全退出点。每个资产都要登记支持何种中断：冻结、受控过渡、取消、可继续或不可继续。

收势完成不提交原业务动作完成；视频回到角色不等于视频播放完。引擎回调、完成标记和场景提交之间保留MIRA适配器，正是产品代码最应该花力气的地方。

### 10.5 Live2D与VRM是资产路线选择，不是热切换兜底

`three-vrm`提供Three.js上的VRM加载与运行，是有实际生态的另一条角色路线。[OS-W12](https://github.com/pixiv/three-vrm) 可以用于偏3D的后续资产选择，但不是Live2D模型加载失败时无需准备就能切换的备份。

首个可交付版本先锁定一种角色资产路线，验证三种表情、两种非语音动作、状态辨认、手机帧率和打断退出。框架示例角色不能代替需求书要求的原创成年角色。B2，第1–2页

### 10.6 许可不能只看仓库顶部MIT

Charivo的`render-live2d`包是复合作品：自有代码MIT，Cubism Core与Framework／Samples有独立Live2D条款，模型资产另算。包级LICENSE已经明确说明，不能把整个分发物写成MIT。[OS-C16](https://github.com/zeikar/charivo/blob/62f3a4369643d4e132cfc25104a15422e1155c05/packages/render-live2d/LICENSE.md)

发布前按实际包、Core、衍生SDK代码、模型、纹理、动作与声音分别登记许可；本书不替发行方判断是否满足具体商业／可扩展应用授权。若需要改变资产路线，先比较许可与制作成本，不用一条“开源可商用”概括。

### 10.7 ink：成熟剧情作者工具，但当前简单storylets不必升级成语言项目

ink有作者脚本、编译器、运行时和Web侧inkjs入口；其README明确它不是端到端游戏引擎，而是可以嵌入自有UI的叙事工具。[OS-W13](https://github.com/inkle/ink/blob/master/README.md)

如果后续作者要大量条件、分支与可视化试演，可以接入其作者工具或版本化脚本。现在只支撑一段3–5分钟场景时，已有storylets配置可能更直接，没必要仅为“有现成工具”再引入完整运行时。

**需要保留的边界：**剧本解释器推进并生成下一行，不等于该行已呈现；将其结果作为计划候选，经G03/G02/G04执行后提交剧情。不可把完整未解锁秘密随Web导出包送到客户端，再用UI隐藏来充当访问控制。若选inkjs，单独锁定其版本与故事格式兼容性；借鉴书原核查未审其源码，不承诺与任意ink版本直接匹配。

### 10.8 记忆与媒体的主归属

Hindsight显式客户端、outbox和重试的复用细节由M01 §10持有；媒体承载与生图产物取得由M09持有。本章继续拥有Canon、生成域、D-M、能力与当前展示规则，不复制第二份接口和权限定义。

**交接：** WP02/04/05；RI-05–07、RI-10–13。已有动画、检索和生图代码不等于已经有原创角色资产或实际MIRA体验。
