## 1. 三层证据各司其职

确定性合同检查身份、次序、许可、依赖、取消、回执和幂等；语义评测检查指代、请求覆盖、人设、边界理解与跨模态一致性；真实设备验证收音、权限、实际输出、同步、尾部和恢复。

不能用schema成功证明自然性，也不能用角色自然性评分抵消旧输出复活。源码／配置静态检查、固定回放、真实API、移动端和人工判断要分别报告，不合并成一个“全部通过”。[MIRA §19；V02 §19；H1 §12]

## 2. 必需观测链

一次互动应能关联输入事件和版本、判断读取快照、约束合同、生成候选、输出批准、资源准备、许可发放、本地抑制、真实呈现与状态提交。

来源记录应回答“当时系统看到什么、允许什么、实际发生了什么”，不是暴露模型隐藏思维链或声称知道角色真实心理。可使用应用记录的理由标签、版本和证据引用。[MIRA §2.6]

语音原指标仍记录输入结束、首安全文本、内容审批、音频ready、实际首播、停止观测与实际静音；新增非语音路径记录关键效果首次呈现和建立完成。审批等待、TTS、媒体、设备和网络成本分开，不能把所有延迟归咎主模型。[V02 §14–15；H2 §11]

### 4.1 G03验证：固定回放与真实A／B分开

固定流回放覆盖不同字节分片、非法记录、缺封口、改写前段、审核乱序、范围拒绝、许可增量、打断、无语音、图片替换、TTS无法对齐、缓冲超限和局部失败。相同已批准计划及相同呈现顺序下，A／B应保有相同状态归约与事实；这不代表真实模型输出相同。[G3R §12.1]

真实A／B按短回复、纯动作、多段说明、必要限定、强全局依赖、媒体前置与安静请求分组，保持输入、合同和可比较的模型／TTS／设备条件。报告语义错误、请求覆盖、首实质行为／语音、媒体可见、完整请求满足、语音间隙、审核排队、成本、取消浪费和补偿频率。失败不得从延迟结果中悄悄删除，不用更短但不完整的输出替换质量约束。[G3R §12.2]

样本量、阈值和最终启用配置尚待定标。架构确认不等于B已更快；短回复收益不足、排队或语音连续性变差，都应在A对照中如实报告。

### 4.2 G04验证：政策回放、语义范围与设备尾部分开

G4-P01–G4-P24覆盖无语音动作打断、图片已解码但未显示、留图／关闭／重连、字幕曝光、收势假完成、镜头新披露、视频静帧、预审雨声与全部静音、高版本旧许可、同次PTT、空输入、S1/U2/S2竞态、STOP无请求、附和门槛、PCM游标、混合恢复、过期定时器、G03尾部、迟到回执和预算耗尽。[D6；G4R §12]

固定回放验证控制身份、依赖与幂等；语义评测区分“别停”“等一下”“不看了”“继续”的指代、范围与未知；真实设备验证各通道停止残余、动画退出、视频帧来源和可恢复游标。分别记录本地立即抑制、服务端传播及不可撤回设备尾部，不报一个无法解释的统一“停止毫秒数”。

旧结束回调不得假完成，保持不得新披露，更新停止不得被旧重新开启覆盖。PTT同次新请求应能回应，空输入不解锁；这些安全性与可用性一起验证。本次没有执行上述回放、语义或设备测试，语义恢复仍默认关闭。

## 10. 复用落点：Mock、浏览器与竞态测试

### 10.1 MSW：一个协议，两种环境

MSW在网络层提供Mock，浏览器与Node可以复用处理器。[OS-W14](https://github.com/mswjs/msw) 建议将成功、慢返回、断流、401/429、空图片、旧许可和图片加载失败做成同一份fixture，替换网络边界而不是直接操纵页面“演示下一幕”。

确定性核心也可以直接用Fake Backend重放固定事件，不必每个单元测试都经网络。关键是不创建另一个省略Actor、审核或许可的Demo App。两个网络Mock工具不要对同一请求同时拦截：MSW用于共享演示/集成fixture；Playwright路由用于指定浏览器测试，职责明确。

公开无密钥演示还需固定合法素材与声明式判断回放；不得把所有判断写死为allow，或者让Mock显示一段计时剧本伪装成当前对话触发。B2，第2–3页

### 10.2 Playwright：浏览器动作、故障、HAR和诊断

Playwright已有HTTP路由拦截、修改及HAR回放文档；不必自建浏览器自动化和网络录制框架。[OS-W15](https://github.com/microsoft/playwright) · [OS-W16](https://playwright.dev/docs/mock)

对应MIRA，可以覆盖停止按钮、持续输入、照片先显示后失败、移动尺寸和断线重连。HAR只是HTTP材料，不是完整MIRA因果账本；音频队列、回执和Actor事件仍需以应用事件记录。浏览器trace中的网络完成，也不证明扬声器真实发声或用户听到。

HAR和trace可能含headers、正文与私人素材，必须在允许的测试profile中采集并裁剪；题目要求可回放，不要求泄露私人账户。

### 10.3 fast-check：让竞态变成可复现的反例

fast-check已有属性测试和可控异步scheduler，不需要再研发随机测试运行器。[OS-W17](https://github.com/dubzzz/fast-check) · [OS-W18](https://fast-check.dev/docs/advanced/race-conditions/) 我们提供状态模型和不变量，例如：

```text
任一被永久失效的分支，不得新增未来呈现。
更晚停止发生后，旧请求的重新开启不得清除它。
同一效果已消费，不因快照更新或重连再次执行。
迟到的有效回执只补历史，不制造新表演。
```

让库生成stop/grant/resource_ready/receipt的排列与重复，再把失败输入缩成较小反例。scheduler只控制测试接入的异步操作，不证明所有真实声卡、GPU或网络调度都被穷举。

### 10.4 复用上游测试的正确方式

CLIProxyAPI图片测试说明怎样构造假的上游图像响应；Pi的fetch测试可以参考如何注入传输；AIRI和角色项目的接口提供播放回调替身入口。我们应读并引用这些测试风格，而不是把测试存在当成已验收。[OS-C03](https://github.com/router-for-me/CLIProxyAPI/blob/2044a01f422998de79a5da8015141b878886534d/internal/runtime/executor/codex_openai_images_test.go) · [OS-C11](https://github.com/earendil-works/pi/blob/9fba660cf1caca0ade5bea72269352416e595a19/packages/ai/src/legacy-api-aliases.ts) · [OS-C17](https://github.com/moeru-ai/airi/blob/731123861093abfd7fc34c0654ba9f99206ab944/packages/pipelines-audio/src/speech-pipeline.ts)

采用后要分四项记录：依赖能安装、上游相关测试通过、MIRA适配合同通过、真实设备／账户通过。一次`npm install`或若干schema断言不能被加总成自然对话的质量证据。
