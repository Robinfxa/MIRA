# M03 表演计划、非语音回应与完成合同

> **v0.6整合说明：** 原架构合同继续有效；本章新增“复用落点”只将借鉴书的既有证据和建议接到本章。具体技术栈未由本次整合自动批准；差分见A4，源码原阅读范围见A5。


**地位：** G01、G01.1及G03已确认；G04补充中断／收势与保持政策。G03采用同一次主要生成、完整语义充分范围增量审核／发布；A作为同合同保守模式和评测对照，C不进默认主链。精确字段、流格式和实现算法仍待冻结。  
**依据：** MIRA §9–13；V02 §7–9；H1 §6、§10；H2 §2–6；H3 §2；G3R §2–8、§10–12；D5；ADR-0005。 D6；G4R（相关小节见正文）；ADR-0006。

## 1. 继续使用TurnPlan／PresentationBeat

一个beat尽量对应一个可独立解释的交流动作，一轮可以包含多个beat。保留MIRA术语，不另建职责重复的CommunicationAct服务或账本。声音只是beat的一种实现，不是它存在的前提。[G01；MIRA §11.1]

交流目的、实际效果、完成条件和持续互动方式分开：`intent`回答要完成什么，`effects`回答怎么表现，`completion_policy_ref`回答凭什么算完成，`engagement_mode`描述建立后继续保持的互动方式。后三者的具体字段是H2提案，不是已冻结供应商JSON。

## 2. 三类画面行为

| 类别 | 例子 | 是否能独立完成实质回应 |
|---|---|---|
| 运行反馈 | 正在收音时进入倾听、真实工作中的加载状态 | 不能 |
| 无新语义维持 | 受控呼吸、眨眼、雨声、保持姿态 | 不能 |
| 交流行为 | 根据“不拍我”放低相机，应请求显示照片，应邀建立安静陪伴 | 可以，满足本次完成合同后 |

同一个动作资产可以用于不同目的，不能凭“画面动了”就记为用户请求已经完成。有认同含义的点头或微笑也不能一概登记为无语义装饰，从而绕过输出审核。[H2 §3；MIRA §4.1]

## 3. 模型候选与程序接受计划

候选字段提案：

```text
BeatCandidate
  key / intent / evidence_refs[]
  utterance: nonempty_text | null
  effect_candidates[]: capability_ref + bounded_parameters
  optional_engagement_proposal
```

`utterance=null`只在完整合法的候选中表示有意不说话。空响应、缺字段、解析中断、被拒绝的内容和TTS失败不自动成为quiet成功。动作描述、工具参数与内部标签不进入朗读。

服务端接受后分配plan／beat／effect身份，绑定精确内容摘要、原始生成来源、当前输出分支、已冻结正文引用、有限效果依赖、完成要求和失败政策。模型不能决定用户身份、执行版本、任意URL／代码、完成状态或任意状态补丁。[MIRA §11.2；H2 §4]

`AcceptedBeat`中的requirement groups、替代关系、required／optional与completion policy来自受控模板和程序编译。模型不能把失败的关键动作改optional来获得成功。

## 4. 完成条件不是audio_end

```text
生成结束 ≠ 单个模态播放结束 ≠ 本次交流行为完成
```

保留MIRA基础生命周期 `planned → authorized → started → completed` 及interrupted／failed；改变的是转换条件，不为B再造近义状态机。[MIRA §12.2]

| 行为 | 完成需要的证据 | 不足以完成的信号 |
|---|---|---|
| 纯语音 | 必需语义范围的可靠交付及约定字幕条件 | 模型Completed、TTS最后一个包 |
| 放低相机 | 对应能力规定的完成／终态 | 指令发送或入队 |
| 展示照片 | 正确内容版本在指定展示位可见 | 下载、解码或隐藏DOM节点 |
| 完整剧情片段 | 合同要求的播放终点 | canplay或第一帧 |
| 混合回应 | 全部必需要求满足 | 声音先结束 |
| 建立安静陪伴 | 关键姿态／环境已成立，或核实目标状态原本成立 | 长时间没声音、模型无返回 |

必需效果失败时按已接受的替代政策处理，不能用一个可选表情抵消。回执缺失保留evidence incomplete／partial／unknown并核对，不凭超时推断完成。可选效果也应终结、取消或进入明确场景保持政策，不能在回应结束后留下会自动推进剧情的旧任务。[H2 §5]

G03的增量计划必须有明确封口，不能第一个beat完成就猜后面没有内容。完整计划边界与可信流终态、语义覆盖、实际必需效果完成是不同条件；精确封口消息仍待冻结，见§7.5。

### 4.1 G04：原动作中断与收势完成不互相代偿

G04允许预审的非语义运行态过渡，不允许为了自然而把旧业务动作演完。原动作interrupted与停止过渡completed分开，动画结束／视频结束回调不得在停止后提交原动作完成或推进剧情。[D6；G4R §5]

静帧仅证明相应帧曾呈现且可保持，不等于video_completed；已成立场景可以按M04保持，但未执行OpenIntent不自动续演。必需效果不可恢复时须已有降级合同或新计划，模型不能临时将其改optional。准确回执和停止能力字段待冻结。

## 5. 安静陪伴的建立与保持

用户应邀安静听雨时，本次建立行为可以没有语音；其目标变化由真实回执证明。建立完成后主生成任务结束，场景在有限保持政策下继续，输入和停止入口仍可用。

不以永久挂起的LLM调用维持雨声，不因倒计时到点自动重新找话题。若目标状态本来已经成立，可以记录请求与维持决定，而不是伪造一次新动作回执或反复转镜头。当前状态无法核实时先同步。[H2 §6]

安静仍是情境内的互动方式，不推断用户永久内向、希望依赖角色或关系升级。后来明确提问时重新解释当前请求与静默范围，不永远禁语音，也不复活先前未完成的旧讲解。[MIRA §13]

## 6. 跨模态语义依赖

“我找张照片给你看”可以不依赖图片已可见；显示照片需要资源与内容获准、当前执行资格成立；“你看左边这里”则依赖指定照片此时仍处于正确展示位置。

语义审核可以提前批准带条件的候选，但不能证明条件已经成立。实际依赖由本地可验证呈现屏障或回执支持。历史上显示过P1与现在展示槽仍是P1是两种条件；不能P1被P2替换后仍凭旧ACK指称“这张”。[H1 §6.4；H3 §6]

beat不等于TTS输入或音频packet。没有可靠时间对齐时不虚构“说到第几个词时转头”；只阻塞真正依赖媒体的内容，不建立所有资源全就绪才能说首句的全局屏障。

## 7. G03裁定：按完整语义充分范围增量审核／发布

### 7.1 用户确认与A／B／C地位

> G03 采用同一次主要生成，以完整且具备充分语义上下文的范围增量审核和发布。一个范围可以包含多个 beat；必要后文未知时等待，必要时扩大到整轮。保留 A 作为同合同的保守模式和评测对照，不把 C 放入默认主链。

以上为D5用户确认，记录见ADR-0005。A与B主要区分审核／发布粒度，C改变生成拓扑；不能把“一个beat一到就播”当作B的含义。

| 路线 | 当前地位 | 运行边界 |
|---|---|---|
| B：同一次主要生成，语义充分范围增量审核／发布 | **已确认的架构路线** | 一个范围可以含多个beat；必要后文未知时等待，必要时扩大到整轮 |
| A：整轮计划形成后再进入发布 | **保留为同合同的保守模式和评测对照** | 复用约束、编译、审核、许可、执行和回执；不另造演示或降级执行器 |
| C：额外场景导演生成调用 | **不进入默认主链** | 不是对所有复杂场景的永久否决；后续变更须另行论证与裁定 |

A／B使用共同合同，不意味着它们在真实生成时必然返回相同内容或具有相同延迟。G03确认架构方向，不证明真实后端结构化流、审核质量与TTS能力已经达标。[G3R §3–4、§12]

### 7.2 两种完整性与一个范围

```text
传输数据到达 ≠ 结构完整 ≠ 语义上下文充分
≠ 内容审核通过 ≠ 当前执行资格 ≠ 实际呈现 ≠ 整轮请求满足
```

一个PresentationBeat是计划组织单位，不必与审核／发布范围、TTS输入或音频packet相同。“可以”与“但前提是先确认不会拍到你”必须保留必要限定；若两beat共同表达这一条件，就作为同一范围审核。范围可以扩大到整轮，不能为了首段指标强行切字。[V02 §8；G3R §5]

结构完整不保证对任意未知后文的语义等价。已接受前缀不能被后续内容追溯改写；必要后文未知则等待，后段矛盾在发布前拒绝。关键披露继续使用受控事实、文本与素材；本合同不宣称自然语言判断已获形式化正确性保证。[MIRA §9.3；G3R §5.2]

### 7.3 有序生成、完整候选与审核范围

```text
固定本次ResponseContract与ContextPacket依据
  → 同一次主要生成，有序累积输出
  → 完整候选的结构／能力核验
  → 按必要上下文组成审核范围（可含多个beat）
  → Output Decision：当前合同＋实际呈现＋有效已接受前缀＋候选／必要后文
  → 连续已批准范围
  → Actor重验适用性，更新G02-A完整许可集合
  → 客户端检查最新活动、停止锁、依赖及消费游标后执行
```

固定生成依据不是冻结世界；可靠新输入仍可使分支失效。若采用头部＋记录＋封口格式，影响前段权限、对象或必要完成要求的信息不能到结尾才出现。具体framing尚未冻结，不能仅靠换行或右花括号触发执行。[G3R §6.1–6.2]

`BeatCandidateReady`只是应用完成解析后的可能事件名，不是已核验供应商原生事件。后端若只能在整轮结束后可靠校验，就在同一合同下使用A，不虚构逐beat可用能力。解析器不产生未审核副作用。

### 7.4 冻结、接受、授权与呈现不合并

冻结形成不可同版本覆盖的待审范围；接受表示精确内容过审；G02许可表示当前执行资格；真实回执支持事实提交。四者分开。

批准绑定当前范围的精确内容、动作参数、素材版本、所需前缀与本轮合同，不能给一个仍在变化的整轮plan摘要发证。已冻结／接受的内容不允许同身份原地改写；修改未来内容时撤销相关资格，以新候选身份重审，实际已呈现事实保留。[G3R §6.3–6.4]

正文只推进连续已批准范围。视觉并行也限于已准入范围与显式依赖；后段素材可以在独立许可和预算内提前准备，但就绪不赋予提前演出资格。范围序号、内容摘要规范与审批结果组合算法仍是实现细稿。

### 7.5 显式封口与局部失败

自然结束需要明确计划边界与可信流终态；EOF、超时、token上限、解析中断不能伪造PlanEnd。若使用最终数量／清单，程序须核对实际记录；最终清单只能确认范围及顺序，不能重写已批准前段。[G3R §8]

O6区分合法阶段推进与整轮覆盖，详见M02 §5。封口后的语义覆盖不等于呈现完成，整体成功仍需必需效果回执与适当收尾。无声候选正常结束、失败无返回、安静保持状态继续存在，不能混为同一终态。

若前段已呈现而后段拒绝或流失败，保守取消该失效分支的未呈现尾部，显式记录失败与未满足义务；不跳过错误中段发布依赖后文，不把整轮标成completed。续接须依据最新输入、已呈现／partial／unknown范围及有效义务，不能重播整轮，也不能违反静默等当前约束。[V02 §8.5、§13；G3R §8]

### 7.6 保守模式、背压与启用证据

A保留为同合同整轮模式；语义上下文不足时范围也可以自然扩至整轮。具体模式配置、自动回退触发与阈值尚未冻结，不在此暗中选择一个调度策略。

不得以增量为由逐帧／逐token审查，或引入无界审核并发。保留有界FIFO，必要时合并连续范围；缓冲达到硬边界时按失败合同处置，不latest-only丢中间限定。[G3R §9.1]

固定输出回放验证解析、顺序、冻结、封口和失效；真实A／B运行比较必要限定、请求覆盖、首实质回应、语音间隙、成本与取消浪费。实际启用以能力与验证证据为依据，不因架构获批而宣称已经获得性能收益。TTS依赖准入归M05 §5.1，测量与验收归M08／A2。

## 8. 失败与验收

拒绝候选后不能由执行器私自删除关键部分并把剩余片段作为原批准继续。若要替代，应使用已获准替代合同或重新生成审核；次数与预算未定，不新增无限修复循环。[H3 §2.2]

验收对应B01–B16、M08–M11、P09–P14及G3-P01–G3-P14，全部仍为not_run。重点是无语音不创建空TTS、无内容不等于静默、动作回执才能证明动作完成、实质请求不被装饰替代、未封口计划不提前完成。

G03路线已确定。仍待冻结：完整流framing、候选／范围身份和摘要规范、必要后文等待／合并实现、计划封口格式、完成schema、模式配置、资源可见性标准、可选效果收尾、场景保持字段／期限及真实音频对齐。G04停止／保持政策已确认，G05／G06方向已由D7确认，具体能力待验证；具体收势／保持字段与资源能力待冻结，现有资料没有这些对象的可直接部署代码或组合实测。

## 9. 订阅LLM与媒体结果的G03接缝

D7改变主生成承载优先级，不改变本章语义充分范围合同。Codex消息、工具进度、分析摘要和普通文本delta都不能直接当PresentationBeat；只有约定候选通道解析完整后，按同一Output Decision核验。若当前承载只可靠提供整轮结果，使用G03-A同合同保守模式，具体切换与能力探测归M09。

增量生图请求的未知产物只能先作为受控意图／待定槽位，D-M后通过新的具体接受记录绑定实际资源，不能篡改已冻结批准。主生成提出意图、图片worker执行受控规格不构成第二个剧情导演；图片的新细节若引发后续LLM生成则明确记录额外慢路径。[M06 §7]
