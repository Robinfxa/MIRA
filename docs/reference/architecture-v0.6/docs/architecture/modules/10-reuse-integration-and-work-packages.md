# M10 开源复用组合、工作包与实现交接

**地位：** 把借鉴书的组合建议、最小自建边界与工作包回填成实施入口。用户本次批准的是文档整合，不是具体开源栈选择；原G01–G06及八份ADR不变。本章不是新服务或运行时模块。

**来源：** OS-REF §08–09、A3；本章与各M章的映射属于本轮编辑性整合，不增新功能或工期承诺。

## 1. 建议组合与最小自建边界

### 1.1 建议第一轮联调组合

**借鉴书的首联调建议是订阅承载先验证CLIProxyAPI（须先处理M09／IC-01），原生Codex作另一条明确adapter；音频基础先验证Pipecat，LiveKit作为有独立理由时的替代；角色使用Charivo渲染模块；记忆使用Hindsight显式客户端；测试复用MSW／Playwright／fast-check。**Pi是偏嵌入式TypeScript接入时的替代，不与CPA叠成一串；AIRI和Open-LLM-VTuber主要贡献实现模式和现成接口经验。

这是借鉴书依据其原源码记录提出的组合建议，不改写架构书已批准的业务政策。后端语言尚未固定时，也不强制引入XState；固定短剧情暂不引入ink运行时。

```text
场景前端
  ├─ Charivo具体renderer：角色、口型、动作
  ├─ 已有音频／传输基础的客户端适配
  └─ MIRA本地许可检查与呈现回执
             │
        MIRA Session Actor
  约束 / 范围审核 / 许可集合 / 停止 / 当前事实
      │                 │                 │
  GenerationBackend  ImageBackend     语音服务adapter
      │                 │                 │
  CPA或原生Codex    CPA或原生Codex     Pipecat基础设施
      │                 │
   合法候选         隔离 → 实际D-M检查
             │
   当前状态与呈现事件 → outbox → Hindsight

  MSW／Fake Backends + Playwright + fast-check
             └─ 对同一合同进行Mock、回放与竞态验证
```

图不表示全部操作顺序串行；尤其媒体慢任务不阻塞Actor。首个图片失败时，仍合法的基本互动继续。API替换位在Backend层，不侵入G02/G03/G04。

### 1.2 真正要自建的窄层

| 自建对象 | 为什么不能直接交给上游默认值 | 可以利用的现成基础 |
|---|---|---|
| ResponseContract与上下文投影 | 本产品当前边界、允许披露与义务 | 序列化／schema库与既有Provider接口 |
| 语义充分范围接受与封口 | G03具体规则，不是普通token chunk | 上游文本事件、FIFO模式、解析库 |
| 全局许可集合与本地安装规则 | G02跨音频、字幕、动作和媒体的资格 | Actor库、现成传输、现成播放器 |
| 停止／保持／因果重新开始 | G04批准的体验政策 | abort、任务取消、Renderer停止能力 |
| ExposureState及回执归约 | 图片／声音／字幕实际发生和unknown不同 | 现有回调与事件存储，不另造通用数据库 |
| 原创角色、剧情条件与能力manifest | 是产品内容和授权，不是技术库可代写的默认素材 | Charivo、作者工具、受控生成素材 |

“自建”不等于几千行不可避免的框架。先写这些对象的状态转移和adapter，以最小代码连接已有设施；不要额外建立通用Agent编排平台、OAuth平台、视频生成平台和记忆管理平台。

### 1.3 不建议整仓套壳

完整AIRI或Open-LLM-VTuber可以快速验证“麦克风→模型→声音→角色”这条经验链；但要实现已确定的G03/G04，直接沿用其全部会话状态和播放器通常需要系统性协调。更稳妥的做法是复用模块，或在选定单一底座后明确替换其控制位置，而不是运行两套回复与两套历史。

同理，不建议为“统一”强迫图片审核走只能读文本的JEV，也不建议每个运行事件新调用一个Codex Agent。已有工具越多，越要缩小主控数量。

## 2. WP01–WP08工作包

以下是可交接的生产入口，**不是新增批准功能，也不是本轮已完成实现**。每个工作包以“先读现成入口→接一条合同→用真实和负例证明”为单位；不按假定72小时产能填工期。

### WP01 订阅文本桥接

读C01、C04–C07、C10。选一个首接入carrier：CPA为来源建议，实际调用前先处理IC-01；原生任务需求则Codex；嵌入式TS才考虑Pi。交付薄GenerationBackend，输入固定ContextPacket和cancel，输出有序数据及真实终态。API profile独立。验收RI-01/02/03/04；必须证实没有读入上一轮未播尾部，没有隐藏付费切换。

### WP02 生图产物与隔离

读C02/C03及C08/C09。复用既有图片接口或原生结果，不重写其底层协议。交付ImageBackend、受控产物引用与D-M前隔离；记录实际路线、驱动模型、返回失败和内容身份。验收RI-05/06/07。任何“already displayed”或partial image都不得直接下发为主场景内容。

### WP03 语音最小纵向接入

读C12/C13、C14及已有语音v0.2。选一个主要语音框架/传输入口，将JEV与MIRA范围审批放在已确定控制面；合成与输出两处有准入，不让默认Agent再生成第二轮回复。验收RI-08/09。先真实明确打断，语义恢复仍关闭。

### WP04 角色执行器

读C15/C16。仅接Renderer及必要控制模块；用原创资源发布真实能力目录。交付表情、动作、视线、口型、失败和中断回执；处理audio_end释放策略与muteSound。验收RI-10/11。不能把示例模型作为原创交付，也不能臆造尚未制作的动作。

### WP05 中断后的历史与记忆

读C18/C19、M01/M04/M06。交付回执归约、可靠前缀和partial/unknown上下文；Hindsight使用显式异步写入。验收RI-12/13。图像已经显示而解释没说完时，下一轮既不重演照片，也不把未说完解释当完整历史。

### WP06 Actor与许可集合

读C20，语言合适时用XState公开Actor；否则现有async任务。实现G02/G04业务状态，而非通用FSM框架。媒体字节不占满控制队列；停止锁具备请求因果。验收RI-14/15。参数与wire算法仍按架构实现细稿冻结。

### WP07 共用Mock与故障回放

读W14–W18，复用MSW/Playwright/fast-check。真实与Mock进入相同执行器；用例包含401、429、空图、断流、乱序、重复、隐藏后重连。验收RI-16/17。固定模型回复回放只证明协议，不计入真实语义准确率。

### WP08 发布清单与第三方说明

生成固定依赖锁、镜像/包版本、许可证表、素材来源与运行说明。外部服务不可用时提供合法Mock；录制成功打断和一个真实故障状态。验收RI-18。不得为了回放把认证材料、原始私人HAR或未解锁剧情一并公开。

### 2.9 工作包之间的依赖

WP01、WP03、WP04可以分别做窄能力验证；WP02要通过WP01选定承载和D-M接口；WP05/06连接共同事实与控制；WP07从开始就伴随，不留到最后补；WP08收口依赖真实结果。最先完成的产品切片应是：**角色正在回应→用户打断→旧图片迟到→新输入得到回应→历史仍准确。**不先做账号池、后台控制台或完整剧情编辑器。

## 3. 开始实现前的窄门槛

| 门槛 | 要解决的具体问题 | 不能扩大为 |
|---|---|---|
| S01 承载 | 原生、社区兼容或显式API的选择，处理IC-01 | 重造OAuth平台、默认付费或账户轮换 |
| S02 语音 | Pipecat首联调或有理由的LiveKit替代，唯一主控 | 同时开启两套AgentSession与播放授权 |
| S03 角色 | Charivo所需renderer与原创资产，复合许可核对 | demo模型充当原创；动态猜出未制作动作 |
| S04 语言／状态 | 后端语言及是否适用XState，Hindsight显式接入 | 为使用库而增加跨语言状态权威 |
| S05 合同 | G02 wire、G03范围／封口、G04因果锁、D-M对象绑定 | 让上游默认值代替未冻结业务合同 |

S编号只是[实施清单](../pending/implementation-and-access-gates.md)的接入任务索引，不新增需要重议的G编号。原材料已经指出这些需锁定；本版将其集中，不默默作出选择。

## 4. 交接证据的边界

先读具体接口与已定位源码，优先依赖／适配；仅在公开扩展点不能承载合同且已有反例时，提出最小patch。每个patch保留固定上游版本、差分原因、测试和移除条件。测试文件存在、包能安装、上游测试通过、MIRA合同通过、账户与设备合格，是五种不同证据。

RI目录与原目录的相关性见[A6](../appendices/A6-requirement-reuse-traceability.md)。RI不是覆盖原146条的替代总分；也不是本轮产品执行结果。

## 5. 实现任务统一模板


以下模板用于每个工作包。它限制重复造轮子，也限制把第三方默认行为当成本产品批准规则。

```text
工作包：WPxx
当前架构：MIRA v0.6（架构＋复用整合版），关联G项与模块：...
唯一实现目标：...

先读来源：
  A5中的仓库、固定commit、文件／符号、原阅读范围、相关上游测试
  若只定位未通读，不把线索当已核查实现
复用方式：
  包／SDK／本地sidecar／机制移植／最小patch
不重写：
  已有认证、事件解码、传输、渲染、检索或测试基础
必须适配：
  输入／输出合同、取消、历史、身份、权限、失败／完成
不能改变：
  G02/G03/G04/G05/G06相关不变量

待准入：
  具体依赖／版本选择、M09/IC-01承载边界、付费／账户／公开部署范围

交付：
  adapter与最小配置
  受控fixture与负例
  实际依赖和许可证条目
  本次真实执行的命令／版本／结果
不算完成：
  README声称支持；只演一次成功路径；只过schema；凭hash说可重验

验证分开：
  安装／上游测试／MIRA合同／账户和真实设备
  未执行项写not_run，不借用其它层结果补齐
```

后续只有发现公开扩展点确实无法承载所需合同，才提出新的小范围架构分歧。基础能力已有实现，就以证据收敛接缝，不再把每个功能变成一轮从零研究。
