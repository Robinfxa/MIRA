# M01 状态、来源与写入权威

> **v0.6整合说明：** 原架构合同继续有效；本章新增“复用落点”只将借鉴书的既有证据和建议接到本章。具体技术栈未由本次整合自动批准；差分见A4，源码原阅读范围见A5。


**地位：** 单一运行权威属于选定基线和G01方向；对象与来源分型继承MIRA；G04停止／保持与重新开始政策已确认；额外字段与存储布局为细化提案。  
**依据：** V02 §4、§11–13；MIRA §5–7、§10–14；H1 §3；VH03 §0。 D6；G4R（相关小节见正文）；ADR-0006。

## 1. 定位与依赖

本章先定义系统知道什么、依据是什么、谁能写入，再让生成、判断和执行消费这些状态。不把所有内容塞入一份可由模型任意改写的角色状态，也不让声音历史、剧情历史和长期记忆各自成为互相竞争的真相源。

这是对ValueHermes“状态合同先行”的方法承接；没有移植其业务数据库划分。表名、数据库种类与持久化事务边界仍属实现合同。

## 2. 一份来源，多个视图

| 对象 | 保存内容 | 合法更新依据 | 禁止替代 |
|---|---|---|---|
| Canon／CoreSpec | 作者身份、动机、知识边界与受控剧情 | 版本化作者配置 | 普通对话不能重写核心身份 |
| EvidenceEvent | 用户输入、纠正、呈现、失败等来源事件 | 输入入口与执行路径 | 解释不能伪装成原始事件 |
| CurrentState | 当前称呼、有效边界、场景和已接受约定 | Actor顺序归约 | 后台摘要不直接覆盖 |
| Interpretation | 角色对事件的解释和替代解释 | 模型候选＋来源引用 | 不能当独立外部事实 |
| ExposureState | 已呈现、部分呈现、未知及明确用户确认 | 真实回执与用户明确回应 | 生成完成不是披露完成 |
| OpenIntent | 未完成、挂起、拒绝的交流意图 | 计划提案与后续事件 | 不是已完成经历，不是外部定时服务 |
| MemoryProjection | 语义索引、摘要、专题理解 | 来源事件派生 | 不写执行许可，不取代当前纠正 |

这一对象表继承MIRA §6。对同一事实可以有不同角色解释，但不能因此制造第二份来源事实。

## 3. 所有权与运行边界

Session Actor拥有当前话轮、分支、约束、计划接受与语义状态的写入权。网络任务完成后只向Actor返回结果，不自行改变CurrentState或调用播放器。

客户端拥有本地活动序号、停止锁、真实播放／显示游标和即时抑制能力。它可以在服务端尚未知晓新输入时立即停止；不能因为自己认为“用户在附和”，自行恢复旧内容。客户端回执是工程观察，Actor负责核对身份、次序、截止范围和重复事件，再形成呈现记录。[V02 §4、§11；MIRA §12]

作者资产决定允许动作与关键披露条件；模型只能选择允许候选。CompletionPolicy、执行身份、用户身份与作用域不能从模型自由文本中直接获取。

## 4. 正交状态不合并

```text
interaction_mode  实时交互状态：idle / listening / thinking / speaking
emotion           情绪表现状态：例如 guarded / reflective / relieved
story_state       剧情与已接受进度：由事实与呈现事件支持
execution_state   具体效果的准备、执行、中断与完成
```

上述前三类来自MIRA；执行进度来自V02与呈现合同。H2另提议 `engagement_mode` 表达普通交流／安静陪伴，它不取代interaction_mode，也不是另一种媒体格式。

进入listening不代表情绪归零；没有语音不代表角色没有回应；声音停止不代表已经显示的照片被历史抹去。动画插值参数也不是心理学置信度，不构造无依据的好感分数。[MIRA §5.4、§13]

## 5. 身份与版本：保留原含义

| 字段 | 所有者 | 变化原因 |
|---|---|---|
| activity_seq | 客户端 | 需要抑制输出的新活动或明确停止；重传沿用同一序号 |
| input_epoch | Actor | 确立新逻辑用户话轮；疑似声音不直接分配新话轮 |
| input_revision | 规范化输入路径／Actor | ASR修订或补充改变完整转写 |
| output_epoch | Actor | 旧输出分支永久失效或被替换；单纯暂停不变 |
| generation_id | 主生成任务 | 一次真实生成的身份；恢复不伪造新生成 |
| permit_revision | Actor | 全局有序授权／撤销，承载完整有效许可集合（G02=A）；字段实现归M04 |
| persona／scene／policy版本 | 各资产或策略owner | 版本化配置变化；不能由模型自填 |
| plan／beat／effect身份 | 程序编译与接受计划时 | 绑定精确接受内容，不相信模型生成的权限身份 |

原媒体包保留生成来源；当前许可记录它经过哪个更新输入的兼容性验证。`origin` 与 `validated` 不是同一个字段。不能把旧包来源改成新revision来绕过检查。[V02 §11.2]

H1提议依据相关状态依赖判断失效范围，避免一次眨眼或无关表情更新使全部正文失效；依赖指纹和精细局部复用尚未冻结。缺少可靠局部依赖／对齐时沿用v0.2保守失效未播分支的方式。

### 5.1 G03的审核范围身份与有效前缀

G03已经确认按完整语义充分范围增量审核／发布。一个范围可以含多个beat；前段审批绑定当前精确内容与依据，不能以仍在变化的整轮plan摘要发证。具体范围ID、摘要规范和前缀引用字段由M03／M02细化，不由模型自由生成。[D5；G3R §6.3–6.4]

已接受但尚未呈现的有效前缀可以供后段一致性审核读取，但它不是ExposureState，也不能进入“已经说过”的普通assistant历史。前缀被撤销后，不再作为有效待执行上下文；实际呈现记录继续保留。

### 5.2 G04的停止依据、当前可见与场景保持

G04确认回应分支与已成立场景维持的生命周期分开。output_epoch是回应分支代际，不能作为所有持久场景对象的唯一寿命；两者仍受同一Actor和全局许可控制。停止／保持资格的精确编码归M04，不先发明另一套场景epoch。[D6；G4R §6]

停止依据、当前可靠请求与新回应需要因果关联；本地更新停止优先，重新开启新回应不删除旧分支失效记录。当前隐藏／静音等持续约束与单次停止分开保存，不因新grant或重连自动清除。[G4R §7]

照片曾呈现、照片当前可见、照片已隐藏、允许再次显示是不同事实或资格。原动作interrupted与运行态收势completed分开，收势回执不得提交原业务完成；隐藏不删除曝光历史。具体表和字段未冻结。[G4R §4–5、§10]

## 6. 来源强度与时间

至少保留 `authored_backstory`、`user_statement`、`presentation_receipt`、`interpretation`、`generated_visualization` 的区别。用户自述不代表外部核实；生成图片不是现实拍摄证据；界面回执不证明用户注视、听清或理解。[MIRA §6.1]

发生时间、获知时间、呈现时间各自记录，会话次序使用单调序号。不同设备的墙上时钟或单调时钟不能未经映射直接比较。具体clock映射和许可期限协议尚待实现验证。[MIRA §6.2；V02 §11.4]

## 7. 呈现提交和迟到消息

计划提出“放低相机”不能先写成相机已放低；但用户可靠输入“不拍我”可以独立进入当前边界，后来的动作失败不撤销这个边界。

旧输出、旧图片结果不再获得执行资格。旧有效回执可能描述打断前实际发生的内容，需核对effect身份、客户端序号和停止截止游标后幂等补记。未知截止位置记partial／unknown，不武断记成成功或未发生。[MIRA §12.4–12.5]

下一轮历史只使用确认呈现的助手内容，并显式携带部分或不确定范围；不能把被取消回答的全文放回普通assistant历史。外部conversation引用也须防止重新注入被取消分支。[V02 §13]

## 8. 完成、失败与未决

本章验收关注：新纠正不被旧摘要覆盖；重复回执不重复写入；取消不抹去有效用户边界；旧输出不复活；呈现未知不被写成已完成。对应A2中的M02、M09–M16、M24、B11、B15、P18–P21及G4-P04–P06、G4-P14、G4-P21–P23。

未决包括：物理存储与事务边界、回执可信范围、重连水位、客户端实例生命周期、相关依赖指纹、精细局部复用。H2的engagement_mode及完成要求字段是后续合同，不把它们标成已上线对象。

## 9. G05／G06与订阅承载的来源边界

D7确认的生成图片始终以generated_visualization记录，生成成功／验证通过／当前可见／曾经呈现是不同事实。图片意外细节不晋升为Canon，用户现实陈述不被图像补写。[M06]

原生Codex的thread记录不成为本产品会话史。被取消而未呈现的模型文本只能留作受限过程材料；主生成或D-M新请求按真实ExposureState与当前约束构造，不直接续接包含未播尾部的thread。上下文与凭据隔离归M09，额度与模型型号只是执行元数据，不获得剧情权威。

## 10. 复用落点：显式记忆与单写者

### 10.1 Hindsight：不要重复建设一套通用记忆产品

Hindsight已有retain/recall/reflect、派生mental models、服务与显式客户端。MIRA应复用其检索和异步整理，不重写向量检索、通用记忆提取或管理界面。[OS-W10](https://github.com/vectorize-io/hindsight)；B3 §14

固定提交`f7dd3f4fd7420f7beec60c32c965e5e5cf7be066`中的维护型Python客户端还明确区分了重试语义：operation_id只对异步retain的幂等重试起作用，同步retain不会因此自动变幂等；容量重试也区分可安全重复的操作。[OS-C19](https://github.com/vectorize-io/hindsight/blob/f7dd3f4fd7420f7beec60c32c965e5e5cf7be066/hindsight-clients/python/hindsight_client/hindsight_client.py)

**我们补的是写入的因果入口：**应用可靠事件与outbox先落地，再提交记忆；源事件／bank／世界由服务端确定。召回结果叠加当前纠正、删除和限制，不直接覆盖状态。客户端自带重试与应用outbox不能叠成重复写入风暴。

### 10.2 不使用自动记住完整聊天的便利路径作为当前权威

项目README提供自动包装与显式调用两种整合方式。[OS-W10](https://github.com/vectorize-io/hindsight) 对普通聊天，自动保存完整对话可能方便；对MIRA，主模型完整生成不等于用户完整听见。

因此建议使用显式SDK：只有实际呈现支持的assistant内容和可靠用户事件进入共同经历；未播尾部不能由包装器顺手存为“已说过”。图片生成结果只能保存为generated_visualization，展示后才产生呈现记录。Hindsight失败时保留当前会话运行，不把检索服务做成每次停播的依赖。

这是**应用写入政策**，不需要修改Hindsight核心。后台summary必须带源引用和适用范围；当前称呼、禁拍边界、开放意图与曝光不从向量命中反向推导。B3 §6、§12、§14

### 10.3 XState：Actor与mailbox有库，不必另写通用状态机框架

固定提交`fbee62e7c1586315ed478c2fedf530d7e0ff5a3e`的`Mailbox`已有串行flush与处理中clear的处理；XState项目提供actors与statecharts。[OS-C20](https://github.com/statelyai/xstate/blob/fbee62e7c1586315ed478c2fedf530d7e0ff5a3e/packages/core/src/Mailbox.ts) · [OS-W11](https://github.com/statelyai/xstate)

如果服务端采用TypeScript，可用公开actor API承载MIRA的状态转移。自己写业务事件、guard和effect，不写可扩展表达式引擎、分布式工作流或通用状态机DSL。若后端选Python，则保留原异步Actor实现；不能为了“必须复用XState”再加一层跨语言进程。

尤其注意：普通mailbox不自动等于有界优先队列。媒体数据不塞进同一个无限控制队列；本地停止优先，Actor异步启动耗时工作后继续处理控制事件。重启恢复、客户端水位和G02许可并不是装上XState就自然成立。

### 10.4 中断历史借鉴与本章所有权

固定提交`992309c0aa19845960228f880013d4685fde93b5`的`handle_individual_interrupt`取消会话任务，再把`heard_response`交给Agent并保存中断历史。[OS-C18](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber/blob/992309c0aa19845960228f880013d4685fde93b5/src/open_llm_vtuber/conversations/conversation_handler.py)

这个模式非常接近MIRA的需求。应复用“打断回传已听前缀、停止旧计算、下轮用截取历史”的工作流；MIRA再补客户端身份、截止游标、partial/unknown、字幕与图片的独立曝光记录。不能仅因为客户端传了一个字符串，就声称精确证明用户听到了每个字。



已发生的assistant内容进入可靠历史，已接受未呈现前缀只供当前计划审核，不混入共同经历；Codex线程、Hindsight包装器、VTuber历史处理器均不能成为第二写入者。该差分承接G03/G04，不重新定义生成器或数据库。

**交接：** WP05负责历史／outbox，WP06负责Actor；验收RI-04、RI-12、RI-13、RI-14、RI-15，原M系列与G4-P用例继续保留。表层`heard_response`不是精确sample证明；同步retain不能仅凭operation_id推断幂等。
