# M04 执行许可、打断与恢复

> **v0.6整合说明：** 原架构合同继续有效；本章新增“复用落点”只将借鉴书的既有证据和建议接到本章。具体技术栈未由本次整合自动批准；差分见A4，源码原阅读范围见A5。


**地位：** G02=A与G04政策已确认：单一全局控制版本＋完整有效许可集合；停止未来演出、保持仍合法的已成立结果；恢复与新计划重新开始分开。具体wire／算法、资源与设备能力仍待冻结／验证。  
**依据：** REQ第2–3页；V02 §11–12；MIRA §4、§5.4、§11.3、§12、§17；H1 §7–9；H3 §3–8；D4–D6；ADR-0004／0006；G3R §6.5、§10；G4R §1–14。

## 1. 三种资格与停止范围不能互相替代

准备计算不代表内容通过；内容通过不代表此刻可呈现；资源加载成功也不表示应该展示。首段隔离TTS仍需独立外传／合成授权，不能以“最终不会播放”为外发理由。[V02 §6.5、§11.1]

Input／Output Decision只参与资格形成，不能直接操作设备。Actor发放后客户端仍检查本地最新活动，因为用户可能在网络往返期间开口。

G04将停止范围明确区分为以下操作，不以一个含糊stop布尔量代替：[D6；G4R §1–3]

| 操作 | 未来行为 | 已有状态／持续约束 |
|---|---|---|
| 暂停当前输出 | 暂不推进，旧许可不可再用；工作只可有界暂存 | 可保留合法已有画面和可靠游标，等待进一步判断 |
| 停止当前回应 | 旧分支未呈现尾部永久失效 | 不自动清空已成立场景，不抹除历史 |
| 关闭指定对象 | 停止对象及依赖它的后续行为 | 隐藏／退出对象；重连不得自动显示 |
| 全部静音等持续限制 | 所有相关声音出口服从当前限制 | 与一次回复停止分开保存，不由新grant自动解除 |

这些是政策语义，不是已冻结的wire枚举，也不要求首版增加所有对应按钮。重置会话、隐私删除与麦克风权限是不同操作，不能由“停止回应”暗中代替。

## 2. G02裁定与保留备选

| 选项 | 组织方式 | 各通道关系 | 当前状态 |
|---|---|---|---|
| **A** | 一个全局控制版本＋完整有效许可集合 | 同一Actor发布完整状态，效果分别满足依赖 | **已确认，当前架构路线；D4** |
| B | 各通道版本＋公共撤销屏障 | 同一Actor管理通道增量与共同输入／分支失效 | 本次未采用；未来变更须新ADR |

B不等于多状态权威，也不天然不安全；A不等于所有模态一起等待或开演。分歧在授权组织与同步方式。[H3 §3]

G02确定组织方式；G04补足停止、保持与重新开始政策。两次裁定都不把下面的字段、安装算法和参数自动变成已冻结wire协议。

## 3. G02-A：许可集合与生命周期

逻辑载体采用PresentationPermitSnapshot，字段列表仍为细化提案。书版v0.6不替代消息schema_version。

```text
PresentationPermitSnapshot
  schema_version
  session_id / client_instance_id
  permit_revision / snapshot_digest
  observed_activity_seq
  input_epoch / validated_input_revision / output_epoch
  active_grants[]
```

每个EffectGrant引用接受计划、beat、effect、生成或资源来源、精确内容摘要、回应合同、允许范围、依赖、消费及停止／保持政策；不得带任意URL、代码或自由状态补丁。[H3 §4]

```text
snapshot 41：语音S1仍可继续
snapshot 42：保留S1合法范围，增加P1展示资格
snapshot 43：当前回应分支不再有未来执行资格
```

42替换41不使S1重播或误停；43之后迟到旧快照不能恢复旧演出。新集合替换授权状态，不重置effect消费和stream/sample游标。相同grant不得暗换内容；扩展范围等变更需新授权身份，但不改媒体来源，不倒退进度。集合是有界当前授权，不是全部历史或无限未来计划；媒体字节走数据通道。

### 3.1 与G03增量发布衔接

完整且语义上下文充分的范围经审核后由Actor重验，加入完整许可集合并保留仍合法的既有grant；不是每到一个beat就清空集合，也不是重播已完成效果。A整轮模式共用同一合同。[D5；G3R §6.5]

内容批准不覆盖本地停止或真实依赖。集合不能创造缺失的文字—音频对齐；无法可靠隔离的待依赖台词按M05 §5.1限制送入TTS或使用经验证隔离边界。

### 3.2 G04：回应效果与已成立场景维持分开

当前分支还要说、做、展示或推进的内容属于回应效果；取消后其未来执行资格消失。已显示照片、已完成镜头位置、预审环境循环属于已成立状态或受控维持，依据当前场景与有限保持政策保留，不是复活旧效果。[G4R §6]

上面的顶层output_epoch标识回应分支，**不能同时被当作所有持久场景对象的唯一寿命**。作用域如何编码、保持资格如何进入完整集合属于后续wire细稿；这一接缝未冻结，不得直接把示例schema当可部署合同。

两类对象仍由同一Actor、同一全局控制序列管理，不增加自发放权限的scene engine。停止／保持政策在效果获准时就应可供本地使用；客户端只在已批范围内制止、收紧或维持，不为每次制止等待云端，也不自行增加语义。

Actor后续快照明确移除旧回应未来资格，保留仍合法的场景维持。保持要求同一内容、合法作用域、无新披露、无未来beat及旧回调自动演出；显式隐藏／静音／撤销优先。资格或对象未知时先收紧并同步。新客户端、重连、保持期限变化须复核；保存历史不授权重新显示。[G4R §6.2–6.3]

## 4. 接收、安装与最终检查（实现细稿）

区分highest_seen_control_revision与installed_snapshot_revision；它们是同一控制序列的接收与安装水位，不是两个权威来源。看到较高版本但缺少前提同步时hold，不继续沿旧许可播放；撤销可立即收紧，扩权须等前提满足。同版本同摘要重传幂等；同版本不同摘要按协议错误收紧；跨会话／实例消息不推进本地水位。[H3 §5.1]

回应效果执行的候选检查：

```text
会话／客户端实例匹配
AND 当前控制状态同步、许可有效
AND 本地无阻止该效果的停止屏障／未决活动
AND 许可观察到本地最新activity
AND 当前输入与有效回应分支相符
AND 覆盖精确效果／流范围、批准内容身份匹配
AND 资源、当前可见对象与其它依赖成立
AND 游标合法、连续、不重复
AND 角色人声槽及其它资源条件允许
```

场景维持按§3.2与§7的已批保持合同检查，不凭旧回应grant继续；精确检查分流仍待实现。快照替换、入队和sink须有清晰顺序；检查后恰好打断的旧回调也不能获得新提交资格。长段内容不能因一次检查就全部不可撤销地交给设备。

本地观测立即收紧逻辑资格，但远端事实传播与设备已提交尾部不可瞬间回收；分别测量，不宣称逻辑原子替换等于声卡／GPU／网络物理事务。[V02 §11.4；MIRA §11.3]

## 5. 本地接管、停止锁与重新开始

客户端activity从8到9即抑制旧未来输出；随后更高版本但仍观察8的许可不能执行。较新控制版本不证明看见本地最新输入。明确STOP设置锁并通知Actor永久失效相关分支，不等待模型批准；grant本身不能清除锁。[V02 §11–12]

### 5.1 重新开启采用因果绑定

重新开启必须关联已处理的停止依据、当前用户交互／可靠请求与针对它的新回应；精确事件和字段名待冻结。客户端核对没有更新停止或未决活动，才能按同步顺序允许新回应。不能随手设置stopped=false，也不能只看grant数字更大。[G4R §7]

重新开启只授权合法新回应，不移除旧分支invalidated终态，不自动解除静音、隐藏或其它持续用户边界。

### 5.2 同次主动输入可以既停旧又发起新请求

明确按住说话或提交新文字按主动接管处理：立即停止旧未来演出、旧未呈现分支失效；可靠请求形成后，允许新分支响应这一次交互，不要求多点一次解锁按钮。空录音、纯噪声、旧请求重传或服务器任务完成不构成可靠新请求；空输入不恢复旧分支。[G4R §3.2、§7.2]

### 5.3 只有停止，没有新请求

只点击停止回应时，旧任务完成、无新有效请求的ASR final、计时器、重连或filler就绪都不构成重新开口的原因。停止按钮不自动授权“好的”。可以显示非语义停止反馈；只有真实新输入才进入对应收音／倾听流程，不扩大麦克风权限。[G4R §7.3]

### 5.4 更新停止覆盖旧的重新开启

S1停止→U2请求→准备响应→S2再次停止：针对S1/U2的迟到重新开启不得清除S2，必须核验本地最新活动、停止依据及请求因果。该检查独立于许可版本较大；同次交互与更新停止的准确仲裁算法仍待实现与负控验证。[G4R §7.4]

## 6. 暂停与永久失效分开

| 事件／入口 | 即时处理 | 分支与收口 |
|---|---|---|
| 类别未知的疑似发声 | 本地暂停声画语义推进，增加activity | 不直接新建逻辑话轮；有效工作仅有界暂存 |
| 确认噪声／短附和且旧回答仍适用 | 不自动恢复旧许可 | 只有恢复开关与全部合同满足，才有新授权可能 |
| 明确PTT／提交新文字 | 用户主动接管，停止旧未来演出 | 旧未呈现分支失效；可靠请求响应同次交互 |
| 明确停止回应 | 本地锁与清理可播尾部 | 永久失效，按钮本身不新增主动回复 |
| 含糊停止词／未识别完整 | 先抑制 | 不靠关键词或静音时长判定恢复；可靠确认停止后不再投票 |
| 新问题／关键纠正／换话题 | 阻止依赖旧条件的内容 | 默认失效未呈现分支；不先建设任意跨模态局部拼接 |
| 关闭指定对象 | 本地隐藏／停止对象及依赖 | 其它未呈现部分只有真实依赖证明才可能保留，否则取消相关分支 |
| 不确定／超时／预算耗尽 | 不把超时当恢复资格 | 关闭复用优化，取消旧分支，等待有效输入或重规划 |

“别停，继续”不能按孤立“停”字处理；用户要求等待的暂停也不能仅因随后无声而自动续播。兼容补充不是把新输入偷偷塞进不支持原地更新的模型API。[V02 §12；G4R §3]

暂停期间停止新增TTS push，但在途音频和主模型仍可能计算；时间、追加音频及总缓冲均有预算。永久无效即取消，不为提高复用率保留；共享合法场景缓存与旧任务执行权分开。[G4R §10]

`pause_resume.semantic_resume_enabled`仍**默认关闭**，只有适配器、设备回执及相关必需效果能力验证通过后才可独立启用。关闭时先即时暂停，再保守取消，不因本次G04批准而自动打开。[V02 §12.5；G4R §8.1]

## 7. G04已确认的画面保持与停止政策

原则：停止未来语义演出，保留仍获准且已经成立的场景结果；显式隐藏、静音和用户边界覆盖保持。下表是G4R回填的政策，具体资产、布局、时长和回执实现不是已验证能力。[D6；ADR-0006]

| 对象 | 临时暂停 | 明确停止／新请求后 |
|---|---|---|
| 正文、等待语、视频内角色人声 | 即时抑制，停止口型驱动 | 清理可播尾部；等待语不续播，不自动补“好的” |
| 未显示字幕／后续更新 | 停止推进 | 取消，不补齐未显示整句 |
| 已显示字幕 | 可保持已显示前缀 | 新交互清理主字幕位，披露历史保留 |
| 已显示静态照片 | 同内容、同展示状态保持 | 默认作指代对象保留；关闭、撤销或条件失效则隐藏 |
| 尚未显示的照片／媒体 | 就绪不自动显示 | 旧资格失效，迟到成功不弹出 |
| 已完成环境／镜头状态 | 不自动复位 | 在有限保持政策内保留；输入反馈仍应可辨认 |
| 正在推进的语义动作／镜头 | 停进度与事件 | 终止原动作，只走预审非语义收势 |
| 剧情视频 | 停时间线与人声，不前跳取帧 | 回常驻角色；有可靠且获准的已呈现静帧才可保留参照，无则保守退回 |
| 呼吸、眨眼、持续雨声 | 预审无新语义维持可继续 | 默认可继续；静音／静止要求优先，不夹带剧情 |
| 未执行OpenIntent | 不当已发生 | 打断后挂起不自动重邀，明确拒绝关闭，新请求再评估 |

### 7.1 已展示与当前可见分开

保持照片不保留继续旧讲解或自动换图资格；隐藏只改变当前可见状态，不回滚曾呈现事实。当前可见依赖与历史曝光使用不同依据，重连须同步已隐藏状态，不能从“曾显示过”推断应当重新显示。[G4R §4.2、§6.3]

### 7.2 视频静帧必须有真实来源

只能使用已真实呈现、位置与来源可追溯且仍获准的帧；不seek未来关键帧，不改用未展示剧情封面。不能核验时退回常驻角色并记录不确定范围。静帧不等于video_completed，不触发依赖视频完成的后续效果。此政策不批准G06生成视频范围。[G4R §4.3]

### 7.3 安全收势是有限运行态过渡

停止口型、释放旧动作参数、进入受控倾听姿态可以作为停止过渡；不得新增话语、同意、承诺或披露，也不得演完递照片、揭幕和越过新信息区的镜头。[G4R §5]

原效果interrupted与停止过渡completed分开，旧动画结束回调不能提交原业务完成。没有已验证的无新语义退出能力时保守保持当前显示或切至审核中性状态，不能跳最后一帧；不满足的素材不得宣称具备本场景打断能力。interruption_policy_ref是候选字段，尚未冻结。

倾听状态不清空情绪／剧情，不推断用户生气；默认姿态不能重新举起相机、破坏已有拍照边界。

## 8. 恢复原分支与新计划续接

### 8.1 未失效分支的恢复条件

分支未失效、最新输入兼容、内容批准有效、新许可看见最新活动、可靠游标可续、对象与必需依赖仍成立、适配器具备能力、预算未耗尽且实验门槛通过，缺一不可。compatible或用户让出话轮不是恢复许可；同话题新问题不能被旧讲解替代。[V02 §12.4；G4R §8]

可靠sample游标与逐字对齐分开。缺逐字时间不必然禁止PCM恢复；设备尾部或队列未知时不能猜精确位置，保留partial／unknown并放弃盲目重放。

### 8.2 混合表演与定时器

音频可续不代表动作、视频与镜头都能续。若必需效果不能恢复，按已批准降级或新计划处理；可选装饰仅在原批准降级范围内省略，不临时改optional。旧绝对时间定时器不得在恢复瞬间追赶执行过期字幕／镜头；依真实媒体游标和仍成立依赖重调度。[G4R §8.2]

### 8.3 已失效后的“继续”

必须形成依据已呈现事实、partial／unknown、当前限制与未完成义务的新计划；允许合法素材数据复用，不恢复旧effect身份或旧许可，不重复弹出仍显示的照片。[G4R §8.3]

“继续”所指视频、讲解或动作由Input结合当前实际候选消歧，无法确定则在当前限制内澄清，不默认启动全部通道。新回应使用G03完整语义范围审核和G02-A资格路径，A保守模式也相同。

## 9. 迟到、重复与重连

旧结果不得执行；旧有效回执核验effect、序号与停止截止后只补历史，不触发补演。ACK丢失不等于未播放，重连不清空消费账后重播；未知按partial／unknown处理。

恢复连接必须同步实例、许可水位、停止屏障、已消费范围、已隐藏状态和仍有效持续约束；重新连上本身不授权说话或重新显示用户关闭媒体。[G4R §10]

新客户端实例使旧实例授权不适用。Actor重启不得在同一可接受身份内重置单调序列后接受旧消息；不能可靠续接时需明确新控制实例。持久化、重启和时间映射算法仍待冻结。[H3 §8]
