## 2. 正常混合回应

用户请求看照片。R1解析指代与邀请，Actor保留当前可用事实及限制；R2同一次生成提出与指定照片一致的完整候选；R3按语义充分范围核验，必要时等后文或合并多个beat；R4在依赖准入条件下准备素材与可选语音；R5使用Actor发出的完整有效许可集合，仅在本地最新活动、精确效果许可和依赖都成立时执行。

不依赖图片的预备台词可先出现，依赖“现在这张图”的讲解则等待真实展示条件。R7分别记录声音、字幕、图片和动作，不因为其中一个完成就宣称整个计划完成。G03允许完整且语义上下文充分的前段先进入审核与发布；必要信息不足时等待至整轮，A作为同合同保守模式和对照。具体范围与封口格式仍待冻结。[D5；G3R §6–8；H1 §6.4]

## 3. “不要拍我”：纯动作可以回应

可靠输入先成为当前边界，不等待动作完成。主模型在允许能力内提议放低相机，utterance可以为null。输出审核检查动作与边界一致；程序绑定必需完成条件；有效许可下执行，真实回执才支持“相机已放低”。

如果动作失败，边界继续有效，不能写相机已放低，也不能因失败再次拍用户。没有语音效果则不创建空TTS，不等待不存在的audio_end。[G01；H2 §9.1]

## 4. “陪我听雨”：完成建立，不让生成永远挂起

新请求先抑制旧演出，再按当前输入范围提议姿态／场景变化。实际建立后完成本次回应，进入情境性的安静陪伴保持；麦克风和停止入口仍可用。

没有正文音频不代表需要filler。用户明确要求不讲话时，等待和失败路径也不能补播语音。之后新提问会产生新的受限选择，不复活旧讲解；同一个“嗯”也不自动开启剧情。[H2 §6、§7.1、§9.2]

## 5. “这张里是谁”：展示中打断

打断前：P1已呈现，S1已播完，S2部分播放，S3秘密解释与C1近景尚未执行。

```text
新活动
  → 本地抑制声音和未来S3／C1，记录实际游标
  → 可靠转写“等一下，这张里是谁？”
  → Input看到P1、S1、partial S2、未执行S3／C1和允许剧情事实
  → 确认新问题后旧分支失效
  → 新计划基于真实呈现历史回答，不假定S3已讲过
```

话题仍是照片不证明旧解释应继续；“保持P1已显示事实”也不等于“允许旧未来效果继续”。按已确认G04，P1仍获准且未被要求关闭时保留原位；用户明确关闭或保持条件失效时隐藏。[D6；G4R §4、§11]

旧图片结果后来到达不能展示；旧有效回执核对停止截止范围后可补历史。无法确认S2确切末尾时保留partial／unknown，不以字数估计伪造精确已说内容。

## 6. 取消后的“继续”

若原分支只是暂停且仍有效，最新输入、批准、依赖、游标和能力都满足，才可能在启用门槛通过后新授权恢复。若已永久失效，“继续”应形成基于当前事实的新计划；可以引用已审核资产或材料，但不能重新激活旧effect身份。[V02 §12；H1 §8.3]

不把ValueHermes节点重跑方式直接用于已呈现效果。远程计算可以根据任务能力重做，已经看到的图片或听到的台词不能因重跑再来一次。

### 6.1 G04：只有停止与同次主动输入

只有停止时，本地锁、取消旧尾部与非语义UI反馈完成后等待新请求；旧任务完成、计时器、重连或filler就绪不自动发声。

主动PTT／文字可以在同一交互内先停旧、再以可靠请求发起新分支；空录音和旧重传不解锁。重新开启关联已处理停止、当前请求与新回应，未完成请求和持续边界按真实当前状态重建。[G4R §7]

### 6.2 更新停止优先的竞态

S1停止→U2请求→准备新回应→S2停止→S1/U2的许可晚到：本地按最新停止与activity拒绝旧重新开启。许可版本更高也不清除S2；旧分支invalidated不因新交互抹除。

### 6.3 混合恢复与场景保持

未失效分支只有全部输入、批准、游标、依赖、预算、能力与开关门槛成立才可新授权。声音可续但必需动作不可续时按已批降级或新计划，不伪称整体恢复；旧定时器不追赶执行。照片保持不重播展示效果，视频静帧不当完成，原动作中断与收势完成分别记账。[G4R §5–8]

## 7. 失败路径的统一处置

| 失败 | 用户侧处理方向 | 状态与资格 |
|---|---|---|
| ASR不确定／关键修订 | 继续倾听或在限制内澄清 | 旧候选不得利用旧判断放行 |
| 主模型超时／流损坏 | 显式失败反馈和重试入口 | 未验证半句不执行；保留真实已播前缀 |
| schema错误／未知动作 | 有限修复或受控替代 | 不执行错误计划的一部分来冒充成功 |
| 内容审核失败／过时 | 重规划受影响候选 | 不把allow旧结果应用到新内容 |
| TTS失败 | 允许时字幕／文字降级 | 文字实际显示另记披露，不记已播 |
| 图片未就绪／失败 | 在当前约束内说明或替代 | 不提交photo_presented，不放行依赖图的台词 |
| 生成媒体验证缺失 | 不放行或受控素材回退 | prompt和文件成功不能自证内容 |
| 缓冲超限 | 截断原因可见，取消未播尾部 | 不跳过中间段继续，不伪装正常完成 |
| ACK丢失／断线 | 核对实例与消费游标 | unknown不当未发生，不重复执行 |
| 后台摘要晚到 | 当前会话继续 | 不覆盖新边界或删除状态 |

这里的“替代”不是执行器随意改台词。替代必须已在当前合同内，或重新经过相应审核与资格路径。静默、披露和作用域约束同样约束故障处理。[H3 §2.2；MIRA §17]

### 7.1 增量首段已呈现，后段失败

第一范围显示P1并产生真实回执，第二范围生成失败或审核拒绝：R3／R8记录失败并失效受影响分支未呈现尾部，R5更新许可集合，R7保留P1呈现事实及未满足义务，不能把整轮写成completed。不得跳过错误中段执行依赖后文，也不得用同一身份改写前段。[G3R §8、§11]

需要续接时，R6依据最新输入、可靠历史及partial／unknown范围形成新计划；语义／静默／披露限制仍成立，不重演已完成效果。若采用A整轮模式，同样复用接受、许可、执行、回执和失败合同，不另写一条演示成功路径。

## 8. 流程验收和未决

以固定输入、判断、计划和回执序列回放，检查状态归约与取消是否确定一致。真实Provider与Mock要经过同一计划、资格和回执路径，不能只在演示模式成立。[MIRA §19 M24–M25]

本章已回填G02=A、G03语义充分范围增量发布及G04停止／保持／因果重新开始，G05／G06现由D7确认，具体后端、订阅承载和真实媒体能力仍需验证。集合安装算法在M04细化，范围／framing／封口在M03细化，TTS依赖准入在M05细化；路线获批不等于字段、算法或适配器已经验证。

### 10.1 联调切片：不是重新开发基础设施

沿用借鉴书的首个纵向切片：**角色正在回应→用户打断→旧图片迟到→新请求得到回应→历史仍准确。**桥接提供候选和实际图像，音频与Renderer提供执行，Actor保留已定状态规则，回执归约补可靠历史；MSW或Fake Backend控制迟到与失败。

先固定这条链的输入／输出，不并行启动第二套AgentSession；公开演示仍以同协议Mock承接不可公开的外部服务。首个链路成功也不抵消后续真实中文、声音与素材验收。
