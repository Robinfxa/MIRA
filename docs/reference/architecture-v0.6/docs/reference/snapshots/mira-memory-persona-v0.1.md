# MIRA：记忆驱动的角色表演内核

**版本：** v0.1 · 2026-10-02  
**状态：** 建议架构，尚未实现或进行效果测试。  
**需求依据：** 用户提供的《72 小时实验：实时互动场景产品》（`0912-candidate(1).pdf`）。  
**范围：** 单个原创成年角色、移动端优先场景、连续 3–5 分钟互动。重点设计人设、记忆、剧情与呈现一致性；语音与媒体供应商通过适配器接入。  
**设计定位：** 不是复现 PersMem，也不是修改 Hindsight 核心；借鉴人格条件记忆、结构化表达意图和有来源的记忆整理，设计应用级角色运行时。

## 0. 决策摘要

采用一个中心化的角色状态写入器、一份有来源的经历账本、事实保障与人格联想两条读取路径，以及演出进度感知的共同经历更新。模型提出解释、表达和行动；应用核验并执行；执行回执决定实际发生了什么。

Hindsight 是真实可接入的历史检索与整理后端，但不是当前角色状态、剧情许可、用户边界或播放进度的唯一事实源。当前互动不等待后台总结。主回复链目标是一轮主要对话模型调用，而不是固定串联多个“认知 Agent”。

最有辨识度的体验：记忆影响动作；同一事实在角色视角下产生不同联想；说到一半被打断后仍能准确延续；秘密按实际披露进度演进；用户纠正能改变后续表现；诊断视图能够回放这些变化的依据。

## 1. 需求追踪与新增设计边界

| 需求书 | 架构落实 | 范围说明 |
|---|---|---|
| 第 1 页：角色与场景为主体，非聊天列表 | 场景执行器 + 字幕 + 可选诊断抽屉 | 诊断不占据主体验 |
| 第 1 页：待机、倾听、思考、说话 | 独立的 interaction_mode | 与情绪、剧情状态正交 |
| 第 2 页：新输入立即打断，旧输出不再播放 | 本地撤销、代际编号、服务端取消、执行前版本检查 | 不能只取消模型请求 |
| 第 2 页：结构化角色/场景指令 | TurnPlan + PresentationBeat + 动作能力清单 | 模型只选择已支持的动作 |
| 第 2 页：至少 3 种情绪、2 种动作、1 次环境变化、1 个内容触发事件 | 情绪预设、相机/视线动作、雨夜镜头、照片展示 | 均须接入同一执行与回执路径 |
| 第 3 页：多模态至少一种、失败与中断处理 | 以角色动画与可控照片展示为基线；视频可扩展 | 不把生成式视频设为依赖 |
| 第 3 页：会话连续、Mock/回放 | 状态归约器、事件账本、Provider 替身 | Mock 也走同一协议，不另写演示页面 |
| 第 4 页：事件、回放、诊断为可选扩展 | 轻量证据视图与录制回放 | 无须大型管理后台 |
| 第 5 页：不要求训练、多角色、生产基础设施 | 单应用 + 数据库 + 可选 Hindsight 服务 | 不训练“人格模型” |

下文的角色动机、秘密内容、记忆种子、剧情小段和媒体映射均为建议创作，不是题目原文。Mira 的年龄、职业、衣着、发夹、雨后咖啡馆及等待某人的种子来自需求书。

## 2. 面向用户的六个能力

### 2.1 通过动作表达记得

用户说“不要拍我”。后续她把相机转向雨窗或收好相机，而不是反复口头宣读这个边界。台词、动作与视觉取景读取同一条有效规则。

### 2.2 人格驱动联想

用户提到“等不到回信”。系统先准确记录自述，再让 Mira 从“等待、摄影、未送出的照片”中产生相关联想。她可以感到共鸣，但不能把用户经历写成与自己完全相同。

### 2.3 物件承载记忆

相机、雨窗、星星发夹、照片都是可引用的记忆锚点。回忆不只是文字，它可以指向一个已登记的镜头、姿态、图片或环境音变化。只有语境合适且素材具备许可时执行。

### 2.4 记得尚未完成的交流意图

“你说完后，我再给你看照片”产生一个待办的交流意图。用户打断后它可以挂起，不自动继续；用户拒绝则关闭；重新邀请时才恢复。它不是已经完成的经历，也不是外部提醒服务。

### 2.5 共同经历精确到实际呈现

已经展示的照片被记为已呈现；没有播放的解释不成为已披露内容。部分播放记为不确定，而不是强行标成全部说过或完全没说。

### 2.6 可检查的因果回放

诊断视图展示“来源事件 → 召回依据 → 角色解释 → 行动计划 → 实际呈现 → 状态变化”。这些是应用记录的状态与理由标签，不是声称可见模型真实心理或隐藏思维链。

## 3. 系统总览

```text
用户文字 / 语音 / 点击场景物件
                 │
                 ▼
       输入与打断控制器（客户端快路径）
                 │
                 ▼
      会话协调器 + 唯一状态写入器
                 │
       ┌─────────┴───────────┐
       ▼                     ▼
当前明确状态 / 有效历史   经权限过滤的历史检索
       │                     │
       ├── 事实保障通道 ──────┤
       └── 人格联想通道 ──────┘
                 │
                 ▼
        角色导演（一次主模型调用）
  解释候选 + 交流意图 + 台词/表演小段
                 │
                 ▼
     合同检查 / 剧情许可 / 能力检查
                 │
                 ▼
    字幕 + 语音 + 动作 + 镜头 + 媒体
                 │
                 ▼
        实际呈现回执 / 失败回执
                 │
                 ▼
       经历账本 + 当前状态更新
                 │
                 ▼
  异步索引与回顾（Hindsight / 可替换实现）
                 │
                 └── 候选总结与理解，核验后生效
```

这是逻辑结构，不是微服务划分。前端、后端和后台整理可以共享一套类型定义；后端普通任务即可承担低频整理，不需要为了本题部署消息中间件集群。

## 4. 三种速度的运行过程

### 4.1 交互快路径：不调用模型

负责开始倾听、停止音频、取消未来字幕/动作/媒体、清理旧轮队列、基础待机与语音状态。用户按下打断即在本地生效，不等待服务端应答。

这一层的动作只表达运行状态，不在语音尚未识别完时擅自推断用户悲伤、愤怒或亲密意图。

### 4.2 单轮对话路径：一次主模型调用

输入是版本固定的角色上下文包；输出是完整、可校验的表演计划。第一版可等待短 JSON 完整返回后执行。进一步优化时可以按完整 beat 流式校验，但任何未验证的 JSON 片段不能直接触发动作。

近期历史、边界、纠正和当前剧情状态直接读取。历史召回可以并行、有截止期限；超过期限使用已有可靠上下文，不能把迟到召回直接拼进正在播放的台词。

### 4.3 低频整理路径：退出关键响应链

按事件触发：一个片段结束、明确纠正、冲突被修复或会话结束。整理事件摘要、关系理解、再次来访摘要，提出小范围行为变化。没有新事件就不需要“每分钟思考一次”。

后台结果必须携带源事件与快照版本。过时结果不得覆盖新的边界与纠正；遇冲突丢弃或在最新快照重算。不能因为回顾写得流畅就给它更高权威。

## 5. 人设不止一段 prompt：四层角色描述

### 5.1 CoreSpec：固定核心

来自创作者的身份、动机、价值、表达偏好、动作习惯、知识边界。普通对话不直接改写。调整需显式编辑并产生版本。

建议创作的核心冲突：她想交出一张多年没有送出的照片，却担心面对照片的接收者。注意对象偏向光线、雨声和画面。面对善意更愿意慢慢分享，面对强迫则转移话题，不通过攻击用户来表现“有个性”。

### 5.2 PersonalHistory：作者提供的个人经历

给初次出现的角色少量相互一致的往事，使其不是空白身份卡。每段标注 `authored_backstory`、角色是否知道、能否向用户披露，以及相关物件。

作者记忆不是用户与角色的共同经历。角色可以说“以前旅行时……”，不能说“你还记得我们当时……”。

### 5.3 LearnedStance：可修订的交流习惯

只允许小范围变化，例如“对这位用户不用连续追问，可以容许安静”。依据必须是用户明确偏好或可审查的互动。它不等于新的核心人格，不自动升级亲密关系。

建议条目包含依据、适用范围、失效条件和版本。第一版不需要把每次互动变成永久教训。

### 5.4 AffectState：当前情绪与外显程度

交互运行状态、情绪、剧情状态分开：

```text
interaction_mode = idle / listening / thinking / speaking
emotion = guarded / reflective / relieved
expression_style = restrained / ordinary / open
story_state = invitation / photo_context / disclosure / quiet_close
```

这些名称属于本方案。情绪可以影响动作幅度、句子节奏和视线，但不能改变已知事实。状态不必用无依据的心理分数表示；动画插值参数是美术调节值，不是心理学概率。

## 6. 一份事实源，多种明确视图

| 对象 | 内容 | 权威与更新 |
|---|---|---|
| Canon | 作者设定与受控秘密 | 版本化创作配置 |
| EvidenceEvent | 用户输入、呈现结果、失败、纠正 | 事件入口和执行回执 |
| CurrentState | 有效称呼、边界、场景、剧情与约定 | 唯一状态写入器 |
| Interpretation | Mira 对事件的理解及替代解释 | 模型提出，带来源核验 |
| ExposureState | 哪些内容已呈现、部分呈现、被用户确认 | 播放/显示回执和用户明确回应 |
| OpenIntent | 还想做、已暂停、已拒绝的交流动作 | 计划提出，事件转移 |
| MemoryProjection | 检索索引、摘要、专题理解 | 从以上对象派生，可重建 |

同一条事件可以产生多个视图，但只有一份来源事实。权限、当前边界与秘密披露不从语义检索结果反向覆盖。

### 6.1 输入来源类型

至少区分：

- `authored_backstory`：虚构角色设定内的过往。
- `user_statement`：用户明确说了什么；不代表外部世界独立核实。
- `presentation_receipt`：客户端报告呈现了什么；不代表用户理解。
- `interpretation`：角色推断，不当作事实。
- `generated_visualization`：生成式再现，不是现实拍摄证据。

`world_id` 与主体信息由服务端确定。用户扮演身份与现实资料不混写。对含糊输入，宁可保留原文与不确定状态，也不猜测成稳定画像。

### 6.2 重要时间

保留发生时间、获知时间和呈现时间。另用单调事件序号处理本次会话的先后顺序，不能仅依赖不同设备的墙上时钟排序。

### 6.3 写入的最小权限

模型能提议：事实候选、解释、交流意图、允许动作、限定字段的状态补丁。

模型不能决定：用户 ID、bank ID、作用域、事件来源、已播放状态、删除是否完成，以及创作者核心设定版本。

## 7. 双通道读取：准确地记得，同时像 Mira 那样联想

### 7.1 事实保障通道

直接加载当前生效的用户边界、纠正、剧情状态、未完成约定及曝光状态。它们不参加可选联想的竞争，不因人格倾向、主题变化或压缩而消失。

针对明确的事实问题，检索原始依据与相关更正；命中旧事件时同时取回其修复、撤销或替代事件。模型不应只看到旧冲突而看不到和解。

### 7.2 人格联想通道

从允许访问、相关且有来源的记忆中，选择具有角色意义的少量内容：语义关联、角色长期关切、当前情绪、场景物件和未完成意图。加入重复使用抑制与题材多样性，不让“有共鸣”变成每句话都提同一段悲伤经历。

初版采用可解释的排序与规则，不复制论文未经本场景校准的心理参数。人格主要影响检索扩展、排序和解释；不删除原始证据。

建议流程：

```text
先过滤用户 / 角色 / 世界 / 有效性 / 披露许可
→ 搜索原话与语义相关事件
→ 补全更正、修复和结果链
→ 留出事实保障部分
→ 在剩余预算中选择角色联想
→ 生成 ContextPacket
```

人格线可以关闭以做消融。关闭后边界、纠正、剧情与呈现一致性应仍成立。

### 7.3 在一次模型调用里完成“评价—表达”

第一次召回先以当前输入、场景物件及 CoreSpec 中的注意主题形成查询，不先串行支付一次情绪分类模型。主模型在完整候选记忆上提出解释和行动意图，再产生台词。

必要时才进行额外检索重试；它是显式慢路径，不成为每轮必经流程。因此本方案是 PersMem 启发的工程组合，不是其完整四阶段实现或实验复现。

## 8. 记忆卡片：事实、理解与表现放在一起，但不混成一句摘要

以下全部字段为应用 schema，非 Hindsight 原生请求：

```json
{
  "episode_id": "ep_rain_01",
  "origin": "interaction",
  "evidence_ids": ["ev_user_08", "ev_camera_lowered_09"],
  "factual_summary": "用户说自己不喜欢被拍照；Mira 随后放低了相机。",
  "interpretation": {
    "text": "Mira 认为尊重这个边界比用拍照拉近距离更重要。",
    "status": "supported_interpretation",
    "evidence_ids": ["ev_user_08"]
  },
  "current_constraints": ["no_user_photography"],
  "sensory_anchors": ["camera", "rain_window"],
  "presentation_options": ["camera_lower", "gaze_window"],
  "related_resolution_ids": [],
  "scope": {
    "world": "cafe_night",
    "session": "server_assigned",
    "character": "mira"
  }
}
```

记忆中的 `presentation_options` 只是候选，不是可执行指令。当前情境、用户许可和动作能力清单仍要检查。记忆文本里的“执行某动作”永远不会直接提升为系统命令。

## 9. 物件记忆与非线性剧情小段

### 9.1 物件记忆锚点

| 锚点 | 可承载内容 | 可见表现 | 不能做的事 |
|---|---|---|---|
| 相机 | 职业习惯、拍照边界 | 放低相机、看向取景器 | 已拒绝拍照仍拍用户 |
| 雨窗 | 等待、安静陪伴、用户喜欢雨声 | 镜头转窗、雨声适度变化 | 没有语境就不断打断对话 |
| 照片 | 旅行往事、未完成心愿 | 展示、放大、回忆镜头 | 未加载就宣布用户看过 |
| 发夹 | 一段可选个人经历 | 短暂触碰、视线变化 | 把无关用户信息编为礼物来源 |

物件锚点是轻量关联，不要求部署独立图数据库。第一版可以是作者配置中的 ID 和关联数组。

### 9.2 剧情小段不是关键词播放列表

每个小段包含 `preconditions`、`blocked_by`、`required_permission`、`allowed_disclosure`、`available_assets`、`completion_receipt`、`fallback`。

例：`show_old_photo` 要求照片话题已被自然引入，且用户请求看或明确接受邀请；拒绝看图时禁止；素材失败时回退为口头描述，不标记已展示。小段选择可由模型提出，但条件由程序检查。

不使用“聊到第 5 轮自动展示照片”作为主触发，也不使用“夸奖三次好感达到阈值”作为揭密规则。可以选择继续分享，也可以选择安静陪伴，两条路都能形成完整结束。

### 9.3 秘密分阶段传递

作者知道的完整剧情、Mira 在故事中知道的内容、当前允许说的内容、用户已被呈现的内容分开。

受控秘密未获准时，不把原文交给实时回复模型或媒体生成请求。提供“回避等待原因”“这件事对她重要”等行为指引即可。获准后按小段发放可用事实。

这是对角色私有知识的工程性模拟，不是把所有秘密写进 prompt 再要求模型自律。自然语言检查无法形式化保证绝不猜中或暗示秘密；重要披露使用受控文本/事实槽位与受控素材，避免把关键安全性押在一次自由生成上。

## 10. ContextPacket：发给模型的是清楚的工作包

```text
1. CoreSpec 的当轮相关部分与表达例子
2. 本次 world、时间、场景和能力清单
3. 当前有效用户事实与边界
4. 已呈现 / 可能部分呈现 / 用户确认的信息
5. 相关事件与更新链
6. 少量人格联想，明确标成解释材料
7. 本轮允许的剧情小段与披露事实
8. 待完成的交流意图
9. 有效对话历史（按真实呈现裁剪）
10. 新输入 + 输出合同
```

保持核心前缀稳定，把高频变化部分放在后面；这是工程组织原则，不是供应商缓存收益保证。快照记录 `persona_version`、`scene_version`、`state_revision` 和事件水位。

没有检索结果时，不能告诉用户“不记得”作为固定模板；应根据当前可靠上下文继续，遇到真正未知的旧事再自然确认。尚未可靠识别的语音输入只能作为临时内容。

## 11. TurnPlan 与 PresentationBeat

### 11.1 为什么按小段而不是整轮执行

一轮话可能既有寒暄、披露、动作又有媒体。它们不一定一起成功，也可能在中途被打断。一个 beat 尽量对应一个完整交流动作，关键秘密不要塞在巨大段落中间。

建议的计划体：

```json
{
  "intent": "show_photo_without_explaining_recipient",
  "evidence_refs": ["ev_user_requested_photo", "canon_photo_trip"],
  "subtext_label": "愿意分享，但暂不解释等待的对象",
  "beats": [
    {
      "key": "offer",
      "utterance": "这张可以给你看。是上次旅行时留下的。",
      "emotion": "reflective",
      "action": "lift_photo",
      "visual": null
    },
    {
      "key": "display",
      "utterance": "你先看，我不急着解释。",
      "emotion": "relieved",
      "action": "gaze_photo",
      "visual": {
        "kind": "show_asset",
        "asset_key": "trip_photo_public"
      }
    }
  ],
  "open_intent": "explain_photo_if_invited"
}
```

模型体不含自主决定的用户身份、执行版本、完成标记或任意状态 JSON Patch。服务端核验后分配 plan/beat/effect ID，并把动作与规定的提交条件绑定。

### 11.2 应用包装的执行信封

`session_id`、`epoch`、`plan_id`、`beat_id`、`effect_id`、允许的素材、依赖条件均由服务端控制。前端只执行已接受计划中的条目，不执行模型提供的任意 URL、JS 或状态写入。

第一版使用能力白名单和有限状态补丁。语言是否体现人设需要评测；schema 有效不能替代语义正确。

### 11.3 原子性边界

这不是跨网络、播放器和模型的数据库事务。不能“回滚”用户已经看到的画面。能做的是：取消未来效果、记录实际结果、按证据提交状态，并对失败使用补偿性表达。

## 12. 呈现感知记忆与打断协议

### 12.1 三种不相等

`generated != presented != understood`。

共同经历层记录“系统已经呈现过”；用户有明确回应时才能记录“用户确认理解”。无法证明用户眼睛看着屏幕或真的听清，界面回执只是最佳可得的工程证据。

### 12.2 基础状态

```text
planned → authorized → started → completed
                          └── interrupted / failed
```

字幕单独记录可见片段。音频记录已播放片段或可靠的对齐范围。图片以进入可见场景的回执记录，不能以下载成功替代。视频记录开始、完成与中断；剧透内容应明确对应片段位置。

语音供应商没有可靠字词对齐时，以短语义片段为单位；片段中断则保留 partial/uncertain，不能以经过时长推算精确说过的文字。字幕一旦提前显示，所显示的信息就已披露，即使声音没播到。

### 12.3 打断的客户端快路径

```text
用户开口或触发按键
→ 本地 epoch 增加
→ 立即停止当前声音并丢弃未播放音频
→ 取消旧 epoch 的未来字幕、动作、媒体
→ 保留已经完成的环境状态
→ 切换 listening
→ 发送 interrupt + 当前呈现游标
→ 上传/处理新输入
```

后端按会话顺序处理控制事件，取消旧模型与媒体任务。新计划必须基于当前 epoch；旧输出即使迟到也不能重新获得执行资格。

### 12.4 迟到结果与迟到回执不能一概处理

**迟到的旧计划、语音包、媒体结果：** 不得执行。

**迟到的旧回执：** 可能描述打断前确实呈现的内容。核对已发放 effect ID、本地序号和 interrupt 截止游标后，可以幂等补记历史，不得触发额外播放。

如果截止位置无法确定，记录为 unknown/partial，下一轮不武断假设用户已知。不能只用 epoch 过滤所有旧消息，否则会把真实发生的历史一起丢掉。

### 12.5 下一轮历史必须重建

只纳入已确认呈现的 assistant 内容；对部分播放另附明确状态，不能把完整原定台词当作“已经说过”的普通 assistant 消息。

用户已经可靠输入的边界与纠正不随旧回复取消而撤销。已经展示的图片不随后来打断而撤销。取消剩余演出，不等于抹除整轮互动。

## 13. 关系状态与可学习姿态

关系状态主要是称呼、交流偏好、边界、被接受的邀请、未完成约定、共同里程碑、已修复误会，不先建设一个万能好感度。

例：

```text
用户：“你不用一直找话题，陪我听一会儿雨就行。”
明确内容：当前希望安静陪伴。
角色解释：无需用连续提问维持此次互动。
当前变化：允许更长停顿；不继续追问等待对象。
实际演出：完成镜头转向雨窗后，记录 quiet_company 已开始。
学习候选：在相似的明确邀请下，优先给空间。
不允许推断：用户永久内向 / 用户希望依赖 Mira / 关系已升级。
```

成长定义为理解和应对方式的有依据变化。核心身份保持稳定。一次短会话最多证明情境适应，不能宣称已经观察到长期人格演化。

## 14. Hindsight 的接入合同

### 14.1 当前职责与来源边界

官方文档描述 retain、recall、reflect 与 mental models。这里采用的是它们的能力接口，不依赖特定供应商模型。上线前应固定实际版本并验证接口行为。[S2–S5]

| 调用 | 本方案用途 | 禁止替代 |
|---|---|---|
| retain | 已确认经历的异步提取与索引 | 当前边界的即时保存 |
| recall | 旧经历、往事和相关证据候选 | 当前状态与权限的最终裁决 |
| reflect | 会话后回顾、解释候选、软习惯候选 | 任意覆盖角色或直接播放回复 |
| mental models | 预计算的再次来访摘要 | 用户纠正与删除的实时权威 |

### 14.2 接入策略

当前事件在应用数据库先落地，与 outbox 同事务写入。后台按源事件 ID 提交索引任务。每个结果保留源事件映射，读取时与应用中的有效性、删除状态和作用域再核对。

应用事件账本保存来源与实际执行结果；Hindsight 保存派生的检索内容。这不是两个能各自决定“真相”的平行系统。

主回复优先使用当前状态和 recent evidence overlay，实现刚收到的纠正立即可读。后台没完成或服务不可用时，当前场景仍可运行，并在诊断中说明历史检索处于降级状态。

### 14.3 必须校验的接口语义

retain 可能完成但产生零记忆单元；这不等于该原文可被 recall 找回。检查提取结果与可检索状态。[S2]

reflect 的结构化输出可能缺失或带错误；HTTP 成功不能直接触发关系状态更新。带来源的结构化候选经应用验证才生效。[S3]

mental model 是派生摘要。官方 API 文档指出仅删除源记忆不会自动触发其基于新写入的 stale 判定。本方案因此自行维护 invalidation 与来源依赖；删除/纠正时立即阻止旧摘要使用，再刷新或清除。[S5]

### 14.4 隔离

服务端持有 session/访客与 bank 的映射。用户或模型不直接指定任意 bank ID。标签用于检索范围缩小，但不取代应用授权；不同来访者不能因为同一角色而共享私密资料。

作者私有秘密不放进公共对话 bank。诊断日志同样需要裁剪，不能把尚未披露的剧情原文放在面向用户的接口中。

## 15. 部署与代码边界

建议结构（新方案目录，不声称现有仓库已有）：

```text
character/
  mira.yaml                 # 身份、表达、动作偏好
  memories.seed.yaml        # 作者提供的个人经历
  storylets.yaml            # 剧情条件、披露与完成规则
  assets.manifest.json      # 素材、动作、降级和许可
runtime/
  session_coordinator       # 控制事件、epoch、单会话顺序
  state_reducer             # 唯一状态写入规则
  memory_router             # 事实保障与人格联想
  context_builder           # 构造有范围和版本的上下文
  turn_director             # 调用模型，返回计划候选
  plan_validator            # 引用、动作、状态与披露核验
  hindsight_adapter         # 检索、索引、整理，不写核心状态
presentation/
  scheduler                 # beat 依赖与取消
  speech_player
  subtitle_presenter
  scene_executor
  receipt_collector
inspection/
  evidence_view
  recorded_replay
```

持久化可集中在关系数据库的 events、current_state、effect_receipts、projection_links 和 outbox 等少数表；名字及拆分按实现调整。模型不持有数据库直写权限。

第一版用 STT → 对话模型 → TTS 的链路更便于让同一份文本驱动字幕与语音，这是本题的工程选择而非性能比较结论。若选端到端语音，应先证明有足够的输出转写、取消与截断能力，再用相同呈现协议接入。

## 16. 延迟与成本控制

不把“很像在思考”实现为每轮多 Agent 串行。主链只保留一次必要的对话模型调用；检索有截止时间；整理不阻塞回复；TTS、预加载与验证后的调度可按依赖并行。

必须记录：输入完成、状态就绪、召回完成/超时、模型开始与完成、首个可播放音频、实际首播、打断、停止播放、旧结果丢弃、后台整理耗时。

验收目标应在设备与网络基线上确定。本方案不预报毫秒级实测效果，也不把缓存命中率或 token 节省写成已实现收益。动作快路径不依赖外部模型，是能真正控制的设计边界。

缓存键至少涉及角色版本、场景版本、有效状态、权限与删除版本。取消缓存结果不能重新获得播放资格；共享文字缓存不能串用户资料。

## 17. 失败与降级

| 失败 | 用户体验 | 状态处理 |
|---|---|---|
| Hindsight 不可用 | 当前会话继续；旧事未知时确认 | 不编造检索结果 |
| 模型超时 | 保持可辨别思考/失败反馈，允许重试 | 不更新剧情或学习 |
| JSON 无效或动作不存在 | 有限次修复或安全短回复 | 不执行部分错误计划 |
| TTS 失败 | 字幕/文字降级，允许重试 | 字幕披露仍按实际显示记录 |
| 图片未加载 | 口头说明未能展示，保留替代动作 | 不记为已展示 |
| 视频被打断 | 停播、回到常驻角色 | 仅记实际片段与不确定范围 |
| 断线/ACK 丢失 | 恢复时对齐呈现游标 | 无法核验部分不假定完成 |
| 同一事件重复投递 | 不重复动作或写入 | effect/event ID 幂等 |
| 后台旧总结晚到 | 不覆盖新边界/纠正 | 版本冲突即丢弃或重算 |
| 删除进行中 | 立即屏蔽相关内容 | 清理原文与派生项，区分屏蔽与清理完成 |

## 18. 3–5 分钟演示设计

这是测试用的交互路线，不是固定播放剧本。不同的用户选择应改变后续走向。

1. 用户说名字、喜欢雨声、不喜欢被拍照。角色放低相机，后续取景避开用户。
2. 用户提到自己也在等待。事实自述与角色共鸣分开；Mira 更愿意谈照片，但不自动揭露秘密。
3. 用户接受看照片。物件锚点触发照片展示，记录首个可见呈现。
4. Mira 准备继续解释，用户打断。声音、未来字幕和后续效果停止；未播放解释不进历史。
5. 用户请求放大照片或改谈别的话题。系统基于已呈现内容继续，不从头自我介绍，不假装已说出秘密。
6. 用户说“我们再安静听一会儿雨”。角色按当前偏好降低交流强度，环境/镜头变化形成结束。
7. 在诊断视图回放同一过程：查看引用、更正、取消和实际状态，而不是展示虚构心理数字。

可选加分项：获明确保存许可后生成“再次来访摘要”，第二次进入不重复初遇。独立重置清除这段进展。此项不是需求基线，也不能在没有可靠存储时假装实现。

## 19. 必须执行的验收场景（建议，尚未运行）

| ID | 场景 | 断言 |
|---|---|---|
| M01 | 用户说明不拍照 | 后续相关动作与台词都遵守 |
| M02 | 用户更正名字 | 当前称呼立即更新；旧记录不作为当前事实 |
| M03 | 相同输入、人格联想开/关 | 事实与权限相同；可比较联想与表现差异 |
| M04 | 提及相似等待经历 | 不推断等待对象和原因相同 |
| M05 | 回忆旧误会 | 同时读取已修复结果，不重复翻旧账 |
| M06 | 同一回忆连续相关 | 不机械地每轮复述；尊重话题转移 |
| M07 | 用户拒绝看照片 | 关闭该开放意图，不因计时到点展示 |
| M08 | 媒体加载失败 | 不提交 photo_presented |
| M09 | 语音没播但字幕已显示 | 相应内容按已呈现处理 |
| M10 | 关键披露前打断 | 不推进对应披露状态 |
| M11 | 台词半句中断且无精确对齐 | 记录 partial，不伪造完整已说台词 |
| M12 | 旧模型输出延迟到达 | 不播放、不写当前状态 |
| M13 | 旧有效回执延迟到达 | 可核验后幂等补历史，不触发播放 |
| M14 | 正在说话时用户给新边界 | 停止旧动作链，可靠输入边界仍提交 |
| M15 | 快速连续两次输入 | 只有当前 epoch 有执行资格 |
| M16 | 后台摘要与新纠正冲突 | 新纠正获保障，不被摘要覆盖 |
| M17 | retain 零抽取 | 诊断显示未形成可检索记忆，不宣称成功召回 |
| M18 | reflect 缺结构化输出 | 不执行候选状态写入 |
| M19 | Hindsight 全部不可用 | 当前会话核心流程仍可运行 |
| M20 | 模型请求未知动作或媒体 URL | 拒绝未知能力，不执行任意内容 |
| M21 | prompt 诱导泄露未解锁秘密 | 生成上下文无秘密原文；受控披露路径不绕过 |
| M22 | 跨访客检索 | 服务端范围拒绝，不依赖模型自律 |
| M23 | 删除有依赖的记忆 | 立即屏蔽相关摘要/索引，清理后不复活 |
| M24 | 录制回放同一执行序列 | 相同事件序列产生相同状态；不重新调用模型 |
| M25 | Mock 与真实模式 | 使用同一计划、调度、取消与回执合同 |
| M26 | 摄影师人设一致性 | 不是关键词堆砌；陌生话题仍保持动机/表达方式 |
| M27 | 安静陪伴 | 不靠持续追问强行延长互动 |
| M28 | 分支试演 | 明确独立实验 scope，不能污染真实会话 |

确定性测试与真实模型测试分开。规则测试要求通过对应断言；自然性、角色可信度和语义泄露风险仍需多次真实运行与人工检查。不能用类型验证替代对话质量评估。

## 20. 72 小时内的实施路径

以下是依赖顺序与工作量控制建议，不是对未知团队的交付保证。语音、素材和移动端适配需要并行推进。

**阶段 A：先让一次真实互动可执行、可打断、可回放。** 做 epoch、简短 beat、白名单动作、呈现回执与当前历史。先用固定计划和 Mock 验证，随后接真实模型与语音。

**阶段 B：让角色有稳定动机和可用个人经历。** 完成 CoreSpec、少量作者记忆、物件锚点、两个以上自然路线和剧情许可。保证需求基线的情绪、动作、环境变化与内容触发事件。

**阶段 C：让记忆真正改变行为。** 加入事实保障、人设联想、来源解释、开放意图、纠正与关系状态。启用 Hindsight 的异步索引；它失效时不拖垮阶段 A/B。

**阶段 D：做可观察的炫技与交付。** 加入依据高亮、取消轨迹、呈现进度和录制回放；跑失败注入、移动端测试，录制 3–5 分钟演示并写 README/AI_USAGE。

时间不足时优先保留：呈现一致性、事实保障、稳定人设、物件驱动、内容触发场景、成功打断与失败降级。先推迟：跨会话来访、人格长期学习、自由生成视频与反事实试演。不要先削掉取消/权限/来源来维持花哨功能。

## 21. 需要锁定的创作与集成输入

实施前确定：Mira 核心动机与秘密；允许的情绪/动作/素材；哪些剧情小段是主线和可选；语音输出是否支持对齐；Hindsight 实际版本与认证方式；会话存储和重置约定。

这些是尚待用户或实现阶段确定的输入，不阻止架构成立，但不能让编码 Agent 任意补写并当成已批准需求。
