# v0.1 → v0.2：建议修订，不是已实施变更

依据见 evidence-index.md。以下为本次研究后的设计建议；不冒充同行的原始实现。

## 1. 把自建范围收窄到角色语义与状态合同

优先评估现有实时框架能否承接传输、音频发送、取消、预生成和预制音频播放，再补我方角色策略。不要默认重新实现全部 RTC/音频调度。

JEV 保留为主语义决策候选。接入框架时明确谁有话轮所有权：框架检测与我方判断可分别产生信号，但只有一个最终仲裁器。不要让两套控制器独立抢着 commit/cancel。

借鉴：S13–S15。

## 2. 单一仲裁器不等于所有声音采用相同静音规则

区分 MAIN_ANSWER、LISTENER_BACKCHANNEL、THINKING_FILLER、TOOL_STATUS。用户仍在说话时，正文不能无条件进入，但被明确许可的倾听反馈可以出现。用户发出停止指令或真正打断时，所有类型都服从取消。

同一路物理输出可以承载不同逻辑通道。不要为每种声音建立互不协调的播放器。

借鉴：S01–S02。

## 3. 预制与动态垫音分别测试

保留用户提出的缓存角色语音库作为低启动成本路径；同时设小模型动态生成垫音的对照。动态生成不是必需替代品。比较语境贴合度、重复感、额外网络时间与正文被拖延的时间。

播放触发检查 final audio readiness，而非只看 LLM 首 token。首 token 已来、TTS 未准备好仍然可能存在空档。预选不代表立即出声。

不要把 350ms、1200ms 或某个供应商推荐阈值当作通用自然节奏。实验应把阈值、冷却、最大次数与主回答延迟分开记录。

借鉴：S01、S12。

## 4. 角色规则与通话规则分开

共享角色事实、记忆和关系背景；另设 spoken interaction policy，控制句长、轮次、是否朗读动作描写、打断容忍与语气词密度。

对于游戏/故事场景，增加小型 interaction state（场景、当前目标、未解决事件、允许动作），不要只不断堆“活泼、可爱”类形容词。普通闲聊不需要立刻引入复杂剧情图。

借鉴：S08、S11、S24–S25。

## 5. 把 Performance Context 作为选项

TTS 选择除声音相似度外，还要测试多轮韵律连续性。若供应商支持近期声音上下文，保留单独适配路径；若仅支持文本，使用近期说话风格状态与少量变化控制，不要每个短片段重新强制标签。

严格区分 fast-start 与上下文更完整的模式。某服务的 conversational 模式需要等整轮文本时，不能宣称通过另外开启 fast_start 就消除了等待。

借鉴：S03–S04、S22。

## 6. 正确理解开源音频并行模式

借鉴 AIRI 的 intent、sequence、有序播放、取消检查，不直接照搬并发数。

TTS Adapter 必须声明是双向输入/输出流、完整文本后流式音频、还是整段音频文件返回。不同模式使用不同调度策略。

保存 generated、synthesized、delivered-estimated 的区别。前端提交 heard_response 的方式必须独立验证，不能假定已做到 sample 级准确。

借鉴：S17、S20–S21。

## 7. 输入正确性先于更激进的响应

增加短音频 pre-roll，检测开始前已进入麦克风的首音不能丢掉。只在当前会话和用户授权范围保留必要短缓冲，不作永久录音。

对“没”“不”“但是”“我还没说完”等用例进行真实录音链路回归测试，不只用设置页面录音或预先裁切好的 WAV。

借鉴：S19。

## 8. 建议最小对照实验

A. 托管 Inworld Realtime：功能体验参照，不把不同底层模型的结果当纯架构公平比较。
B. 现有框架 + 同一 ASR/主 LLM/TTS：无自定义 JEV 策略的组合式基线。
C. B + JEV 角色/语义控制：测准确率收益与暴露延迟。
D. 在 C 上分别开关 speculative text、speculative TTS、缓存 filler、back-channel；避免一次全开后无法归因。

声音方案至少比较快启动和更完整上下文两种模式。保留已使用的原生语音作为自然互动参照；无需为了测试一口气部署全部研究模型。

核心指标：首实质回复延迟、首反馈延迟、错误抢话、误打断恢复、打断尾音、预生成废弃率、中文角色持续性、语境内韵律、垫音重复率、正文被垫音拖延、每分钟成本。

验收不应以“有声音了”代替“回答开始了”，也不应以“开源 README 写实时”代替实测。
