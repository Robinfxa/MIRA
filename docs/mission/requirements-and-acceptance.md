## 结论

本项目的交付对象是一个**移动端优先、以原创成年角色和场景为主体、能够连续互动 3–5 分钟的实时多模态 MVP**。它必须有文字与麦克风输入、角色语音与同步字幕、可辨认的角色四态、内容驱动的表演，以及真正能够停止声音并阻止旧结果复活的打断链路。聊天列表、状态文字占位、接口声明或仅有 Mock 的基础工程，不能单独证明核心体验完成。

交付还包括源码仓库、演示地址或清晰启动说明、一条命令启动或不超过 15 分钟的完整启动流程、3–5 分钟演示录屏、README 和 AI_USAGE.md。录屏与如实的验证记录应从现在开始准备。

## 产品目的和用户

### 明确的产品目的

设计并实现一个结合实时语音、角色表演和多模态内容的互动场景。用户面对一个身处具体环境中的角色，能够用文字或语音交流；角色说话、变换表情或动作，并随着交流触发场景演出（第 1 页）。

### 用户定位

- **明确的体验使用者**：在移动端网页上与角色交流的人；桌面端也必须可以正常体验（第 1 页）。题目没有限定年龄、职业、付费意愿或商业市场，不应把这些推断变成硬要求。
- **推断的第二类使用者**：评审或接手运行项目的人。他们需要没有私人密钥也可查看核心流程，并能根据源码、README、录屏复验结果。依据是第 3–5 页的交付与无密钥体验要求。
- **角色年龄要求不等于用户年龄要求**：明确要求原创成年角色，示例 Mira 为 26 岁；题目未要求用户年龄验证、注册或账号系统。

### 故事种子不是强制剧情

第 1 页允许自行设计简短场景，也提供了 Mira 的咖啡馆种子：暴雨后的夜晚、即将打烊的咖啡馆、26 岁旅行摄影师、琥珀色雨衣、银色星星发夹、似乎在等人但暂不说明缘由。选择这个种子有助于降低创作与资产成本，但姓名、衣服、咖啡馆和等待对象均不是题目锁定的强制条件。若项目选择保留 Mira，则宜在角色设定和资产中保持连续性。

## 24 小时范围与风险判断

### 有希望完整交付的范围

如果沿用现有基础工程，集中完成一个原创角色、一个场景、显式按住说话/点击打断、一个可用语音链路、一种轻量角色动画、多轮会话、结构化事件、无钥匙模式、故障处理及交付材料，24 小时内有机会覆盖核心要求。这里是计划判断，不是工期保证。最关键的不确定项是可获授权的真实模型/语音资源、浏览器实际音频行为、角色资产质量和最终录屏。

### 不应在同一窗口承诺全部完成的组合

从基础工程出发，同时承诺高质量 Live2D 定制绑定、自然全双工 VAD/附和、逐词口型、运行时一致性生图与生视频、跨会话记忆、跨浏览器真实手机矩阵以及生产级部署，缺少可验证的 24 小时可行性。多数属于原文可选扩展；应保留在明确增量/后续计划，不占用核心交付的验证与录屏时间。

### 建议执行顺序

1. **先锁定最窄合规路径**：角色与场景、真实语音路线、动画分支、可公开的无钥匙入口、唯一播放/取消控制面和证据目录。
2. **尽早接通实际可听的纵向链**：移动场景 → 输入 → 服务端/模型或明确 Mock → 声音/字幕/角色 → 打断 → 新输入。不要继续用架构扩建替代表演和音频。
3. **把负控与核心功能同时完成**：延迟旧响应、排队媒体、音频加载失败、快速多轮输入。没有旧结果不复活的证据，就不能把打断标完成。
4. **达成所有数量和因果门槛**：3 表情、2 非说话表现、1 环境变化、1 内容触发事件，并在真实画面逐一复核。
5. **保留充分交付时间**：建议最迟在截止前 4 小时冻结新增能力，完成干净启动、连续会话、失败演示、录屏、README、AI_USAGE 和缺口清单。该 4 小时是执行建议，不是原文规定。

### 主要威胁与应对

- **真实资源阻塞**：配置已存在但实际适配/授权/服务不可用。应尽早验证授权范围和实际链路；对缺口如实说明，不静默回落到 Mock 冒充 live。
- **浏览器音频阻塞**：自动播放、麦克风权限、音频上下文、移动端后台行为与设备兼容。用真实音频证据检查，不用 DOM 事件收据代替听觉验证。
- **异步旧轮复活**：音频结束、媒体加载、生成响应、字幕定时器或动画回调落后。建议为所有呈现动作检查当前活动身份/许可，取消时先撤销本地呈现权，再处理远端资源；这是实现建议。
- **视觉计数虚假通过**：三个标签对应同一张脸，两个按钮对应同一动作，动画只有面板闪烁。验收应直接看角色和场景，而非仅看状态字段。
- **固定时间轴伪装互动**：无论用户说什么都会展示同一事件。必须有正反输入和不同触发时间的对照证据。
- **内容与已呈现历史混淆**：取消后角色仍认为未播内容已被用户听到。PDF 至少要求连续状态与取消正确；仓库更强的实际呈现历史合同应继续保留。
- **秘密或素材来源问题**：密钥进仓库、日志或录屏；第三方角色被当作原创。交付前做文件/历史/素材来源检查。
- **交付证据不足**：只有测试清单、没有实际录屏或干净启动记录；把 Agent 自检写成人工验证。每项标记实际证据与尚未验证范围。

## 可直接执行的验收场景

所有步骤需要记录版本、模式、设备/浏览器、实际结果和证据位置。以下先后顺序便于覆盖需求，不限定实现协议。

### A01 无钥匙启动与主界面

在无私人密钥的新配置下，按 README 所述方式启动。验证场景主体、角色、字幕、文字与语音入口；窄屏和桌面各操作一次。记录完整耗时及既有前置依赖。覆盖 PDF-02–04、PDF-27、PDF-D02–03。

### A02 文字连续会话

输入姓名/问候，再输入场景相关问题与追问。验证角色回复、声音、字幕、四态和状态连续性。整个场景持续 3–5 分钟而不依赖页面刷新或重置。覆盖 PDF-01、05–06、08–09。

### A03 真实麦克风回路

在有权限的真实麦克风环境说出可区分的内容，核对实际输入与响应相关性。记录模式及 STT/实时语音实现。再测拒绝或不可用时的提示与文字替代，这一拒绝用例属于建议健壮性测试。覆盖 PDF-07、09。

### A04 说话中打断

让角色发出足够长的实际语音，并排队后续字幕、动作与媒体事件。中途开始新语音输入。逐项检查声音停止、回复取消/失效、待播事件不出现、切换倾听、新输入被处理。继续交流，不能只验证停止而不验证恢复。覆盖 PDF-10–14。

### A05 迟到响应与连续打断负控

建立可控制的旧轮延迟屏障：旧轮已开始 → 用户打断 → 新轮运行 → 释放旧轮。分别释放模型响应、音频加载、媒体加载和结束回调，确认无旧内容复活。连续快速提交和打断，确认状态不会停死。覆盖 PDF-12–15。推荐使用确定性屏障，避免靠随机 sleep 猜竞态。

### A06 表演数量与内容因果

逐一触发三种表情、两种非说话表现和一次环境变化。对明显视觉事件执行相关输入、无关输入以及延迟触发三组对照；只有符合内容/节点的组发生事件。记录结构化指令和画面证据。覆盖 PDF-17–21。

### A07 多模态分支及生命周期

在会话中展示所选动画/视频/生成媒体。若为视频，检查加载、结束和中断；若为运行时生成媒体，检查生成中、失败与取消后旧结果。纯动画分支不需要为不存在的视频或生成接口制造通过记录。覆盖 PDF-22–24。

### A08 故障与恢复矩阵

分别注入模型超时、连接中断、音频加载失败、适用的媒体加载失败。每次验证可理解反馈、可继续使用的恢复路径和不存在旧输出复活。至少一个故障须出现在最终录屏。覆盖 PDF-26、PDF-D04。

### A09 真实模型证据与模式诚实

在授权配置下实际运行页面 → 服务端 → 模型 → 呈现。验证真实请求与 Mock/回放明确区分，失败不静默伪造成功。若资源阻塞，将本项标为 blocked/not_run 并写明原因与下一步，不能因为 A01 通过而标本项通过。覆盖 PDF-25、27、PDF-D07。

### A10 发布材料

核对仓库和录屏版本、素材/服务来源、秘密检查、完整 README、AI_USAGE 真实错误修正实例、3–5 分钟录屏内容与时长、启动路径。录屏可采用一条清晰路线，但不得剪接隐藏打断后的旧声音或失败。覆盖 PDF-28、PDF-D01–07。

## 交付状态记录格式

建议逐项使用 `pass`、`fail`、`blocked`、`not_run`、`not_applicable`，同时填证据、测试模式和限制：

- `pass` 仅用于本版本真实执行且符合条件的条目。
- `not_applicable` 只用于未选择分支的条件要求，不能用于尚未完成的核心项。
- Mock、真实模型、真实麦克风、桌面浏览器、模拟窄屏、真实手机和人工验证应分开记录。
- 未运行、没有资源、已有配置、代码实现、自动测试通过和用户可感知通过是不同状态。
- 如果核心能力未完成，按第 6 页要求在 README 披露具体差距，不改写原需求或覆盖历史记录。

本报告到此仅定义验收标准。最终是否完成，须由交付版本与实际证据决定。

## 用户追加北极星：可定位故障与显式开发录制（2026-10-03）

以下来源为本轮用户最新明确要求，**不是 PDF 原文要求**：项目需要准备充分的日志
与报错，以免出问题无法定位；此项加入项目北极星。用户随后补充开发模式下记录原始
内容。建设此功能不等于现在已经获准开启原始录制。

- **USER-OBS-01：可定位故障。** 关键流程应有关联的请求/会话/轮次/效果标识、阶段、
  已知安全错误码、耗时与明确取消原因；用户 Stop、断连、超时、供应商失败分开。
  失败消息含恢复方向，未知原因不猜测。默认日志不保存私人对话、模型正文、音频或凭据。
- **USER-OBS-02：有界可靠诊断。** 本地私有 JSONL 队列、轮转和保留期有界；磁盘或日志
  故障不使产品崩溃或阻塞取消；一条命令导出重新校验的脱敏诊断包。
- **USER-OBS-03：显式开发录制。** 原始内容录制独立默认关闭，需明确本地开关和同意，
  开启时持续可见。经隐私审核的原始对话/模型输入输出/音频可用于复现；密钥、认证
  token、Authorization 头和凭据结构永不合格。不能可靠过滤或尚不确定的内容丢弃。
  不承诺通用口述秘密自动识别；原音频隐私审核不由 ASR 文本或语义审核许可代替。
- **USER-OBS-04：原始数据隔离。** 原始内容只保留在独立私有、有容量/时间上限的本地
  目录，排除 Git 和普通诊断包；原始导出需另一次显式确认，分享仍需另有授权。

验收：在纯合成数据下验证 401/403/429/超时、Stop/断连、权限拒绝、模式切换、凭据过滤、
队列/字节配额、轮转/过期清理、普通导出排除原始内容及日志 IO 故障。真实供应商、设备、
声学停止、真实敏感数据识别与原始录制启用均不能由这些离线用例代偿。
