# 成功插话后的完整转写

本切片修复0114中成功打断回复后，完整转写仍被“采集与播放重叠”提示要求手动发送的问题。识别完成的同一句现在保留轻声前缀和内部停顿，并关联实际被打断的原请求。不会仅截取达到声音阈值之后的词，也不根据“等一下”等关键词授予动作。

声音检测仍只是一种本地启发式。新实现将成功本地停止、原请求身份和服务端最终语句的样本范围关联起来；已确认消费的旧样本不能重放为新句。新文字请求、全局Stop、关闭及撤权继续阻止旧结果复活。排队但尚未提交给播放设备的PCM不再算已开始播放。

用户启动参数、麦克风许可、STT/TTS次数和时长没有变化。当前语音插话开关继续有效；关闭时保持按钮打断方式。已有草稿和不能安全关联的旧转写继续保留，不覆盖新文字。

合成验收使用编译后的生产控制器、实际提交协议和播放生命周期，覆盖轻声前缀、句内停顿、晚到final、排队未播放、连续子流、新输入/Stop/Close、旧样本重放与重复提交。软件检查不证明实际麦克风声源、物理听见或同版本设备已通过；最终完整检查以交付包START-HERE为准。

设备复验可沿用原命令：开启连续聆听，在Mira回应中说“等一下，等一下”并补完条件。核对完整语句只发送一次、后续回应保留原请求与补充、旧尾音不再播放；随后用普通文字新开一轮，旧插话不能附到该轮。
