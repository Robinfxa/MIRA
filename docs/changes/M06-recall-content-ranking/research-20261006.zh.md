# Mira 长期记忆：实查、缺口与本轮实现

实查日期：2026-10-06 UTC。来源是公开技术资料和本项目源码；没有读取真实会话、记忆数据库、.env、认证文件，没有把私人语料送去搜索或模型。本轮只有本机确定性修改和合成测试。网页为查阅时的 main/官方文档，不冒充固定 commit 上的可重现代码或跨版本保证。

## 结论

Mira 已有作者给她的第一人称人生、喜好和当前心事，也有作用域隔离、可更正/软忘记的持久存储。用户最近只带 --story 的启动方式不会启用任何真实长期对话库。它每次重新加载作者设定，剧情运行进度在内存；这不能称为“她已自动长期记住我们聊过的一切”。现有可选记忆也没有从对话自动准确抽取人格或偏好的能力。

本轮找到并修复的是实际召回链条的缺陷：旧版把中文整句当一个词，对整个 JSON（含字段名/ID/未完整播放的语音计划）做子串匹配。于是普通中文问题找不到较早的偏好/经历，最近的无关消息或 metadata 反而占满八个名额。修复仅改变已获准历史记录的本机排序，既不是新增资料权限，也不是“智能摘要已经完成”。

## 当前实现链条

以下位置均相对本项目根目录，可直接复核。

- 作者人生和喜好：adapters/story/assets/mira.story-seed.v1.json 包含 first_person_text / memory_temporal_type；例如 attention、small_delights 是她的喜好/习惯，first_trip 是作者创作的过去，waiting 是当前打算。bootstrap/character_story.py:builtin_definition 验证 seed hash 并使用明确选择的 canon ID。domain/story.py:project_shared_context 及 domain/story_memory.py:first_person_story_memory 生成版本绑定投影，把过去、意向、未公开信息与已回执剧情分开。application/character_memory.py 的 self_continuity 是八个 trait ID 和附加召回状态/数量的紧凑索引，不是自动人格学习。
- 剧情记录：application/actor_story.py:checkpoint_snapshot / persist 把运行态 snapshot 交给显式 checkpoint callback；bootstrap/character_story.py:persistent_character_factory 只有配对后才打开 async store，按固定 scope load/save；adapters/memory/story.py 保存剧情 checkpoint 及有回执的经历，版本不符需显式迁移。ephemeral_character_factory 是 --story 的默认方式。剧情作者过去可由角色自然以“我”讲述；剧情释放、软件显示、真实用户经历仍不能相互替代。
- 手动记忆：adapters/memory/sqlite.py:append / supersede / forget / undo_forget 保存不可变带来源的条目和变更；固定 user/character/world scope、source version、依赖失效控制更正和忘记。bootstrap/development_memory.py 装配单个只读 worker，application/actor_memory.py 固定 scope/200ms/32768 bytes；memory_context.py 形成先当前约束后可选过去的 ContextPacket，再检验 revision。自然聊天不会自动往这个库写偏好。
- 对话档案：SessionActor 的已提交输入/回执事件 → SessionConversationBinding.schedule_capture → 异步 archive.capture → ConversationArchive.append_input / append_receipt 保存完整已接受文字和实际软件回执。archive.load_session 只返回同作用域、明确选中会话中的有效版本，排除被更正/软忘记条目及其依赖。SessionConversationBinding.build_packet 调 conversation_recall_data，携带 source IDs/version/stage，默认最多8整条/8192 bytes；ensure_current 在使用前核对来源 revision。没有摘要缓存。
- 实际送模：application/contracts.py:generation_context_data 序列化 conversation_recall / memory_evidence；unavailable 时先移除旧包。codex_support/payload.py:build_prompt 与 direct_tools.py:_prompt 使用该投影，后者组成真实 native Responses request input。旧角色自称留在 conversation_recall，不进入当前 role_active、权限或 presented_effects。第一人称的普通表达由提示与模型实现；来源标签供内部约束，不要求每次对用户复诵。

## 三项独立启动选项

真实开关见 tools/live_provider.py:159–197 及 _story_options；README 的“可选保存与重入”也已说明。

1. 剧情持久化：--story + --story-db + --story-scope + --authorize-story-persistence-and-recall + --create-local-operator-pairing。
2. 既有手动记忆召回：--memory-db + --memory-scope-config + --memory-scope + --authorize-memory-to-selected-provider + 配对。写入管理、Google 派生语音另有独立同意。
3. 对话记录：--conversation-db + --conversation-scope-config + --conversation-scope + --authorize-conversation-persistence + 配对。读旧会话还要选择准确会话、单独同意所选 provider；不会自动选最近会话，管理和 Google 派生语音另行同意。

本轮不替用户选择路径、scope、跨设备共享或传输授权，不打开真实库，不改这些开关。

## MaiBot 与近期社区资料：实际查到什么

1. [MaiBot 1.3.1/1.3.0 release](https://github.com/Mai-with-u/MaiBot/releases)，2026-09-28 / 09-26：版本说明包括图片记忆、人物画像、Episode、事实账本、生命周期状态的记忆包。版本列表能证明发布者声明了哪些功能，不能证明 Mira 已经具备它们。
2. [官方 A_Memorix 配置](https://docs.mai-mai.org/manual/configuration/a-memorix)：把写回、查询、人物画像注入、启发式召回和维护分开。摘要写回按新增消息数触发，需额外模型调用；heuristic recall 默认关闭且有频率/条数/字符上限。一般共享和 heuristic cross-chat 的边界并不等价，后者可能扩大查询范围并绕过普通过滤。Mira 不照搬这些授权默认值。
3. [A_Memorix 内置模块 README](https://github.com/Mai-with-u/MaiBot/tree/main/src/A_memorix) 与 [sdk_memory_kernel.py](https://github.com/Mai-with-u/MaiBot/blob/main/src/A_memorix/core/runtime/sdk_memory_kernel.py)：源码提供独立 summarize_chat_stream、ingest_summary、ingest_text、search_memory 接口；摘要输入带 chat_id、external_id、时间/参与者，写入与检索是不同步骤。Mira 应保留来源、可更正记录和明确写入链，而不是仅把“请记住”加进 prompt。
4. [heuristic_injector.py](https://github.com/Mai-with-u/MaiBot/blob/main/src/maisaka/memory/heuristic_injector.py)：先用 _build_chat_impression 的 generate_response 生成聊天印象，再 search_related_memory，按开关用当前 session 或全局范围检索，结果格式化为内部参考。这确实是额外模型调用，不可宣称是免费本地摘要。Mira 本轮仅确定性词匹配，不移植此调用。
5. [mid_term.py](https://github.com/Mai-with-u/MaiBot/blob/main/src/maisaka/memory/mid_term.py)：中期回想显式记录时间范围、参与者、summary、recall cues，使用独立 source_kind，与原消息不同。源码把回想标为内部参考并建议仅自然相关时使用。可借鉴“分层和来源”，不能由摘要格式存在推导内容无误。
6. [maisaka_generator_base.py](https://github.com/Mai-with-u/MaiBot/blob/main/src/chat/replyer/maisaka_generator_base.py) 与 [官方 Bot 配置](https://docs.mai-mai.org/manual/configuration/bot-config)，后者更新2026-10-06：人格、行为风格、说话风格是分开的；源码用结构化 source_kind 辨认自身历史，而不是可控昵称。其 persona 缺省中出现“是人类”，不符合 Mira 被直接问 AI/现实问题应诚实的要求，因此不移植这一句或身份策略。
7. [官方记忆与学习 FAQ](https://docs.mai-mai.org/faq/memory-and-learning)，更新2026-09-29，及[记忆管理](https://docs.mai-mai.org/manual/webui/memory-management)，更新2026-10-05：鼓励核对来源、手动画像 override、纠正和删除；明确学习结果可能出错，摘要/画像/向量可能调用配置的模型服务。这支持显式可查来源和可撤回的设计，不能许诺固定轮数后准确学会。
8. [社区 issue #1896](https://github.com/Mai-with-u/MaiBot/issues/1896)，2026-07-09 发起、查阅时 Closed：报告记忆相关同步 SQLite 操作阻塞主事件循环及资源/健康检查问题。这是作者公开复现报告，不是本轮独立验证；对 Mira 的启示是沿用现有有限 worker、deadline、预算，不为功能堆无界后台扫描。

这些来源的共同工程方向是“稳定角色设定 + 有来源的长期条目/事件 + 有界检索 + 单独维护与纠错”，不是把角色所有输出永久当事实。本报告不复制 GPL/AGPL 上游实现代码。

## 本轮最小实现与边界

新增 application/conversation_recall_ranking.py；conversation_archive.py 只有 import 和排序 hook 替换。候选池、scope、schema、授权、存储、数据库读取和最终八条/字节硬界限不动。查询最多前8192字符/64个不同词项；中文连续段用双字片段，其他 Unicode 词保持整词。只评分已接受/更正 input，已呈现 subtitle 和 completed speech；metadata、控制动作和未完成语音不参与相关性。每个词只计一次，同分取更新行。输出仍按原历史顺序排列，保留原文和来源标识。

这只能改善已有文本重合的召回。它不理解同义词或完整语义，不解决任意久远/超出候选范围的记忆，不把旧角色自称变成新会话身份，不把“明天想去”变成“去过”，不从重复输出生成稳定喜好。现有作者自传/喜好、当前对话和剧情回执的区分继续由 typed state/projection 维护。

## 后续建议（未实现）

先让用户实机选择真正需要保存/召回的范围并完成同一版本长会话验收；不能用这次离线召回修复冒充持久人格已启用。若以后要自动形成 Mira 自己的新偏好，需要独立定义：哪些来源有资格成为角色新事实、作者设定与用户提议冲突时谁优先、可审阅的 proposed/accepted 状态、撤回与依赖失效，以及模型服务/摘要调用的明确预算和数据同意。优先保持已有来源库为权威，再加可重建的派生视图；不让无来源摘要反过来覆盖原始证据。
