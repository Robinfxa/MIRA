# 剧情控制文本与角色对白分离

本次修复防止新的应用控制文本被直接编译为字幕、送入TTS，或作为角色已经说过的话进入历史。剧情问题、故事叙述、照片约定和雨景邀请先检查当前前提，再生成一条真正的角色续答；只有该续答的实际呈现回执可以推进相关步骤。正常对白仍可继续，照片预览和实际赠送仍有各自独立的呈现回执。

等待真实对白的状态仅以固定诊断标签 awaiting_dialogue 记录，不把内部说明写入诊断正文。认出角色与交付照片仍不能由工具请求或等待状态冒充成功。

这项修复不会自动删除、重写或按关键词清洗已有会话。若较早的控制文本已被持久化，需要用户另行选择如何处理。默认 --story 使用进程内会话，正常重启会建立新会话；不能因此假定用户启用了独立 conversation store，也不读取私人数据库来猜测。任何旧数据迁移或删除都应另行获得用户选择和授权。

离线测试验证的是应用的数据通道、状态前提和回执边界，不代表真实模型永远不会措辞失当，也不代替真实设备、语音和自然对话验收。
